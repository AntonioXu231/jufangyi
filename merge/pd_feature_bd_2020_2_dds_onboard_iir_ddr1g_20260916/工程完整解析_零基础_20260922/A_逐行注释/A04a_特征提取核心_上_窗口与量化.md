## 0. 先建立三个直觉

### 0.1 什么是"相位窗"、为什么需要它

局部放电检测的最终输出是 **PRPD 图谱**（Phase-Resolved Partial Discharge）：横轴是工频相位 0°…360°，纵轴是放电幅值，颜色深浅是放电次数。它的价值在于**不同绝缘缺陷在相位分布上有不同"指纹"**（尖端、气隙、沿面各有特征形状）。

所以必须把连续波形切成"每 N 个窗对应一圈"的格，在每个窗里统计最大放电。本工程 **N = 1024**（每窗 0.3516°）。

### 0.2 为什么用 Bresenham 而不是除法

**目标**：给第 k 个样本算出窗号 = `k·N/M`（M = 工频周期样本数 = 520,000）。

- 直接做 → 需要 **32 位除法器**，130 MHz 下不可能。
- Bresenham 增量法 → 维护累加器 `ph_acc`，每样本 `ph_acc += N`；一旦 `ph_acc ≥ M` 就"翻窗"并 `ph_acc -= M`。
  - 硬件 = **一个加法器 + 一个比较器**。
  - 代价：必须先把 M 测出来（靠数同步周期长度）。

**数值验证**：`520000 / 1024 = 507.8125` → 每窗约 507.8 个样本，窗长在 **507/508 之间交替**（误差被平摊，累积误差 < 1 个样本）。这正是 Bresenham 的预期行为。

### 0.3 三种输出

| 输出 | 去向 | 内容 |
|---|---|---|
| 事件流（AXI-Stream 8 B/beat） | `pd_axis_fifo` → `pd_axis_arb` → `m_axis` → AXI DMA / ILA | 每个超阈峰值一包（`type=0x00`）；每周期末尾一包统计（`type=0x01`，`tlast=1`） |
| PRPD RAM（1024×16 bit） | `pd_prpd_ram` 端口 A | 每窗历史最大幅值 |
| 状态结果 | `pd_axil_regs` | n / Qmax / Σ\|q\| / Σq·u / 帧统计 / 12 档计数 |

**核心分工原则**：**PL 只做加、比、数，不做除法。** 输出的 `I = Σ\|q\|/T`、`P = Σq·u/T` 的除法留给 PS 用浮点做。

## 1. 设计说明（第 1–23 行）

```
2  // pd_feature_core.v  --  单通道局部放电特征提取核心
4  // 功能: 移植现有 STM32/EP2C5 的 "分段取峰值 -> 1024 相位窗 -> n/I/P/Q 统计"
5  //       算法到 Zynq PL, 补充 AXI 寄存器配置与 8 字节事件打包。
7  // 关键设计说明:
8  //  1. 相位分频采用 Bresenham 增量法: 相位索引 = (样本序号 * N) / M
9  //     (M = 实测同步周期内的 ADC 样本数, N = 每周期相位窗数)
10 //     -> 无需除法器, 自动适配 50~400Hz 任意同步频率, 窗口边界误差 < 1 点。
11 //       50Hz @20MSPS: M = 400000, N = 1024 -> 窗口 390/391 点, 与原算法 391 一致。
12 //  2. 试验电压瞬时值 u 由 32bit 相位累加 + 1024 点正弦 ROM 查表得到,
13 //     相位增量 = 2^32/N 由 PS 计算后写入寄存器, PL 侧零除法开销。
14 //  3. 累加器输出 Σ|q| 与 Σq·u; I = Σ|q|/T、P = Σq·u/T 的除法由 PS 完成
15 //     (PL 不做除法, 省资源, 精度由 PS 侧浮点保证)。
16 //  4. 【路线 B 的固有局限】死区(脉冲分辨时间)只能在"窗口级"实现, 因为本
17 //     路线的数据已经是每窗口一个峰值。样本级死区需在全速域方案中实现。
18 //  5. 时钟域: 本模块为单时钟设计(clk, 典型 100MHz), adc_dv 为 ADC 样本有效
19 //     脉冲。真实板级接入 20MHz ADC 时钟时, 需在前端插入异步 FIFO 做 CDC,
20 //     见 pd_feature_top.v 头部说明。
22 `timescale 1ns / 1ps
23 `include "pd_defines.vh"
```
**五条要点**：

1. **Bresenham 相位分频**：无需除法器，自动适配 50–400 Hz 任意同步频率。
2. **u（试验电压瞬时值）查表**：`u = Upk·sin(2πφ)`，用 32 bit 相位累加 + 1024 点正弦 ROM，**PL 侧零除法**。
3. **PL/PS 分工**：PL 算 Σ，PS 算商。
4. ⭐ **【重要局限】死区只能是"窗口级"**：因为本路线每个窗口只留一个峰值，数据已被压缩。真正的"样本级死区"（两个脉冲只隔几个样本也算一个）需要全速域方案。
5. **单时钟设计**：模块本身不知道采样时钟的存在，`adc_dv` 只是"样本有效脉冲"。接真实 ADC 必须先做 CDC。

⚠️ 第 18 行注释写"典型 100MHz"，与当前实际 **130 MHz** 不符（注释漂移）。

### 3.1 `abs13` 与"提频"主线

```
108    // 13bit 符号扩展绝对值（|−2048| = 2048 需 13bit 才不溢出）
109    // 2026-09-10 提频用：原实现把 absp_max/absp_min 放在 S_PEAK 拍组合计算，
110    // 与 q0_code/q0_sgn 的两级 case mux 串成一条 12 级、含 4×CARRY4 的长链，
111    // 130MHz 下成为 pd_feature_core 的头号失败路径。现改为在 win_close 拍
112    // 与 h_max/h_min **同拍同源**预寄存（源同为 wc_max/wc_min），既缩短链路
113    // 又保证与 h_max/h_min 严格同拍、不存在时序错位。
114    function [ADC_W:0] abs13;
115        input signed [ADC_W-1:0] v;
117            abs13 = v[ADC_W-1] ? -$signed({v[ADC_W-1], v}) : $signed({1'b0, v});
119    endfunction
```
- 返回宽度 `[ADC_W:0]` = **13 bit**。**为什么？** 12 bit 有符号范围是 −2048…+2047，绝对值最大是 `|−2048| = 2048`，而 **2048 无法用 12 bit 有符号表示**（最大 2047）。不加宽就会发生**绝对值溢出**（`-(-2048)` 在 12 位下仍得 −2048）。
- 第 117 行：符号位为 1 时先**符号扩展**到 13 位再取负；为 0 时零扩展到 13 位。
- **第 108–113 行记录了一次真实的时序优化**：
  - 原写法把绝对值放在 `S_PEAK` 拍**组合**计算，与 `q0_code`/`q0_sgn` 的两级 case 多路选择串成 **12 级 LUT、含 4 个 CARRY4** 的长链 → 130 MHz 下的**头号失败路径**；
  - **修法**：把绝对值提前到 `win_close`（窗口收尾）拍，与 `h_max/h_min` **同拍同源**预寄存；
  - ⭐ 关键约束是"**同拍同源**"：若绝对值在别的拍算，就会与 `h_max/h_min` 差一拍 → "用 A 窗口的幅度配 B 窗口的极性"。

```
121    reg signed [ADC_W:0] absp_max_r, absp_min_r;  // 预寄存 |h_max| / |h_min|
122    reg                  pol_sel_r;               // 预寄存 |h_max|>=|h_min|
123    reg  [ADC_W-1:0]     q_pp_r;                  // 预寄存 峰峰值 h_max-h_min
124    localparam [ADC_W-1:0]        ZERO_CODE = {1'b1, {(ADC_W-1){1'b0}}}; // 0x800
```
- 三个"预寄存"变量即上面说的提前算好的结果。
- `ZERO_CODE = 0x800 = 2048` —— **偏移二进制的零电平**。

### 3.2 状态编码（第 126–133 行）

```

| 状态 | 作用 |
|---|---|
| `S_IDLE` | 空闲，等"有窗口/周期待处理" |
| `S_PEAK` | 第 0 级流水：锁存全部判决前提 |
| `S_Q1` | 第 1 级流水：`幅度 × 标定系数`（DSP） |
| `S_Q2` | 第 2 级流水：`sat16` 量化 + 绝对值 |
| `S_ACC` | 发**正峰事件** + 累加 + 暂存 12 档输入 |
| `S_PEAKN` | 仅 POSNEG：发**负峰事件** + 累加 |
| `S_STAT` | 12 档比较/计数 + 帧合计（独立一拍，避免叠加关键路径） |
| `S_PRRD` | PRPD：先读 |
| `S_PRWR` | PRPD：再写 |
| `S_CYC` | 周期边界：发统计包 + 帧快照 + 换档 + 可能 `meas_done` |

第 127–129 行说明了**为什么要拆三级流水**：原路径 `h_max → 模式选择 → q0_sgn → DSP 乘 → sat16 → 累加` 是 **34 级组合**，无法收敛。拆成"每拍 ≤10 级"。

### 3.3 `sat16`

```
135    function signed [15:0] sat16;
136        input signed [31:0] v;
138            if      (v >  32'sd32767) sat16 =  16'sd32767;
139            else if (v < -32'sd32768) sat16 = -16'sd32768;
140            else                      sat16 = v[15:0];
142    endfunction
```
- 把 32 bit 有符号饱和到 16 bit 有符号 `[−32768, +32767]`。这是事件包 `q` 字段的位宽。
- **必须饱和而不是截断**：截断会回绕（大正数突然变大负数），产生荒谬的电荷量。

150    initial begin : SIN_LUT_GEN
151        for (k = 0; k < 1024; k = k + 1) begin
152            ang = 6.28318530717958647692 * k / 1024.0;
153            sin_lut[k] = $rtoi(32767.0 * $sin(ang));
155    end
```
- 1024 深、16 bit 宽的 ROM，`rom_style = "block"` 提示用 BRAM。
- 用 `initial` + `real` + `$sin` + `$rtoi` 生成 **Q15 有符号正弦表**（`1.0 = 32767`）。
- **这算不算违反"不能 `initial` 初始化存储体"？不算。** 因为：
  1. 它是**只读 ROM**（从未被写），不是"需要同步写的 RAM"；
  2. 表内容在综合时被当作常数填进 BRAM 初始化数据；
  3. `pd_axis_fifo.v` 里被批评的 `initial` 是"给需同步写的 RAM 上电清 0"，性质完全不同。
- ⚠️ **【观察】`sin_lut` 声明为 `reg [15:0]`（无符号），存的是有符号值。** 取出来后**必须显式 `$signed()` 转换**（第 496 行做到了）。**漏掉这一步，负半周的正弦值会被当成 3 万多的大正数，`Σq·u` 全部算错。**

```
518    // 测量窗命中判据（2026-09-10 提频）：原式 `(acc_cycles + 32'd1) >= cfg_meas_cycles`
519    // 把「32bit 加法 + 32bit 比较」串成 17 级 CARRY4，成为综合后 pd_feature_core
520    // 的头号路径（+0.111ns，次紧路径尚有 +0.705ns，是明显离群项）。
521    // 等价改写（K = cfg_meas_cycles）：
522    //   acc+1 >= K  ⟺  acc >= K-1                （K >= 1）
523    //   acc[31:16] != 0  ⇒  acc >= 65536 > K-1   （K <= 65535）→ 直接命中
524    // 路径退化为「16bit 比较 + 16 输入或」，CARRY4 由 17 降到约 4。
525    wire [15:0] meas_k_m1    = cfg_meas_cycles - 16'd1;
526    wire        meas_win_hit = (cfg_meas_cycles != 16'd0) &&
527                               ((|acc_cycles[31:16]) || (acc_cycles[15:0] >= meas_k_m1));
```
⭐ **"等价改写省掉 13 级进位链"的精彩例子**：
- **原判据**：`(acc_cycles + 1) >= cfg_meas_cycles`。`acc_cycles` 是 32 bit，`cfg_meas_cycles` 是 16 bit → `32 bit 加法 + 32 bit 比较` = **17 级 CARRY4**，是头号时序路径。
- **改写 1（消掉 +1）**：`acc + 1 >= K` ⟺ `acc >= K − 1`（K ≥ 1）。
- **改写 2（消掉高位比较）**：K ≤ 65535 ⇒ `K − 1 ≤ 65534 < 65536`。于是：
  - 若 `acc_cycles[31:16] != 0`（即 acc ≥ 65536）→ **必定命中**，不必比低位；
  - 否则只比低 16 位。
- **收益**：退化成"16 bit 比较（约 4 级 CARRY4）+ 16 输入或门（约 2 级 LUT）"。
- ⭐ **可复用经验：在比较/判断逻辑里，先把"常数界限"分析清楚，往往能把宽位运算砍掉一半以上** —— 而不是一味"加流水线"。

### 6.2 Σq·u 累加的两拍拆分

```
534    // 原实现单拍串行 [q×u 乘法 + 64bit 累加] (130M 预检 WNS -1.056ns, 关键
535    // 路径全落在 acc_sum_qu 链)。拆两拍:
536    //   事件拍(S_ACC/S_PEAKN): 只把乘积锁存进 qu_pipe_r, 置 qu_acc_v=1;
537    //   下一拍(S_PEAKN/S_PRRD):  把 qu_pipe_r 累加进 acc_sum_qu。
538    // 事件链 S_ACC->(S_PEAKN)->S_PRRD->S_PRWR 原子执行, S_CYC 仅在 S_IDLE
539    // 被取走 -> 进 S_CYC 前 pending 必清, 周期快照/清零无需顺延, 语义不变。
540    reg signed  [63:0] qu_pipe_r;
541    reg               qu_acc_v;
```
- **原实现**：一拍内做 `q×u 乘法 + 64 bit 累加` → 预检 **WNS −1.056 ns**，关键路径全在 `acc_sum_qu` 链（64 bit 加法 = 32 级 CARRY4）。
- **拆法**：事件拍只算乘积并置 `qu_acc_v = 1`；下一拍累加。
- ⭐ **为什么不会漏累加？** 注释第 538–539 行给了论证：状态链是 `S_ACC → (S_PEAKN) → S_PRRD → S_PRWR` **原子执行**（中间不会被打断回 `S_IDLE`），且 `S_PRRD`（第 822–825 行）会再检查 `qu_acc_v` 作为**兜底**。
- ⭐ **设计纪律：改流水线时必须逐条路径验证"数据不会丢"，不能只说"加了拍应该没问题"。**

### 6.3 事件序号

```
546    localparam PH_FIELD_W = `PD_PH_FIELD_W;      // 10 或 12
547    localparam EVT_SEQ_W  = 37 - PH_FIELD_W;     // 27 或 25
550    reg [EVT_SEQ_W-1:0] evt_seq;
```
- `evt_seq` 是**每通道自增的事件序号**，作用是**让 PS 检测丢帧**（序号不连续即丢）。
- **"自然回绕"而不是"饱和"**：回绕后差值仍表示增量，PS 按无符号差值判连续即可；若饱和（停在最大值）就无法继续区分事件。25 bit 在每周期约 4 个事件时可数约 `2²⁵/4 ≈ 8.4M` 个周期 ≈ **46 小时**才回绕。

### 6.4 峰值事件包

```
553    //   [63:56]  type      = 0x00 峰值事件
554    //   [55:40]  q         16bit Q8.8 视在电荷量 pC, 有符号补码
555    //   [39:30]  phase     PH_FIELD_W bit 相位窗号 (PH_FIELD_W=10 时 0~1023)
556    //   [29]     polarity  0=负 1=正  (注意: 内部 q0_pol_r 为 0=正 1=负, 故取反)
557    //   [28:27]  ch_id     通道号 0~3
558    //   [26:0]   evt_seq   每通道自增事件序号
562    wire [EV_W-1:0] ev0 = {`PD_EV_PEAK,               // [63:56]
563                           q0_pc_r,                   // [55:40]
564                           h_ph_r[PH_FIELD_W-1:0],    // phase
565                           ~q0_pol_r,                 // polarity 0=负 1=正
566                           CH_ID[1:0],                // ch_id
567                           evt_seq};                  // evt_seq
```
**事件包的权威定义（当前 `PD_PH_FIELD_W = 12` 时的实际位位置）**：

```
[63:56]  type      8 bit  = 0x00
[55:40]  q        16 bit  Q8.8 有符号（pC）
[39:28]  phase    12 bit  相位窗号
[27]     polarity  1 bit  0 = 负、1 = 正
[26:25]  ch_id     2 bit  通道号
[24:0]   evt_seq  25 bit  事件序号
                         合计 8+16+12+1+2+25 = 64 ✓
```
- ⭐ **`~q0_pol_r` 是最容易搞错的地方**：
  - 内部约定（`pd_defines.vh:27-28`）：`PD_POL_POS = 0`、`PD_POL_NEG = 1`；
  - 事件包约定：**`polarity` 字段 0 = 负、1 = 正**（与内部**相反**）；
  - 所以拼接时**必须取反**。这是"两套极性约定"的历史包袱，改任一处都要检查另一处。
- ⚠️ **【注释与实际不符】** 第 555–558 行注释写的是 **`PH_FIELD_W = 10` 时的位位置**（`[39:30]`/`[29]`/`[28:27]`/`[26:0]`）。当前 12 位时实际是 `[39:28]`/`[27]`/`[26:25]`/`[24:0]`。**testbench 用的是正确位置**（`tb_pd_feature_dds.v:78`）。→ 注释未随参数更新，B09 已记录。
- `ev1`（第 568–573 行）结构与 `ev0` 完全对称，只是用 `q1_pc_r`/`q1_pol_r`（负峰）。

### 6.5 周期统计包

```
574    // 周期统计包: ch_id 在 [31:30]（本包布局: type/cycle_idx/ch/cyc_n/qmax）。
575    //   注意: 峰值包(ev0/ev1)的 ch_id 在 [26:25] —— 两种包型位宽不同, ch 不可能
576    //   同位; 下游解析必须按 type 区分(ch 位置: 峰值 [26:25] / 周期 [31:30])。
577    wire [EV_W-1:0] evc = {`PD_EV_CYCLE, cycle_idx[TS_W-1:0],
578                           CH_ID[1:0], cyc_n[13:0], cyc_qmax[15:0]};
```
**周期统计包布局**：
```
[63:56]  type       8 bit  = 0x01
[55:32]  cycle_idx 24 bit  周期序号（绝对时间基准）
[31:30]  ch_id      2 bit  通道号
[29:16]  cyc_n     14 bit  本周期放电次数
[15:0]   cyc_qmax  16 bit  本周期最大电荷量
                           合计 8+24+2+14+16 = 64 ✓
```
- ⭐ **`cycle_idx` 是新时间基准**：`phase + cycle_idx` 已可还原事件的绝对时间（精度由相位窗大小决定），所以时间戳不再进事件包（但 `h_ts_r` 与死区逻辑必须保留）。
- ⚠️ **【观察】`cyc_n` 只有 14 bit（最大 16383）**：一个工频周期内放电超过 16383 次会**静默回绕**。26 MSPS 下 20 ms 内有 520,000 个采样，理论上可能超出。这是"位宽余量与统计口径"的取舍（B09 已记录）。
- ⚠️ **ch_id 位置随包型变化**（峰值 `[26:25]`、周期 `[31:30]`），**下游解析必须先看 `type`**。设计上的不统一（B09 已记录）。

## 7. 本篇易错点小结

1. **一个 `reg` 只能在一个 `always` 块里赋值**（`frame_ad_max_acc` 的 multi-driven 事故）。
2. **同一 `always` 块内对同一变量的多次非阻塞赋值按书写顺序决定最终值**（`win_lost` 的正确性依赖此语义）。
3. **`$signed()` 不能漏**：`sdata` 存的是补码但声明为无符号；`sin_q` 声明为无符号但存有符号值是致命的（`Σq·u` 全错）。
4. **绝对值要扩位**：`|−2048| = 2048` 需要 13 bit，12 位有符号装不下。
5. **差一拍就是错一拍**：所有"同源派生量"必须在同一拍、用同一组合表达式载入（`abs_q0_r` 与 `q0_pc_r`、`absp_max_r` 与 `h_max`）。
6. **对超出声明范围的位取选择返回 x**：不能写 `cfg_deadtime[TS_W-1:0]`（16 bit 变量选 24 位）。
7. **被覆盖前先锁存**：`close_window` 的 `wc_*` 存在的原因。
8. **"多个相关统计量要被一起读"必须同时快照**：`pos_cnt_live` → `st_pos_cnt` 的原因。
9. **位宽越宽越慢**：`u_val` 从 33 bit 收窄到 18 bit，把 2 级 DSP48 级联变成 1 级。
10. **加流水线要用"同源论证"证明语义不变**：所有流水寄存器的输入都来自同一拍已稳定的源。
11. **极性有两套约定**（内部 0=正 1=负；事件包 0=负 1=正），拼接时要取反。
12. **改流水线要逐路径验证不漏数据**：三处 `qu_acc_v` 检查点（第 727、822 行等）的存在原因。
13. **`PH_FIELD_W` 改变会移动事件包所有字段**，注释里的位位置可能未同步更新 —— **以拼接表达式为准，不以注释为准**。
14. **`cyc_n` 14 bit 可能不够**（>16383 次/周期会回绕）。
15. **`cfg_phase_win == 0` 没有保护**，会让相位窗完全错乱。
16. **POSNEG 模式下 `q0_code = h_max` 可能为负**，与硬置的 `POS` 极性矛盾。
