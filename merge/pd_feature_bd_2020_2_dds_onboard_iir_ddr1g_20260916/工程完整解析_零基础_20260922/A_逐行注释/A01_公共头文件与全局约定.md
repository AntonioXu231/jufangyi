## 1. `pd_defines.vh` —— 特征提取 IP 的公共参数

### 1.1 文件头（第 1–6 行）

```

2  // pd_defines.vh  --  局部放电(DP)特征提取 IP 公共参数定义
```

- 第 1–4 行是注释。**注意第 3 行写的器件是 `clg484`，与工程实际使用的 `clg400` 不一致**——这是文档漂移，不是功能错误。工程实际器件以 `.xpr`（`xc7z020clg400-2`）为准。→ 见 `B09` 的风险清单。
- 第 5–6 行是 **include guard（防止重复包含的保护宏）**：`ifndef` 判断"如果 `_PD_DEFINES_VH_` 还没定义过"，`define` 就定义它。这样一来同一个文件被 `include` 多次时，第二次起会被内容跳过，避免宏重复定义报错。

```

9  `define PD_ADC_W        12          // ADS805E 12bit 并行输出
10 `define PD_PH_W         12          // 相位窗索引位宽(支持最大 2048 窗/周期)
11 `define PD_TS_W         24          // 时间戳位宽(单位: ADC 样本周期 50ns, 溢出 ~0.84s)
```

逐条解释：

| 宏 | 值 | 含义与推演 |
|---|---|---|
| `PD_ADC_W` | 12 | 每通道 ADC 分辨率。这里注释写 ADS805E，而 `pd_ddr_defines.vh:22` 写 AD9226——两个器件名并存只说明**模拟前端型号还没最终锁死**，但**位宽 12 是一致的**，所以对 RTL 无影响。 |
| `PD_PH_W` | 12 | 相位窗索引位宽。**12 bit 能表示 0…4095，为什么注释说"最大 2048 窗"？** 因为窗数 N 本身是配置量：`PD_PH_INC_1024` 对应 N=1024。设计上限制 N ≤ 2048，12 bit 索引（0…2047）刚好够。这是"位宽比当前需要宽一点"的余量设计。 |
| `PD_TS_W` | 24 | 时间戳位宽，单位是 ADC 采样周期。注释写"50 ns"是按 20 MSPS 算的（1/20M = 50 ns）；**当前工程是 26 MSPS，实际单位是 38.46 ns**。溢出时间：2²⁴×38.46 ns ≈ 0.645 s（注释的 0.84 s 是 20 MSPS 下的值）。→ 这两个数字都随采样率变，读代码时以"按实际采样率换算"为准。 |
| `PD_EV_W` | 64 | 事件包宽度，8 字节。之所以选 8 字节，是为了让 AXI-Stream 每次握手搬运正好一个 64 bit beat，与下游 AXI DMA 的 `c_m_axi_s2mm_data_width = 64`（见 `.bd`）对齐。 |

```

16 // 1: PP      窗口内峰峰值 (max - min)
17 // 2: POSNEG  正峰/负峰各输出一个事件 (改进版, 缓解 F2 段内合并)
18 `define PD_MODE_ABSMAX  2'd0
19 `define PD_MODE_PP      2'd1
20 `define PD_MODE_POSNEG  2'd2

23 `define PD_EV_PEAK      8'h00       // 峰值事件
24 `define PD_EV_CYCLE     8'h01       // 周期统计包(帧尾, tlast=1)
25

27 `define PD_POL_POS      1'b0
28 `define PD_POL_NEG      1'b1
```
- 三种峰值模式是**同一个窗口统计出的三个不同派生量**，由寄存器 `CFG0[1:0]` 选择（见 `pd_axil_regs.v:206`）。注意 `PD_MODE_POSNEG` 会让状态机多走一个 `S_PEAKN` 拍，即"一个相位窗可能发两个事件"。
- 事件包类型占 `EV[63:56]`（最高 8 位）：`0x00` = 峰值事件、`0x01` = 周期统计包。**这两个宏是下游软件（PS 的 C 代码）解析事件流的第一把钥匙**——`pd_acquisition_core.c:89-92` 就是按 `type==0 → peaks++ / type==1 → cycles++` 来分类的。
- 极性宏：`PD_POL_POS = 0`、`PD_POL_NEG = 1`。⚠️ **这是"内部约定"，与事件包里的 polarity 字段恰好相反**：见 `pd_feature_core.v:565` 用了 `~q0_pol_r`，而包注释写 `[29] polarity 0=负 1=正`。这是本工程一个很容易搞错的地方，详见 A04 与 B09。

```
30 // ---- 峰值事件包内 phase 字段位宽 ----
31 // 12: 与 B 侧 RTL 一致 (支持相位窗数 N≤2048, 已定案 2026-09-08)
32 // 10: A 接口文档 §6.2 曾定义 (窗号 0~1023); 若需切回只改本行。
33 // 位宽联动: EVT_SEQ_W = 37 - PH_FIELD_W, 保证事件包总宽恒为 64bit
34 //   PH_FIELD_W=10 -> evt_seq 27bit (8+16+10+1+2+27=64)
35 //   PH_FIELD_W=12 -> evt_seq 25bit (8+16+12+1+2+25=64)
36 `define PD_PH_FIELD_W   12
```
这是**全工程最重要的一个"单点定义"**：
- `PD_PH_FIELD_W` 决定峰值事件包里 phase 字段占几位。
- 因为事件包总宽恒为 64 bit，phase 变宽就必须让 `evt_seq`（事件序号）变窄。所以第 33 行的恒等式必须成立：`8(type) + 16(q) + PH_FIELD_W(phase) + 1(polarity) + 2(ch_id) + EVT_SEQ_W = 64`，即 `EVT_SEQ_W = 64 − 27 − PH_FIELD_W = 37 − PH_FIELD_W`。
- **改这一行会连锁改变事件包的位位置**，下游（PS 解析、testbench、ILA 观察）必须同步改。这就是"单点定义"的意义：只改一处，但要知道它牵动多少处。当前值 12 → `EVT_SEQ_W = 25`。

```
38 // ---- 默认配置值 ----
39 // 相位增量 = round(2^32 / N), N=1024 -> 4194304 = 0x00400000
40 `define PD_PH_INC_1024  32'h0040_0000
41 // 默认同步周期 ADC 样本数: 20MSPS / 50Hz = 400000 (首次同步前的兜底值)
42 `define PD_M_DEFAULT    32'd400000
43
44 `endif
```
- `PD_PH_INC_1024 = 2³²/1024 = 4194304 = 0x0040_0000`。这是"用 32 bit 无符号整数表示一圈 360°"的**相位累加器步长**：每过 1/1024 圈就累加这么多，溢出自动回绕。用 2³² 做整除的好处是"除以 2 的幂"在硬件里就是取高位，不需要除法器。
- `PD_M_DEFAULT = 400000` 是**首次同步到来之前的兜底周期长度**。当前工程实际是 26 MSPS / 50 Hz = 520,000，所以这个默认值只有在"还没锁到同步信号"的头一个周期里短暂起作用。

### 2.1 文件头与"关键数字速查"（第 1–16 行）

```
1  // =====...
2  // pd_ddr_defines.vh  --  局放检测仪 DDR 环形缓存 / 冻结快照 公共定义
3  // ---
4  // 依据文件（唯一接口基准，改动须先改文档再动代码）：
5  //   [1] 《接口契约 v1.0》         §1 全局参数  §3 IF-3 PL<->DDR 原始数据
6  //   [2] 《开发目标.docx》         §2.2 数据流  §2.3.1 PL 端模块
7  //   [3] PG022  AXI DataMover     命令字 / 状态字位域
```
这一行注释 `改动须先改文档再动代码` 是本工程的一条**成文纪律**：任何接口语义变更，必须先在接口契约文档里落地，再改 RTL。读代码时如果发现"代码与契约不一致"，按此纪律应以"改契约"或"改代码"其中之一为准，而不是默默两边都改。

```
9  // 关键数字速查（本文件全部常量的推导依据）：
10 //   当前验证：4 通道 x 12bit x 26MSPS = 48bit x 26MHz = 156 MB/s 原始码流
11 //   192bit 块 = 4 个 48bit 字 = 24 Byte  （契约 §3.2，100% 利用率无填充）
12 //   AXI 位宽 64bit = 8 Byte   -> 1 块 = 3 个 AXI beat
13 //   130MHz x 8B = 1040 MB/s 总线能力 -> 占用率 15%，余量充足
```
**这三行是理解整个 DDR 支路带宽的钥匙**，逐条验算：

| 项目 | 来源 | 实算 |
|---|---|---|
| 原始码流 | 4 ch × 12 bit × 26 MSPS | 48 bit/采样 × 26 M/s = 1248 Mbit/s **= 156 MB/s**（1 Byte = 8 bit，1248/8 = 156） |
| 192 bit 块 | 4 个 48 bit 字 | 192 bit = **24 字节**，恰好能被 8 整除 → 100% 利用，无填充字节 |
| AXI beat | 64 bit = 8 字节 | 24 ÷ 8 = **3 个 beat/块** |
| 总线能力 | 130 MHz × 64 bit | 130 M × 8 B = **1040 MB/s** |
| 占用率 | 156 / 1040 | **15.0%** |

→ 结论：26 MSPS 档下 DDR 写入带宽只用掉 15%，理论上能撑到约 6 倍采样率（这也解释了为什么工程敢往 65 MSPS 走）。

### 2.2 数据通路位宽（第 18–36 行）

```
21 `define PD_CH_NUM        4                  // 通道数
22 `define PD_ADC_W         12                 // AD9226 分辨率
23 `define PD_SAMPLE_W      (`PD_CH_NUM * `PD_ADC_W)   // 48 : 一个采样时刻的 4 通道样本字
24 `define PD_WORD_PER_BLK  4                  // 4 个 48bit 字 -> 1 个块
25 `define PD_BLK_W         (`PD_SAMPLE_W * `PD_WORD_PER_BLK)  // 192
26 `define PD_BLK_BYTES     (`PD_BLK_W / 8)                   // 24
27 `define PD_AXI_DW        64                 // AXI / AXI-Stream 数据位宽
28 `define PD_AXI_BYTES     (`PD_AXI_DW / 8)   // 8
29 `define PD_BEAT_PER_BLK  (`PD_BLK_W / `PD_AXI_DW)          // 3 : 1 块 = 3 个 beat
```
- 第 23 行：`` `PD_SAMPLE_W `` 是**宏套宏**的写法——Verilog 允许在宏里引用另一个宏，展开后是 `(4 * 12) = 48`。这也是为什么改 `PD_CH_NUM` 或 `PD_ADC_W` 会自动传导到后面所有常量。
- 第 25–29 行的推导链：`PD_BLK_W = 48 × 4 = 192` → `PD_BLK_BYTES = 192/8 = 24` → `PD_BEAT_PER_BLK = 192/64 = 3`。
- ⚠️ 第 24 行 `PD_WORD_PER_BLK = 4` 是**写死的 4**，不是从什么推导来的。它表达的是"一个 DDR 块由 4 个连续采样时刻组成"，这是契约条款，不是可自由调的效率参数。

```
31 // 48bit 样本字内的通道排布（契约 §3.1，ch0 在最低位）：
32 //   [47:36] ch3   [35:24] ch2   [23:12] ch1   [11:0] ch0
33 `define PD_CH0_FIELD     11:0
34 `define PD_CH1_FIELD     23:12
35 `define PD_CH2_FIELD     35:24
36 `define PD_CH3_FIELD     47:36
```
**这 4 行是"内存里怎么解包"的唯一权威定义**。4 个宏的形式很特别（值是 `11:0` 这种位选表达式而不是数字），它们是给 `pd_pack48.v` 的显式切片用的，也可以直接写在拼接里。记住这条铁律：
> **48 bit 样本字 = `{ch3[11:0], ch2[11:0], ch1[11:0], ch0[11:0]}`，ch0 在最低 12 位。**

配合 `pd_pack192.v:6` 的小端拼接（`V = W0 + W1<<48 + W2<<96 + W3<<144`），最终 DDR 里的字节序是：
```
字节 0..5   = W0（第 1 个采样时刻，{ch3,ch2,ch1,ch0} 小端）
字节 6..11  = W1（第 2 个采样时刻）
字节 12..17 = W2
字节 18..23 = W3
```
PS 侧的 `pd_snapshot_unpack.c:6-13` 的 `decode_sample()` 就是照着这个布局逐字节拼的。

### 2.3 AXI DataMover 命令字位域（第 38–63 行）

```
39 // 2) AXI DataMover 命令字位域（PG022，32bit 地址时命令宽度 = 72bit）
41 //   [71:68] RSVD(4)   [67:64] TAG(4)   [63:32] ADDR(32)
42 //   [31]    DRR       [30]    EOF      [29:24] DSA(6)
43 //   [23]    TYPE      [22:0]  BTT(23)
45 `define DM_CMD_W         72
46 `define DM_BTT_LSB       0
47 `define DM_BTT_W         23                 // BTT[22:0]，取值 1 .. 8388607
48 `define DM_TYPE_BIT      23                 // 1 = INCR（地址递增），0 = FIXED
49 `define DM_DSA_LSB       24
50 `define DM_DSA_W         6                  // DSA[29:24]，关闭 DRE 时填 0
51 `define DM_EOF_BIT       30                 // 末拍产生 TLAST
52 `define DM_DRR_BIT       31                 // DRE 重对齐请求
53 `define DM_ADDR_LSB      32
54 `define DM_ADDR_W        32                 // ADDR[63:32]
55 `define DM_TAG_LSB       64
56 `define DM_TAG_W         4                  // TAG[67:64]
57 `define DM_RSVD_LSB      68
58 `define DM_RSVD_W        4                  // RSVD[71:68]
```
**为什么命令字是 72 bit？** 这不是设计者选的，是 AMD（原 Xilinx）AXI DataMover IP 的固定格式。它的思想是"一条命令 = 一次搬运的完整描述"：

| 字段 | 位 | 作用 | 本工程取值 |
|---|---|---|---|
| BTT | [22:0] | "要搬多少字节"（Bytes To Transfer） | 1536（正常突发）或余量长度 |
| TYPE | [23] | 地址递增(INCR) 还是固定(FIXED) | **1 = INCR**（写连续 DDR 必须递增） |
| DSA | [29:24] | 目的端地址重对齐的字节偏移 | **0**（因为不用 DRE） |
| EOF | [30] | 是否在末拍拉 TLAST | **0**（长度由 BTT 决定，不靠 TLAST） |
| DRR | [31] | 是否请求 DRE 重对齐 | **0**（关闭 DRE） |
| ADDR | [63:32] | 目标/源地址（32 bit） | 环内当前地址 |
| TAG | [67:64] | 由用户自定义的标签 | **0**（不用） |
| RSVD | [71:68] | 保留 | 0 |

- **BTT 最大 23 bit = 8,388,607 字节**，这是单条命令能搬的上限。注意本工程一次搬 1536 字节，远小于上限；上限的意义在快照拷贝那条链里（`CHUNK_BLOCKS=256 → 6144 字节/片`，见 A09）。
- **为什么关 DRE？** DRE（Data Realignment Engine）用来做"数据流任意字节偏移对齐"，会消耗额外延迟与资源。本工程所有地址都强制 24 字节对齐（见 2.4/2.5），数据天然对齐，所以不需要 DRE。**关掉 DRE 的代价是：起始地址必须 8 字节对齐。** 而 24 = 8×3，24 字节对齐自动蕴含 8 字节对齐，所以这一条被自动满足。

```
60 // DataMover 状态字（M_AXIS_S2MM_STS / M_AXIS_MM2S_STS，8bit）
61 //   实测约定：0x80 = 正常完成；0x10 = 长度不匹配/错误。
62 //   注：请按所用 DataMover 版本 PG022 "Status Stream" 表复核后微调 o_sts_err 判据。
63 `define DM_STS_OK        8'h80
```
- DataMover 每次命令完成后会回一个 **8 bit 状态字**，RTL 用它判断"这次搬运成功没有"。`0x80 = 0b1000_0000` 在 PG022 里对应 "OKAY / 正常完成"。
- ⚠️ 第 62 行的注释是**设计者自己留的不确定性提示**：不同版本的 DataMover 状态字编码可能不同。`pd_ddr_ring_wr.v:431` 与 `pd_ddr_snap_copy.v:99-103` 都拿 `!= 0x80` 当错误判据，所以如果这个约定错了，错误检测会失效（全报错或全不报错）。→ 收集到 B09。

### 2.4 DDR 分区与"对齐铁律"（第 65–83 行）

```
68 // 对齐铁律（推导见 pd_ddr_ring_wr.v 头部说明）：
69 //   a) DataMover 关闭 DRE 时，起始地址必须 8 Byte 对齐（= AXI 数据位宽）；
70 //   b) 契约 §3.3 要求块 24 Byte 对齐，故基址与长度均取 24 的整数倍；
71 //   c) 同时满足 4KB 与 24B 对齐 -> 取 LCM(4096,24) = 12288 = 0x3000 的整数倍。
73 //   校验：0x1000_2000 / 12288 = 21846  ✓； 0x07FF_E000 / 12288 = 10922 ✓
74 //         0x1800_0000 / 12288 = 32768  ✓； 0x007F_E000 / 12288 = 682    ✓
76 //   RING  : 0x1000_2000 .. 0x1800_0000   (128 MiB - 8 KiB, 24B/4KB 双对齐)
77 //   SNAP  : 0x1800_0000 .. 0x187F_E000   (  8 MiB - 8 KiB)
78 //   容量校验：50Hz 一个周期 @26MSPS = 5.2e5 样本 x 6B = 3.12 MB < 8 MiB ✓
79 //             环形深度 134.2 MB / 156 MB/s = 860 ms ≈ 43 个工频周期，远大于 1 周期 ✓
80 `define DDR_RING_BASE    32'h1000_2000
81 `define DDR_RING_SIZE    32'h07FF_E000
82 `define DDR_SNAP_BASE    32'h1800_0000
83 `define DDR_SNAP_SIZE    32'h007F_E000
```
**"对齐铁律"的完整推导（必背）**：

1. DataMover 关 DRE ⇒ 起始地址 **8 B 对齐**；
2. 契约要求每个 192 bit 块 **24 B 对齐**，即基址和长度都必须是 24 的整数倍（这样"第 k 个块"永远完整落在 `[BASE+24k, BASE+24k+24)` 内，不会横跨回绕点）；
3. AXI 协议禁止单次突发跨越 4 KB 边界（这条 DataMover 会自动拆包处理，但基址取 4 KB 对齐能减少拆包次数）；
4. 三者取交集：`LCM(4096, 24) = 12288 = 0x3000`。**所以基址和长度都取 0x3000 的整数倍。**

注意 24 = 8×3，所以"能被 24 整除"已经蕴含了第 1 条。第 73–74 行是设计者做的**实算校验**（把宏值除以 12288 看是否整除），这就是"结论必须落到实算"的工程习惯。

容量校验（第 78–79 行）的两个关键结论：
- **一份快照 3.12 MB < 8 MiB**：即使环形区不管，legacy 单快照区也装得下一个工频周期；
- **环形区深度 134.2 MB ÷ 156 MB/s = 860 ms ≈ 43 个工频周期**：意味着"快照搬运期间，新数据要写满 43 圈才会追上被冻结的那段"，给了上层充足的处理时间窗口。（注意这里 134.2 MB 是按"128 MiB − 8 KiB"约等于算的。）

### 2.5 四槽快照区（第 85–139 行）—— 全篇推演最精彩的一段

```

91 // 与 legacy SNAP 区的关系：

103 //   为什么不是交接文档原始建议的 0x2000_0000：
104 //     0x2000_0000 = 2^29，质因数只有 2、**缺因子 3**，
105 //     实测 mod 12288 = 8192、mod 24 = 8 -> 违反 (b)，一票否决。
106 //     注意它 mod 4096 = 0 是通过的，属"看起来合规"的陷阱。
107 //   为什么基址 +0x1000 恰好修正：
108 //     0x1000 mod 24 = 16；0x2000_0000 mod 24 = 8；8 + 16 = 24 ≡ 0 (mod 24)；
109 //     且 0x2000_1000 仍是 0x1000 的整数倍，(c) 不被破坏。
110 //     直观理解：沿 4 KiB 网格向前走一格，正好撞上 12 KiB 网格点。
```

这段注释值得逐句理解，因为它是"**为什么地址不是随便挑的**"的完整示范：

1. 交接文档原本建议槽区从 `0x2000_0000` 开始。`0x2000_0000 = 2²⁹`，质因数只有 2，**缺因子 3**，所以它 **不是 24 的整数倍**（实算 `0x2000_0000 mod 24 = 8`）。
2. 陷阱在于 `0x2000_0000 mod 4096 = 0` 是成立的 —— 只看 4 KB 对齐会误判"合规"。
3. 修正方法：把基址抬到 `0x2000_1000`。因为 `0x1000 mod 24 = 16`，而 `0x2000_0000 mod 24 = 8`，`16 + 8 = 24 ≡ 0 (mod 24)`，所以 `0x2000_1000` 同时满足 4 KB 与 24 B 对齐。**注意这要求 `0x2000_1000` 仍是 `0x1000` 的整数倍——它确实是**（`0x2000_1000 / 0x1000 = 0x2001`），所以 4 KB 对齐没被破坏。
4. 步长保持 12 MiB：`0x00C0_0000 = 12,582,912 = 1024 × 12288`，本身就是 0x3000 的整数倍，所以从一个对齐基址连续累加，永远停在对齐网格上。

```

112 //     0x00C0_0000 = 12,582,912 = 1024 x 12288 -> 本身即 0x3000 整数倍，
113 //     故从任一对齐基址连续累加，始终停留在对齐网格上。
115 //   实测校验（四槽基址 mod 12288 / mod 24 / mod 4096 / mod 8 全部为 0）：
116 //     slot0 0x2000_1000 .. 0x20C0_0FFF

124 //     65 MSPS：1,300,000 样本 x 6 B = 7.80 MB < 12 MiB  ✓
126 //   注意（边界语义）：槽上界用"哨兵地址"（末字节 + 1）表示，是**开区间上界**。

129 //     这是"起点 24B 对齐 且 长度 24B 整数倍"的必然结果。
130 //     -> 越界判据写 (dst_addr + len <= 哨兵)，切勿写成 (<= 末字节)。
```

**哨兵地址（sentinel）语义**（第 126–130 行）是极易写错的地方，务必记住：

- 槽的地址范围是**半开区间** `[base, base+len)`，但代码里用一个"哨兵"来表示上界：`DDR_SLOT_AREA_END = 0x2300_1000`。
- `0x2300_1000` **不是**任何一个槽里的字节，它是"最后一个槽末字节 + 1"。
- 为什么末字节 `0x2300_0FFF` 的 `mod 24 = 23`（不在网格上），而哨兵 `0x2300_1000` 的 `mod 24 = 0`？因为"起点 24 B 对齐 + 长度是 24 的整数倍"，必然导致**末字节不在网格上、末字节+1 才在网格上**。
- 所以越界判据必须写成 `(dst_addr + len <= 哨兵)`，**绝不能**写成 `<= 末字节`（那会漏掉最后一个合法字节）。

```

134 `define DDR_SLOT0_BASE      32'h2000_1000      // 锚点：唯一手写的槽基址字面量
135 `define DDR_SLOT1_BASE      (`DDR_SLOT0_BASE + `DDR_SLOT_SIZE)
136 `define DDR_SLOT2_BASE      (`DDR_SLOT1_BASE + `DDR_SLOT_SIZE)
137 `define DDR_SLOT3_BASE      (`DDR_SLOT2_BASE + `DDR_SLOT_SIZE)

```
- 第 134 行注释强调"**锚点：唯一手写的槽基址字面量**"。这是一个很好的工程习惯：整个四槽区只有一个魔法数字（`0x2000_1000`），其余三个槽基址都是"锚点 + n×槽长"推出来的，改造时只需改一处。
- 单槽 12 MiB 的容量按"**一槽容纳一个完整工频周期**"选定：26 MSPS 用 3.12 MB（余量 3.8×），即使将来上到 65 MSPS 也只要 7.80 MB（余量 1.5×）。
- `DDR_SLOT_IDX_W = 2` 正好对应 4 个槽（`$clog2(4) = 2`）。

### 2.6 突发参数（第 141–149 行）

```
144 // 每个突发命令搬运 64 个块 = 1536 Byte = 192 个 64bit beat
145 //   - 192 beat < DataMover 单次 AXI4 突发上限 256 beat，可单突发完成
146 //   - 1536 % 24 == 0，保证每个命令起止地址始终 24B 对齐
147 //   - 1536 % 8  == 0，满足关闭 DRE 时的 8B 地址对齐约束
148 `define DDR_BURST_BLOCKS 64
149 `define DDR_BURST_BYTES  (`DDR_BURST_BLOCKS * `PD_BLK_BYTES)   // 1536
```
"为什么正好 64 块"的三条理由，每一条都是一票否决级别的：
1. `64 × 24 / 8 = 192` 个 64 bit beat，**小于 AXI4 单次突发的 256 beat 上限**——超了就必须拆包，命令速率和复杂度都会上升；
2. `1536 % 24 == 0` → 每条命令的**起止地址都落在 24 B 网格上**；
3. `1536 % 8 == 0` → 满足关 DRE 的 8 B 对齐约束。
**只有同时满足这三条的一个块数才能被选**，64 是其中较小的一个合理选择。

### 2.7 本篇需要背下来的 6 条结论

1. 48 bit 样本字 = `{ch3,ch2,ch1,ch0}`，ch0 在最低位，内存小端，每 6 字节一个采样时刻。
2. 1 块 = 4 个采样时刻 = 192 bit = 24 字节 = 3 个 64 bit beat。
3. 一切 DDR 基址与长度都是 **0x3000（12288）的整数倍**（LCM(4096,24)）。
4. 槽区上界是**哨兵**（末字节+1），判据写 `<= 哨兵`。
5. 一次突发 1536 字节（64 块、192 beat），三条理由缺一不可。
6. 事件包总宽恒 64 bit，`phase` 宽度与 `evt_seq` 宽度之和恒为 37。

## 3. `pd_align24_check.v` —— 24 字节对齐检查器（一个漂亮的"避免除法器"技巧）

```
1  `timescale 1ns/1ps
3  // 32-bit 值的 24 字节对齐检查器。
5  // 24 = 8 * 3。先检查低 3 位为零，再检查 value>>3 是否能被 3 整除。
6  // 因为 16 mod 3 = 1，可把 value>>3 拆成 8 个 4-bit 数，各自求模后用
7  // 平衡加法树求和。与直接写 `% 24` 相比，不会推导出长串常数除法器。
8  module pd_align24_check (
9      input  wire [31:0] value,
10     output wire        aligned
11 );
```
### 3.1 它解决什么问题

判定"一个 32 bit 地址是不是 24 的整数倍"，最直接的写法是 `(value % 24) == 0`。但在硬件里 `% 24` 会被综合成一个**长串常数除法/取余网络**（几十级 LUT + CARRY4），在 130 MHz 下会成为关键路径。本模块用一个纯组合技巧替代它。

### 3.2 数学原理（分三步）

**第 1 步：先看能否被 8 整除。** 因为 `24 = 8 × 3`，所以"能被 24 整除" ⟺ "能被 8 整除 **且** 能被 3 整除"。能被 8 整除就是低 3 位全 0：
```
44     assign aligned = (value[2:0] == 3'b000) && div3;
```

**第 2 步：再看能否被 3 整除。** 设 `x = value >> 3`（即去掉低 3 位后剩下的 29 位数），判定 `x mod 3 == 0`。
数学事实：因为 `16 mod 3 = 1`，把 `x` 按 4 bit 一组拆开后，**每一位 4 bit 小组对 3 的余数之和 ≡ x 对 3 的余数**。

**第 3 步：用查表 + 平衡加法树算余数和。**

```
12     function [1:0] nibble_mod3;
13         input [3:0] nibble;
15             case (nibble)
16                 4'd0, 4'd3, 4'd6, 4'd9, 4'd12, 4'd15: nibble_mod3 = 2'd0;
17                 4'd1, 4'd4, 4'd7, 4'd10, 4'd13:       nibble_mod3 = 2'd1;
18                 default:                              nibble_mod3 = 2'd2;
19             endcase
```
- 第 12–21 行是一个 4 bit 输入的"除 3 取余"查找表（函数）：0,3,6,9,12,15 → 余 0；1,4,7,10,13 → 余 1；其余（2,5,8,11,14）→ 余 2。综合后就是一个小 LUT，没有算术逻辑。

```
23     wire [1:0] r0 = nibble_mod3(value[6:3]);
24     wire [1:0] r1 = nibble_mod3(value[10:7]);
25     wire [1:0] r2 = nibble_mod3(value[14:11]);
26     wire [1:0] r3 = nibble_mod3(value[18:15]);
27     wire [1:0] r4 = nibble_mod3(value[22:19]);
28     wire [1:0] r5 = nibble_mod3(value[26:23]);
29     wire [1:0] r6 = nibble_mod3(value[30:27]);
30     wire [1:0] r7 = nibble_mod3({3'b000, value[31]});
```
- 注意切片起点是 `[6:3]` 而不是 `[3:0]`——**因为低 3 位已经单独判过 8 对齐了，所以从 bit3 开始按 4 bit 一组切**。这正好对应"先 `>>3` 再分组"。
- 共 8 组（bit 3..31 共 29 bit，最后补齐到 32 bit 的位补 0）：
  `r0=value[6:3]`、`r1=value[10:7]`、…、`r7={000,value[31]}`。

```
32     wire [2:0] s01 = r0 + r1;
33     wire [2:0] s23 = r2 + r3;
34     wire [2:0] s45 = r4 + r5;
35     wire [2:0] s67 = r6 + r7;
36     wire [3:0] s03 = s01 + s23;
37     wire [3:0] s47 = s45 + s67;
38     wire [4:0] residue_sum = s03 + s47;
```
- 这是一个**平衡加法树**：8 个 2 bit 余数 → 4 个 3 bit 部分和 → 2 个 4 bit → 1 个 5 bit。树形结构让组合深度只有 log₂(8) = 3 级，而不是串行 7 级。这是"加法树"相对于"串行累加"的核心优势。

```
40     wire div3 = (residue_sum == 5'd0)  || (residue_sum == 5'd3)  ||
41                 (residue_sum == 5'd6)  || (residue_sum == 5'd9)  ||
42                 (residue_sum == 5'd12) || (residue_sum == 5'd15);
```
- 余数和最大是 `8 × 2 = 16`，所以可能的 3 的倍数是 0,3,6,9,12,15（15 是 ≤16 的最大 3 的倍数；16 不可能是和，因为需要 8 个 2 恰好全满且…严格说 16 需 8×2，是可能的，但 16 mod 3 = 1 ≠ 0，所以不在表里）。**这个"漏掉 16"的写法是正确的**，因为 16 本来就不是 3 的倍数。
- 第 44 行把两个条件与起来：`aligned = (低3位为0) && (余数和是3的倍数)`。

### 3.3 这个模块被谁用

- `pd_ddr_snap_copy.v:107-109` —— 检查 `i_src_addr` / `i_dst_addr` / `i_len_bytes` 三个值；
- `pd_ddr_slot_mgr.v:60-65` —— 检查 `i_freeze_base` / `i_freeze_len`。

**为什么这两个模块需要它？** 因为它们是"防呆"的最后一道闸：如果 PS 下发的快照基址/长度不是 24 B 对齐，直接执行拷贝会写出错位的数据（后续解包全错），所以宁可在启动前拒绝（`o_err` 置位、不产生 `done`），也不要产生一份"看起来成功但内容错位"的快照。

### 3.4 一个可复用的通用结论

> **在硬件里判"能整除常数"时，优先用"分解成 x·y + 查表 + 加法树"，不要直接写 `%`。**

本模块是这条结论的标准范例；`pd_ddr_slot_mgr.v:57-59` 的注释还特别说明"**写成 `% 24` 会让 Vivado 在 freeze 描述符路径上推导出很深的 32 bit 余数网络**"——即设计者正是因为踩过这个坑才抽出这个模块的。

## 4. `pd_feature_bd_timing.xdc` —— 约束文件（24 行）

```
1
2  # adc_clk_0 is the external 26 MSPS sampling clock for all four ADC channels.
3  # Core-board PL 50 MHz oscillator, net name PL_GCLK.
4  set_property PACKAGE_PIN U18 [get_ports pl_gclk_50]
5  set_property IOSTANDARD LVCMOS33 [get_ports pl_gclk_50]
6  create_clock -name pl_gclk_50 -period 20.000 [get_ports pl_gclk_50]
7  create_clock -name adc_clk -period 38.461538 [get_ports adc_clk_0]
```
逐行解释：
- 第 4 行：把顶层端口 `pl_gclk_50` 绑定到芯片封装引脚 **U18**。这是"物理位置约束"。
- 第 5 行：声明该引脚的电平标准为 **LVCMOS33**（3.3 V 单端 CMOS）。这是"电气标准约束"，写错会损伤器件或无法识别。
- 第 6 行：为 `pl_gclk_50` 建立**主时钟约束**，周期 20.000 ns → 频率 50 MHz。约束里 `-period` 用的是纳秒，`20.000` 精确到 ps。
- 第 7 行：为 `adc_clk_0` 建立主时钟，周期 38.461538 ns → `1/38.461538ns = 26.0000 MHz`。

**【观察 · 重要】** 第 7 行给 `adc_clk_0` 建了时钟，但**顶层 `pd_feature_bd_wrapper` 里没有名为 `adc_clk_0` 的端口**——顶层的时钟端口是 `pl_gclk_50`（见 `.bd` 的 `ports` 段只有 `pl_gclk_50`；`.bd` 顶层 `interface_ports` 只有 `DDR` 与 `FIXED_IO`）。因此：
- 在**当前 DDS 自激励配置**下，`create_clock ... [get_ports adc_clk_0]` 是**空转**的（`get_ports` 返回空集，Vivado 会报 warning 但继续）；
- 26 MHz 的 ADC 时钟实际来自 `clk_wiz_0/clk_out2`（MMCM 生成时钟），它由 `pl_gclk_50` 经过 MMCM 自动推导，**不需要**独立 `create_clock`；
- 结论：这行约束在真实 ADC 板卡接进来之前**不起作用**，将来接入外部 ADC 时钟时必须修正端口名。→ 收集到 B09。

```
9  # adc_clk_0 and clk_130 are asynchronous at the BD boundary.  Their intended
10 # crossings are the two independent async FIFOs in pd_ddr_wr_top.
11 # XDC accepts constraint commands only. Do not wrap this in Tcl conditionals:
12 # `if` is rejected by the XDC parser and causes the asynchronous FIFO crossings
13 # to be analyzed as unrelated synchronous paths.
14 set_clock_groups -asynchronous \
15 -group [get_clocks adc_clk] \
16 -group [get_clocks -of_objects [get_pins -hierarchical *clk_wiz_0*/clk_out1]]
```
- 第 14–16 行：把 `adc_clk` 与 `clk_wiz_0/clk_out1` 声明为**互不相关的异步时钟组**。
- **为什么要声明？** 默认情况下 Vivado 会把所有时钟之间的关系都做时序分析，如果两个时钟实际异步、却被当作有确定相位关系去分析，就会出现大量"假的时序违例"（工程上叫 false path）。声明 `set_clock_groups -asynchronous` 就是告诉工具："这两组时钟之间的路径不用做建立/保持分析，它们的跨域由设计里的异步 FIFO 负责。"
- 第 11–13 行的注释是一条真实教训：**XDC 解析器只接受约束命令，不接受 Tcl 的 `if` 条件判断**。如果写 `if {...}`，XDC 会拒绝整条语句，导致异步声明失效、跨域路径被当同步路径分析。这是"约束文件不是脚本"的重要区别。

```
18 # PS FCLK0 and clk_wiz_0/clk_out1 now originate from independent sources:
19 # PS PLL and the external PL_GCLK 50 MHz oscillator, respectively.  The only
20 # FCLK0 destination is the diagnostic ILA; its probes sample lock/reset
21 # levels for observation and create no functional CDC data transfer.
22 set_clock_groups -asynchronous \
23 -group [get_clocks clk_fpga_0] \
24 -group [get_clocks -of_objects [get_pins -hierarchical *clk_wiz_0*/clk_out1]]
```
- 第 22–24 行：把 PS 的 `clk_fpga_0`（即 `FCLK_CLK0`）与 `clk_out1` 也声明为异步。
- 读懂第 18–21 行的注释很关键：**在当前 BD 里，`processing_system7_0/FCLK_CLK0` 唯一的下游只有 `ila_clk_reset_diag_0/clk`（一个诊断 ILA）**。也就是说 PL 的 130 MHz 已经**不再来自 PS 的 FCLK0**，而来自外部 50 MHz 晶振经 MMCM 产生（见 `.bd` 里 `clk_wiz_0` 的 `PRIM_IN_FREQ = 50`）。所以这条异步声明只是为了让工具对"诊断 ILA 的采样时钟"不做无谓分析。

### 4.1 约束文件在整套流程里的位置

```
RTL 源码  ──┐
            ├─► 综合 Synthesis ─► 实现 Implementation ─► 比特流 Bitstream
XDC 约束 ──┘                                          └─► 时序报告 timing_summary_routed.rpt
                                                          （看 WNS / TNS / WHS / THS）
```
- **WNS**（Worst Negative Slack）：最差建立时间裕量，负数表示最差的那条路径没跑赢时钟，必须修。
- **TNS**（Total Negative Slack）：所有违例路径的负裕量之和。
- **WHS / THS**：保持时间（hold）的对应指标。
- 约束写错（例如时钟周期写宽了、异步关系漏声明）会得到**假的"时序通过"**。所以 B09 里把"约束与端口名不匹配"列为需要复核的项目。

1. `pd_defines.vh:3` 写 `clg484`，工程实际是 `clg400` —— 注释漂移，不影响功能但会误导。
2. `PD_TS_W` 的时间单位注释按 20 MSPS（50 ns）写，当前是 26 MSPS（38.46 ns）—— 换算时必须按实际采样率。
3. `PD_POL_POS/NEG`（内部）与事件包 `polarity` 字段**语义相反**（代码里用 `~q0_pol_r` 翻转）。
4. `PD_SAMPLE_W` 等宏是"宏套宏"，改上游宏会自动传导 —— 这是好事，但改动前要确认下游能否承受。
5. `%` 与 `/` 在硬件里很贵；判对齐用 `pd_align24_check.v`（查表+加法树），不要写 `% 24`。
6. **槽区上界是哨兵（末字节+1）**，判据 `<=` 哨兵，不能写 `<` 末字节。
7. XDC 只接受约束命令，**不能写 Tcl 的 `if`**，否则整条异步声明失效。
8. `create_clock ... [get_ports adc_clk_0]` 在当前顶层无对应端口 —— 空转，待真实 ADC 接入时修正。
9. `DM_STS_OK = 0x80` 是设计者按"实测约定"写的，注释里自己要求"按 PG022 版本复核" —— 错误判据依赖它。
10. 事件包总宽恒 64 bit 的恒等式：`8 + 16 + PD_PH_FIELD_W + 1 + 2 + (37 − PD_PH_FIELD_W) = 64`。
