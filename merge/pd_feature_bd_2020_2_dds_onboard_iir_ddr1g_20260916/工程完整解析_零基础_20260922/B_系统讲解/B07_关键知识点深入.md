## 知识点 1 · Block RAM 的 6 条推断规则

### ① 是什么
FPGA 里有专用的「块状 RAM」（Block RAM / BRAM），比用触发器搭的「分布式 RAM」省资源、跑得快。但 Vivado 综合器（synth）**不是你写 `reg [63:0] mem [0:255]` 就一定是 BRAM**，它有一套「推断规则」。满足规则就自动用上 BRAM；不满足就退化成 LUT/触发器，甚至综合失败。

### ② 为什么
BRAM 是固定硬件单元：单端口/双端口、同步读、写有固定时序。综合器只能把「符合它脾气」的代码映射上去。工程里 `pd_axis_fifo.v` 就靠这套规则把 256×64bit 的 FIFO 数据体塞进了 1 个 RAMB36。

### ③ 工程里的真实代码（`pd_axis_fifo.v:5-34`、`99-129`）
对照实测（xc7z020clg484-2，DATA_W=64/DEPTH=256）：
- **组合读 + 异步复位** 写法 → 资源 **4852 LUT + 16764 FF + 2210 MUXF7 + 1105 MUXF8 + 0 BRAM**（没用上 BRAM，资源爆炸）。
- **同步读 + 地址回指** 写法 → 资源 **36 LUT + 27 FF + 0 MUXF7/8 + 1 RAMB36**（用上了 BRAM，资源骤降）。

6 条规则（本工程用到的）：
1. **写不能带异步复位块**：BRAM 单元不支持「复位时整体写」。
2. **读必须同步**（时钟沿读数），不要写 `assign rd_data = mem[addr]`（组合读）。
3. **读地址无条件更新**（每拍都给地址，不要只在 `if(en)` 里改地址，否则推断成寄存器）。
4. **不要给 BRAM 初值**（综合器对 BRAM 初始值支持有限，且上电即 0 即可）。
5. **显式标注 `(* ram_style = "block" *)`**，让综合器别「自作主张」。
6. **一个端口只做一种事**：一个口要么只读、要么只写（单口）；要读写同址用双口但分两个端口。

### ④ 常见错误
- 在 `always @(posedge clk or negedge rst_n)` 里对 `mem` 写 + 同时用 `rst_n` 清零整个 mem → 综合器无法映射到 BRAM，爆 LUT。
- 用 `rd_data = mem[raddr]` 组合读 → 退化成分布式 RAM 或 F7/F8 多路器，时序差。
- 忘了 `ram_style` 标注，综合器在 LUTRAM 和 BRAM 之间「猜」，结果不一致。

## 知识点 2 · 异步 FIFO 的格雷码（Gray Code）指针

### ① 是什么
不同时钟域之间传数据，用「异步 FIFO」：写侧用写时钟，读侧用读时钟，中间一块双口 RAM。难点是：**读侧要判断「满」（full），写侧要判断「空」（empty），而判断要用到对方的指针，指针跨时钟域会出错。** 解决法是把二进制指针换成**格雷码**再跨域。

### ② 为什么
二进制指针跨时钟域时，可能多位同时翻转（如 `0111→1000` 4 位都变），采样瞬间会采到中间态，导致误判空满。格雷码**每次只变 1 位**，跨域最多采到「旧值或新值」，不会采到非法态。

### ③ 工程里的真实代码（`async_fifo.v:8-20`、`78-92`）
```verilog
// 满判断：把 rd_ptr 转格雷后跨到写侧，再与写侧 wr_ptr_gray 比较
// 关键：高 2 位取反后比较（见下）
assign full  = (wr_ptr_gray == {~rd_ptr_gray[PTR_W-1], ~rd_ptr_gray[PTR_W-2], rd_ptr_gray[PTR_W-3:0]});
```
注意 `{~rd[PTR_W-1], ~rd[PTR_W-2], rd[PTR_W-3:0]}`：**满检测需要把最高两位都取反**，只取反一位会漏判。读数据有 **2 拍延迟**（`rd_data` 经格雷码同步 + RAM 读）。

### ④ 常见错误
- 满/空判断只取反最高 1 位格雷码 → 指针绕一圈时误判，FIFO 提前报满或永不报满。
- 把 `rd_data` 当成「写完立刻能读」→ 实际有 2 拍延迟，状态机要等 `rd_valid`。
- 指针位宽不够（PTR_W 要比 DEPTH 的 log2 多 1 位用于区分空满）。

## 知识点 3 · 流水线拆分（Pipeline Splitting）与时序收敛

### ① 是什么
「时序收敛」= 每条组合逻辑路径在两个时钟沿之间跑完，不超时钟周期（本工程 PL 时钟 130MHz，周期 ≈7.69ns）。当一段组合逻辑太长（如 34 级加法链），就把它**拆成多个时钟拍**，每拍只算一段，靠寄存器暂存中间结果。

### ② 为什么
130MHz 下，34 级累加（`Σ|q|`、`Σq·u`）如果全在一个组合云里，路径延迟远超 7.69ns，实现阶段报负余量（WNS<0）。拆成多级流水后每级延迟变小，就能过。

### ③ 工程里的真实代码（`pd_feature_core.v`）
- **abs13 拆分**：原 12bit 绝对值组合算，拆短（`pd_feature_core.v:114-119` 的 `abs13` 函数 + 多级流水）。
- **状态机拆拍**：`S_PEAK → S_Q1 → S_Q2 → S_ACC` 把原本 34 级的组合动作分到 3 拍（`pd_feature_core.v:131-133` 状态定义，`:397-451` 注释与实现）。
- **`Σq·u` 拆 2 级**：乘法与累加分拍。
- **`meas_win_hit` 重构**：原 17 级 CARRY4 长链，重写为 **4 级 CARRY4**（`pd_feature_core.v:526-527`）。
- **`u_val` 单 DSP48E1**：18×16 乘法用 1 个 DSP（`pd_feature_core.v:406-410`）。

### ④ 常见错误
- 拆流水时忘了「边界一致性」：某寄存器在 S_PEAK 采样、某寄存器在 S_Q1 才稳定，混用导致事件包里混入上一窗口的值。
- 拆拍后握手（`ev_tvalid/ev_tready`）没跟着对齐，下游收到错位数据。
- 以为拆流水能「加速」——流水不减少单条延迟，只提高吞吐、降低单级延迟以过时序。

## 知识点 4 · 位宽收窄（Bit-width Narrowing）

### ① 是什么
中间信号不需要全程 32bit，提前截到够用的最小位宽，省 DSP/LUT/布线。

### ② 为什么
`u_val = $signed(cfg_upeak) * $signed(sin_q) >>> 15`（乘法结果 18×15→33bit），但后续只用其中一段，于是锁存成 **18bit** 的 `u_val_r`（`pd_feature_core.v:406-410`）。收窄后后续比较/累加更省资源。

### ③ 工程里的真实代码
```verilog
// pd_feature_core.v:406-410
reg [17:0] u_val_r;   // 18bit 足够：upeak(18)x sin_q(15)>>15 后有效位 ≈18
```
`u_val_r` 用 18bit 而非 33bit，是因为 `>>15` 后高位无意义，截掉不影响精度。

### ④ 常见错误
- 收窄过头：把符号位或进位位截掉，导致饱和判断失效。
- 和「符号扩展」搞混：收窄是无损截断高位 0/符号扩展位；符号扩展是补位。

## 知识点 5 · 符号扩展（Sign Extension）

### ① 是什么
把一个「短的有符号数」接到「长的有符号数」上时，要在高位**重复填它的符号位（最高位）**，而不是填 0。填 0 会把负数变成正数。

### ② 为什么
12bit ADC 码 `-100` 是 `1111_1001_1100`；要送进 16bit 运算，高位必须填 4 个 `1` 得 `1111_1111_1001_1100`，值才还是 `-100`。填 0 会变成 `0000_1111_1001_1100 = +3996`，完全错。

### ③ 工程里的真实代码（`pd_iir_biquad.v:43-44`）
```verilog
wire signed [15:0] pa_ext = {{16-ADC_W{pa[ADC_W-1]}}, pa}; // 把 ADC_W 位符号扩展到 16
wire signed [15:0] pb_ext = {{16-ADC_W{pb[ADC_W-1]}}, pb};
```
`{16-ADC_W{pa[ADC_W-1]}}` = 把 `pa` 的最高位复制 `(16-ADC_W)` 份填到高位。

### ④ 常见错误
- 写 `{ {(16-ADC_W){1'b0}}, pa }` 零扩展 → 负数变正数，IIR 输出炸掉。
- 在 `signed`/`unsigned` 混用时用 `unsigned` 做扩展 → 符号位被当成数值。

## 知识点 6 · 饱和（Saturation）

### ① 是什么
运算结果超过目标位宽能表示的范围时，**截断到最大/最小有效值**，而不是回绕（溢出后从另一端开始）。

### ② 为什么
音频/电量信号溢出回绕会产生巨大尖刺，破坏 PRPD 图。IIR、DDS 输出都要饱和到合法范围。

### ③ 工程里的真实代码
- IIR 输出饱和到 16bit 有符号（`pd_iir_biquad.v:52-53` 的 `sat16`）：
```verilog
wire signed [15:0] sat16 = (&y[18:15]) ? y[15:0] :  // 高 4 位全 0 或全 1 才有效
       (y[18] ? 16'h8000 : 16'h7FFF);                // 负数饱和到 0x8000，正数到 0x7FFF
```
- DDS 输出饱和到 12bit（`pd_dds_adc_source.v:61-71` 的 `saturate_u12`）。

### ④ 常见错误
- 用 `y[15:0]` 直接截低位 → 溢出回绕，出现假脉冲。
- 饱和判断只看符号位不看高位一致性（`&y[18:15]` 必须全同才表示没溢出）。

## 知识点 7 · 有符号 / 无符号（Signed / Unsigned）

### ① 是什么
Verilog 里 `reg [7:0]` 默认**无符号**。要做负数运算必须用 `signed` 或手动按补码处理。`$signed()` / `$unsigned()` 做类型转换。

### ② 为什么
`Σq·u`、`u_val`、电荷 `q` 都是带符号量（可正可负）。用无符号算 `-100 × +5` 会得到全正数结果，PRPD 极性全错。

### ③ 工程里的真实代码
- `pd_feature_core.v:496`：`u_val = $signed(cfg_upeak) * $signed(sin_q) >>> 15;`——两端都转 signed，右移才是算术移位。
- `pd_iir_biquad.v:43-44`：先符号扩展再当 signed 算。

### ④ 常见错误
- `>>> ` 对无符号数是**逻辑移位**（补 0）；对 signed 才是算术移位（补符号）。混用位数错位。
- 比较 `< 0` 时变量是 unsigned → 永远 false，死区/极性判断失效。

## 知识点 8 · 定点数（Q 格式）：Q8.8 / Q2.16 / Q15

### ① 是什么
没有浮点单元（PL 侧）时，用「整数 + 隐含小数点」表示小数，叫**定点数**。Qm.n 表示「整数部分 m 位、小数部分 n 位」，数值 = 存储整数 / 2ⁿ。

### ② 为什么
- **Q8.8**：`cfg_scale` 这类增益系数（0~某范围小数），8 位小数够精度又不占位宽。
- **Q2.16**：IIR 系数（`CW=18, FW=16`），18bit 总宽、16bit 小数 → 系数范围约 ±2、精度 2⁻¹⁶（`pd_ddr_defines.vh` 与 `pd_filter_chain.v` 的 `coef`）。
- **Q15**：正弦表 `sin_lut` 输出（`pd_spectrum.c` 与 DDS），16bit 中 1 符号 +15 小数，范围 [-1,1)。

### ③ 工程里的真实代码
- `pd_defines.vh:39`：`PD_PH_INC_1024 = 32'h0040_0000`（=2³²/1024，相位增量用「整数/2³²」定点，等同 Q32.0 做累加）。
- `pd_feature_core.v:496`：`u_val = ... >>> 15` 把 Q15×某数变回目标。
- `pd_spectrum.c` 的 `q15_mul`（`pd_spectrum.c:32-37`）：`(a*b + (1<<14)) >> 15` 做四舍五入 Q15 乘法。

### ④ 常见错误
- 移位位数与 Q 格式不匹配：`>>15` 却以为是 Q16 → 差一倍。
- 两个不同 Q 格式直接相加不先对齐小数位 → 数量级错。
- 忘记「乘完要再移位」：Q15×Q15 得 Q30，必须 `>>15` 才回到 Q15。

## 知识点 9 · AXI4-Stream 握手（valid/ready）

### ① 是什么
流式总线 AXI4-Stream 用两根握手线：`valid`（主说「数据好了」）和 `ready`（从说「我能收」）。**只有 `valid && ready` 的同一拍，数据才真正传输**。

### ② 为什么
这是反压（backpressure）机制：下游忙时拉低 `ready`，上游必须**保持 `valid` 和 data 不变** 直到握手成功。规则：**`valid` 不能依赖 `ready` 组合生成**（否则形成组合环）。

### ③ 工程里的真实代码（`pd_ddr_snap_copy.v:174-176`）
```verilog
// valid 必须一直保持，直到出现真实的 valid&&ready 握手
// 错误写法：if(ready) valid<=0;  正确：用状态寄存, 握手成功才清
```
`pd_ddr_snap_copy.v` 的注释明确指出「valid 必须保持到真实握手发生」，这是实战踩坑总结。

### ④ 常见错误
- `valid` 一拍有效没等 `ready` 就拉低 → 数据丢失。
- 用 `assign valid = ready && data_ok` → 组合环，综合告警且行为错。
- `ready` 拉低后还改 `data` → 下游采到不一致数据。

## 知识点 10 · AXI4-Lite 的 AW 通道与 W 通道「相互独立」

### ① 是什么
AXI4-Lite 写事务分两路：**AW**（写地址）和 **W**（写数据），协议允许它们**乱序到达**（先来 W 或先来 AW 都行）。`B`（写响应）要在两者都到后才发。

### ② 为什么
总线可以缓冲 AW/W 各自排队，提高吞吐。但很多简化从设备**错误地要求 AW 和 W 同一拍到**，违反协议，遇到「先 W 后 AW」的主设备就死锁。

### ③ 工程里的真实代码
- `pd_axil_regs.v:260/281/287`：要求 `aw_valid && w_valid` **同时有效** 才处理 → 与协议「AW/W 独立」相悖（**事实，非推测**）。
- 对比 `pd_ddr_axil.v`：在 **B 响应处才把 AW 与 W 耦合**，并实现了 `WSTRB` 字节选通（按字节写），符合协议。
- 注意：`pd_axil_regs.v:83` 声明了 `S_AXI_WSTRB` 输入，但**写逻辑从未使用它** → 没有字节选通（**事实**）。

### ④ 常见错误
- 主设备（如 PS）先发 W 后发 AW，从设备卡死等「同一拍」→ 总线挂死。
- 忽略 `WSTRB`，想只改某字节却整字覆盖 → 影子寄存器被邻位误写。

## 知识点 11 · 影子寄存器 + 原子 APPLY（Shadow Register + Atomic Apply）

### ① 是什么
「配置参数」先写进**影子寄存器（shadow）**，由一条 `APPLY` 命令把它**一次性拷贝**到**生效寄存器（active）**。中间改写影子不影响正在跑的算法。

### ② 为什么
局部放电算法在跑的过程中，若中途改半个系数（如只改了 b0 没改 b1），会产生瞬态错误脉冲。APPLY 保证「整组参数在同一周期边界生效」。`coef_dirty` 标志：=1 表示影子被改过尚未 APPLY，=0 表示生效值与影子一致。

### ③ 工程里的真实代码（`pd_filter_chain.v:85-97`）
```verilog
// 影子 sh_* 与生效 ac_* 分开
if (shadow_write)    coef_dirty <= 1'b1;          // 写影子置脏
if (apply_pulse) begin
    ac_b0 <= sh_b0; ac_b1 <= sh_b1; ...           // APPLY：影子→生效
    coef_dirty <= 1'b0;                            // 清脏
end
```
`WSTRB` 合并通过 `merge32`/`mergecoef` 处理。

### ④ 常见错误
- 直接写生效寄存器，没走 APPLY → 滤波中途系数半新半旧，输出毛刺。
- 改完影子忘了发 APPLY，`coef_dirty` 一直=1，PS 以为没生效反复写。
- （本工程待测）`tb_pd_filter_chain` 未覆盖「APPLY 后 `coef_dirty` 变 0」这条路径（见 B09）。

## 知识点 12 · 字节额度（Byte Credit）

### ① 是什么
环形 buffer 写数据时，记录「还能写多少字节」的计数器。生产方写一块 +N，消费方（DMA 搬走）扣 -M，用于防止写指针套圈读指针（溢出）。

### ② 为什么
DDR 环形写 `pd_ddr_ring_wr.v` 里，DataMover 接受命令后还没真正写完，必须**先把额度扣掉**才能继续填，否则读侧还没搬走新数据就被覆盖。

### ③ 工程里的真实代码（`pd_ddr_ring_wr.v:32-40`、`255-259`）
```verilog
// 写一块 +8（生产），DMA 完成 -seg_len（消费）
// 关键教训：合并赋值，避免「先加后减」两拍窗口内额度算错
credit <= credit + 8 - seg_len;   // 合并成一条，原子
```
`255-259` 的注释明确写「merged credit assignment lesson」：额度必须**合并成一条赋值**，不能分两拍，否则中间态被误判溢出。

### ④ 常见错误
- 额度分两拍更新（先 `+8` 再下一拍 `-seg_len`）→ 短暂「超额」触发假溢出。
- 消费侧没等 DMA 真完成就扣额度 → 读指针超前，数据未搬走即被覆盖。

## 知识点 13 · 环形 Buffer 的对齐（Ring Buffer Alignment）

### ① 是什么
环形写要求「每块大小」与「DDR 突发块大小」对齐到**最小公倍数（LCM）**，否则写指针回绕时地址不对齐，DMA 突发失败。

### ② 为什么
- 每个事件包 24 字节（3×64bit AXI beat），需 24 对齐。
- DDR 突发块 4096 字节（4KB 页），需 4096 对齐。
- LCM(4096, 24) = **12288 = 0x3000**（`pd_ddr_defines.vh:65-139`）。哨兵地址（sentinel）用来检测「写指针绕回」。

### ③ 工程里的真实代码
```verilog
// pd_ddr_defines.vh
RING_BASE = 0x1000_2000;  RING_SIZE = 0x07FF_E000;
SNAP_BASE = 0x1800_0000;  SNAP_SIZE = 0x007F_E000;
SLOT0     = 0x2000_1000;  SLOT_SIZE = 0x00C0_0000;
BURST_BLOCKS = 64;  // 64 beats × 24B = 1536B 每块
// LCM(4096,24)=12288=0x3000
```
`pd_ddr_ring_wr.v` 用哨兵地址判断回绕。

### ④ 常见错误
- 块大小不是 24 的倍数 → `pd_align24_check.v` 检错，包错位。
- 忽略 4096 对齐 → DMA 跨 4KB 边界突发被 AXI 拆碎，性能暴跌甚至报错。
- 哨兵地址算错 → 回绕检测失效，读写指针套圈静默丢数据。

## 知识点 14 · 冻结快照的两拍边界锁存（Freeze Snapshot 2-cycle Latch）

### ① 是什么
「冻结」命令要求把**当前正在写的那块**完整保存下来。由于写指针/状态跨时钟域且有流水线延迟，必须在**边界处用 2 拍锁存**，确保冻结的是「完整一帧」而非半成品。

### ② 为什么
如果只在命令到达那拍采样，可能采到「刚写了一半的块」。2 拍锁存让边界对齐到块完成时刻，快照内容自洽。

### ③ 工程里的真实代码（`pd_ddr_ring_wr.v:377-403`）
```verilog
// freeze 命令到达 → 第 1 拍锁存 wr_blk_idx 边界
//               → 第 2 拍确认并拉 o_freeze_done
// o_write_idle 的必要性：只有写真正空闲(idle)才允许冻结，避免冻结中又被新数据冲掉
```
`o_write_idle = (wr_inflight==0) && !m_cmd_tvalid`（`pd_ddr_ring_wr.v:340`）——写空闲信号是冻结前置条件。

### ④ 常见错误
- 单拍锁存 → 采到半块，快照里混着冻结前/后数据。
- 没检查 `o_write_idle` 就冻结 → 冻结瞬间新数据写入，破坏一致性。

## 知识点 15 · 4 槽位状态机（4-slot FSM）

### ① 是什么
快照区被分成 4 个槽（slot），一个「槽位管理器」状态机负责：哪个槽**空闲（FREE）**、哪个**已锁（LOCKED）**、哪个**有效（VALID）**。分配时挑**编号最小**的空闲槽（lowest FREE first）。

### ② 为什么
4 个槽轮流接快照，PS 慢慢搬走已填槽、腾出空槽。挑最小空闲槽保证轮流均匀、不饿死某槽。`VALID→LOCKED→FREE` 是槽的生命周期。

### ③ 工程里的真实代码（`pd_ddr_slot_mgr.v`）
- `79-87`：`free_found` 找最低位 FREE：
```verilog
free_found = ~status[3] & free_vec[3] ? 3'd3 :
             ~status[2] & free_vec[2] ? 3'd2 :
             ~status[1] & free_vec[1] ? 3'd1 : 3'd0;
```
- `134-144`：lock/release 逻辑。
- `151-162`：`VALID → LOCKED → FREE` 状态转移；`o_snapshot_ready` 是**粘滞（sticky）**标志，由 `status_clear` 清除。

### ④ 常见错误
- 分配时不挑最小空闲 → 某槽一直满、其余空，吞吐受限。
- `o_snapshot_ready` 不粘滞、被下一拍覆盖 → PS 轮询错过「就绪」信号。
- lock 后忘了 release → 槽永久占用，最终无槽可分配（`pd_acquisition_core.c:158-159` 的 release 失败会 `fail`）。

## 知识点 16 · 粘滞标志（Sticky Flags）

### ① 是什么
某些「事件」（错误、溢出、快照就绪）是**单拍脉冲**或**异步发生**，下游（PS 轮询）可能错过。把它们做成「一旦置位就保持，直到被显式清除」的**粘滞位**，保证不丢。

### ② 为什么
PS 是软件轮询，频率远低于硬件。脉冲事件若不粘滞，轮询间隔里就溜走了。`o_err`/`o_ovf`/`o_snapshot_ready` 都是粘滞。

### ③ 工程里的真实代码
- `pd_ddr_ring_wr.v:427-439`：`o_err`/`o_ovf` 置位后保持，需 `status_clear` 清。
- `pd_ddr_slot_mgr.v:151-162`：`o_snapshot_ready` 粘滞，由 `status_clear` 清。
- PS 侧：`pd_acquisition_core.c:347` `ddr_write(PD_SLOT_CTRL, 1U<<12)` 清粘滞槽状态。

### ④ 常见错误
- 粘滞位忘了清 → 一次错误永久锁死「错误态」，正常数据也被拒。
- 该粘滞的没粘滞（如单拍 drop 计数）→ 轮询漏采，统计偏小。

## 知识点 17 · PS 侧缓存一致性（Cache Coherence）

### ① 是什么
Zynq 的 PS（ARM）有**数据缓存（D-Cache）**。PL（FPGA）通过 DMA 直接写 DDR，但 ARM 的缓存**不知道 DDR 被改了**；反过来 ARM 写 DDR 后 DMA 也可能读到旧缓存。必须手动 `Invalidate`（作废缓存，让 CPU 从 DDR 重读）和 `Flush`（把缓存写回 DDR）。

### ② 为什么
不 Invalidate：PS 读到的还是缓存里的旧快照，分析全错。不 Flush：DMA 从 DDR 读到的还是旧指令/旧数据。

### ③ 工程里的真实代码（`pd_acquisition_core.c`）
- **搬快照前 Invalidate**：`145` `Xil_DCacheInvalidateRange((UINTPTR)base, bytes);` 再从 `base` memcpy。
- **提交 DMA 前 Flush+Invalidate**：`169-170` `Xil_DCacheFlushRange(...)` + `InvalidateRange(...)` 再 `XAxiDma_SimpleTransfer`。
- **归档后 Flush**：`97` `Xil_DCacheFlushRange(dst, bytes);` 把拷到 PS 侧的数据写回（若 PS 要再读）。

### ④ 常见错误
- 只 Flush 不 Invalidate → DMA 写进 DDR 的数据，CPU 仍读缓存旧值。
- Invalidate 范围不是 32 字节对齐/整块 → 缓存行部分失效，偶发错字节。
- DMA buffer 落在缓存区内却没管理 → 「时好时坏」最难调。

## 知识点 18 · 定点 FFT 的细节（工程里的 `pd_spectrum.c`）

### ① 是什么
在 PS 侧用纯整数（Q15）实现 1024 点 FFT，做局放信号的频谱分析（找放电特征频率）。涉及：1/4 正弦表、汉宁窗、位反转、每级移位防溢出、整数平方根、自测。

### ② 为什么
PL 侧不做 FFT（资源/复杂度），PS 用定点 FFT 既可验证算法又能在板跑（无浮点依赖）。每级 `>>1` 是因为 FFT 每级能量翻倍，不缩放会溢出。

### ③ 工程里的真实代码（`pd_spectrum.c`）
- `q15_mul`（`:32-37`）：`(a*b + (1<<14)) >> 15` 四舍五入。
- `sin_turn_1024`（`:39-50`）：只存 **1/4 周期**正弦表，其余象限靠对称取负/取余推。
- 汉宁窗 `hann_q15`（`:52-56`）：用 `sin(x+256)=cos(x)` 技巧由同一张表得到余弦。
- `bit_reverse`（`:58-68`）：FFT 输入需位反转重排。
- `fft_forward` 每级 `>>1`（`:70-95`）：防溢出缩放。
- `isqrt_u64`（`:97-112`）：整数平方根算幅度。
- `pd_spectrum_self_test`（`:206-236`）：注入已知单频，期望落在 bin `37/83/151/255`，幅度 900–1150 校验。

### ④ 常见错误
- 忘记每级 `>>1` → 中间结果溢出，频谱全 0。
- 位反转顺序错 → 频谱整体错位，峰值不在预期 bin。
- 1/4 表象限符号错 → 负频/镜像峰出现。
- 自测只查 bin 不查幅度 → 相位错也过测。
