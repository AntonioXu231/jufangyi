# B01 · 零基础起点：这个工程到底是什么

> 目标读者：**没写过 FPGA、没碰过 Zynq、也没写过嵌入式 C** 的人。
> 本篇不要求你看懂一行代码，只要求读完能回答："这块板子在干什么？为什么这么麻烦？"

---

## 1. 一句话版本

> 一块 Zynq 芯片（一半是"可编程电路"、一半是 ARM 处理器），把 **4 路 ADC 的高速采样**同时做三件事：
> **① 原样存档（写到 DDR 内存）**、**② 实时判决（找出局部放电脉冲）**、**③ 事后分析（做频谱）**；
> 最后通过**网口**把结果和原始波形送到电脑。

---

## 2. 先认识"局部放电"这件事

### 2.1 为什么需要测它

高压设备（变压器、开关柜、电缆）绝缘里如果有气隙、尖端、脏污，就会在**局部**发生微小的放电——不是整片击穿，而是"小范围火花"。这种放电会慢慢腐蚀绝缘，最终导致事故。

**局部放电（PD, Partial Discharge）检测的价值 = 在事故发生前发现劣化。**

### 2.2 怎么测

- **电学方法**：用一个**耦合电容/传感器**把放电产生的**高频电流脉冲**取出来；
- 放大、滤波之后送 ADC 采样；
- 同时取一路**工频电压（50 Hz）**作为"相位参考"。

### 2.3 为什么必须"分辨相位"

关键洞察：**放电发生在工频周期的哪个相位，能反映缺陷类型**。

- 尖端放电：集中在正负半周某一个相位区间；
- 气隙放电：正负半周对称出现两个簇；
- 沿面放电：不对称、相位更宽。

所以行业的通用做法是画 **PRPD 图谱**：

```
纵轴：放电幅值（或电荷量 q）
横轴：工频相位 0° … 360°
点/颜色：该相位、该幅值上发生了多少次放电
```

**本项目的一切硬件设计，最终都是为了让这张图尽可能准确。**

⭐ **推论：既然要在"相位"上分辨，就必须知道"每个采样点对应多少度"** → 这就是工程里"**相位窗 + Bresenham**"那一整套设计的由来（见 `A04a` 第 0.1/0.2 节）。

## 3. 为什么用"Zynq"而不是"单片机 + FPGA"或"只用 CPU"

### 3.1 数据量有多大

工程当前配置：

```
4 通道 × 12 bit × 26 MSPS = 48 bit × 26 MHz = 1248 Mbit/s = 156 MB/秒
```

**每秒 156 MB 的连续数据**，而且要求：
- **不能丢**（原始数据要能回放、复算）；
- **要实时判**（不能"先存下来、事后慢慢算"，因为要实时报警）；
- **要能事后分析**（频谱、相位分布）。

### 3.2 三种方案对比

| 方案 | 能否胜任 | 问题 |
|---|---|---|
| **纯单片机/CPU** | ❌ | 156 MB/s 的实时处理超出普通 MCU 能力；即使用 ARM，光搬数据就吃掉全部算力 |
| **纯 FPGA** | ⚠️ 勉强 | 实时判决很好，但"频谱分析、协议栈、上位机交互、参数整定"用 RTL 写代价极大、改起来慢 |
| **Zynq（FPGA + ARM 一体）** | ✅ | PL 侧做"高速、实时、并行"的事；PS 侧做"复杂、串行、需要灵活性"的事 |

### 3.3 本工程的划分（背下来这张表）

| 谁做 | 做什么 | 为什么归它 |
|---|---|---|
| **PL**（可编程逻辑 = FPGA） | ADC 采集与跨时钟域、相位窗划分、峰值/极性提取、阈值判决、PRPD 统计、事件打包、原始数据写 DDR、快照拷贝、寄存器接口 | ⭐ **都是"每拍都要做、必须并行、延迟恒定"的事** |
| **PS**（ARM Cortex-A9） | 搬数据到自己的内存、按序号归档、原始快照解包、FFT/频谱、TCP 服务、参数整定 | ⭐ **都是"算得慢一点没关系、但逻辑复杂/需要灵活性"的事** |

⭐ **一句话原则**：**PL 做"加、比、数"；PS 做"乘、除、协议、决策"。**
- 例：PL 只输出 `Σ|q|`（求和），`I = Σ|q|/T`（除法）由 PS 做 —— 因为**硬件除法器很贵、而 PS 有充足的余量**（见 `pd_feature_core.v:14-15` 的注释）。

## 4. 这个工程现在处于什么状态（看图认状态）

### 4.1 一个关键的"临时替身"

**真实板卡上应该有 4 片 AD9226（或 ADS805E）ADC + 模拟前端（放大器、耦合电容）**。
但模拟前端还在设计中，所以工程用了一个**片上替身**：

```
pd_dds_adc_source.v   ← 用 Verilog 写的"假 ADC"
   · 生成 4 通道三角波（约 305 / 508 / 711 / 1117 kHz，幅度几十个码）
   · 每个工频周期（20 ms）在 4 个不同相位处各插入一个 4 样点衰减脉冲（幅度 720/600/460/300）
   · 四通道基线故意不同（2048 / 2056 / 2038 / 2062）
```

启用方式：在 Block Design 里把 `pd_dds_0` 的输出接到 `pd_ddr_0` / `pd_feature_0` 的 ADC 输入（**当前就是这么接的**，见 `.bd` 的 nets 段）。

⭐ **为什么要这样设计？**（这是初学者最容易不理解的地方）
- **如果不这样做**，就要等模拟前端做完才能验证 PL 逻辑 → **整条数字链路的开发被硬件阻塞**；
- 用"假 ADC"可以**先把数字部分全部验证完**（数据通路、相位计算、阈值判决、DDR 写入、快照、DMA、TCP 全链路）；
- **代价**：它验证不了"物理引脚与 I/O 时序"，也验证不了"真实信号的信噪比"。这一点 `pd_dds_adc_source.v:10-11` 的注释写得很清楚（"**它故意不验证物理 ADC 引脚与 I/O 时序**"）。
- ⭐ **这是嵌入式/FPGA 工程的通用手法：先用可控的"片上激励"打通数字链路，再换真实输入。** 值得记住。

### 4.2 当前能跑通的能力（按数据流顺序）

| 环节 | 状态 | 依据 |
|---|---|---|
| 假 ADC 产生 4 通道数据 | ✅ | `pd_dds_adc_source.v` |
| 26 MHz → 130 MHz 跨时钟域 | ✅ | 两个 `fifo_48_cdc`（`.bd` nets） |
| 4 通道打成一个 48 bit 采样字 | ✅ | `pd_pack48.v` |
| 48 bit 字 → 192 bit 块 → 3×64 bit AXI beat | ✅ | `pd_pack192.v` |
| 写进 DDR 环形缓冲区（不回绕丢数据） | ✅ | `pd_ddr_ring_wr.v` |
| 冻结一个完整工频周期并搬到"四槽快照区" | ✅ | `pd_ddr_wr_top.v` + `pd_ddr_snap_copy.v` + `pd_ddr_slot_mgr.v` |
| 相位窗划分 + 峰值提取 + 阈值判决 | ✅ | `pd_feature_core.v` |
| PRPD 图谱写入片内 RAM | ✅ | `pd_prpd_ram.v` |
| 事件包经 AXI-Stream 送出（8 字节/包） | ✅ | `pd_axis_fifo.v` + `pd_axis_arb.v` |
| ARM 通过 AXI-Lite 读写所有寄存器 | ✅ | `pd_axil_regs.v` + `pd_ddr_axil.v` |
| ARM 用 DMA 收事件包并归档 | ✅ | `pd_acquisition_core.c` |
| ARM 把快照取回自己的 DDR 归档 | ✅ | `pd_acquisition_core.c:108-165` |
| ARM 解包 + 1024 点定点 FFT | ✅ | `pd_snapshot_unpack.c` + `pd_spectrum.c` |
| 网口 TCP 命令/数据服务（端口 6001） | ✅ | `pd_tcp_service.c` |
| 真实 ADC + 模拟前端接入 | ❌ **未做** | 缺硬件 |
| 上位机软件 | ❌ **未做** | — |

⭐ **所以这个工程的准确描述是**：**"数字链路已经打通并在硬件上验证；模拟前端与产品化尚未开始。"**

## 5. 读这份文档之前，你需要先接受的 5 个"反直觉"

| # | 反直觉的事实 | 为什么 |
|---|---|---|
| 1 | **硬件里几乎没有除法** | 除法器又大又慢；能改成"加、比、移位"就一定要改（例：相位窗用 Bresenham 增量法代替 `÷`，见 `A04a` 0.2；判"对齐 24 字节"用查表+加法树代替 `% 24`，见 `A01` §3） |
| 2 | **"写代码"在 FPGA 里更像"画电路"** | `always @(posedge clk)` 块综合出来的是一排触发器；`assign` 综合出来的是逻辑门。**同一个意思写法不同，面积/速度可能差几倍甚至几十倍**（例：`pd_axis_fifo` 的实测 LUT 从 4852 降到 36，只因为改了写法，见 `A06` §1.1） |
| 3 | **"能编译"不等于"能跑"，"能跑"不等于"跑对"** | 本工程里有多处"静默失效"：写错不会报错，只是"功能悄悄没了"（例：`pd_iir_biquad` 的 `dv` 间隔 < 5 拍 → 输出永远无效，见 `B09` R-2；BRAM 写法不当 → 只报 INFO 级提示，见 `A06` §1.1） |
| 4 | **软件里"读一下"是免费的，硬件里"跨域传一个信号"要付代价** | 两个时钟域之间传数据必须用**两级同步器**或**异步 FIFO**，否则会读到"既不是 0 也不是 1"的亚稳态值（见 `B02` 概念 4） |
| 5 | **CPU 读到的数据可能是"旧的"** | 因为 CPU 有 cache，而 PL 是通过 DMA 直接写内存的，绕过了 cache。所以每次读之前必须 `invalidate`，否则**会读到上一次的旧快照，而且看起来完全正常**（见 `B03` 第 6 节 / `B07` 知识点 17） |

⭐ **这 5 条是"从软件思维切换到硬件思维"的门槛。** 只要它们变成你的默认直觉，后面 20 多篇文档都会顺很多。

## 7. 本篇自测 6 问

1. 局部放电检测为什么一定要画 PRPD 图谱，而不是只报"放电幅值"？
2. 本工程为什么用 Zynq 而不是"单片机 + 独立 FPGA"？
3. 工程里 `pd_dds_adc_source` 这个"假 ADC"能验证什么、不能验证什么？
4. 为什么 PL 侧只输出 `Σ|q|` 而把 `I = Σ|q|/T` 留给 PS？
5. "静默失效"是什么意思？请举出本工程里的两个例子。
6. 为什么 CPU 读 PL 通过 DMA 写进内存的数据之前，必须做 cache invalidate？

<details>
<summary>参考答案要点（点开）</summary>

1. 因为不同绝缘缺陷在**相位分布**上有不同指纹；只报幅值无法区分缺陷类型。
2. 因为同时需要"PL 的高并行实时处理（156 MB/s、恒定延迟判决）"与"PS 的复杂串行逻辑灵活性（FFT/协议栈/参数整定）"；纯 MCU 算力不足，纯 FPGA 写上层逻辑代价过大。
3. **能**验证：DDS 源 → 26→130 MHz CDC → 打包 → 特征提取 → 事件流 → DDR 全条数字通路。**不能**验证：物理 ADC 引脚与 I/O 时序、真实信号的信噪比与失真。依据 `pd_dds_adc_source.v:10-11`。
4. 因为硬件除法器昂贵（面积+延迟），而 PS 有充足算力余量；PL 只做"加/比/数"。依据 `pd_feature_core.v:14-15`。
5. "写错不报错、功能悄悄消失"。例：`pd_iir_biquad` 的 `dv` 间隔 < 5 拍 → `dout_dv` 恒 0（`B09` R-2）；BRAM 的存储体写法违反 6 条规则 → 只报 INFO，静默降级为 LUTRAM（`A06` §1.1）。
6. 因为 DMA 绕过 CPU cache 直接写内存；CPU cache 里可能留着**上一次**的旧数据。不 invalidate 就会读到旧值，**而且内容看起来完全正常**（有值、长度对、格式对），是最难发现的错误。

</details>
