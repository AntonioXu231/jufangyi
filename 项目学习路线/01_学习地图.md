# 01 学习地图：先知道自己在学什么

## 一张项目数据流图

```text
ADC 四通道样本（4 x 12 bit，26 MSPS，adc_clk 域）
    |
    v
pd_pack48 / pd_adc_cdc / async_fifo
    |  把采样时钟域的样本安全送到 130 MHz 处理域
    v
pd_feature_sys_top
    |
    +--> pd_feature_top
    |      +--> pd_feature_core x4：单通道峰值、相位、n/I/P/Q、PRPD
    |      +--> pd_axis_fifo：缓冲事件
    |      +--> pd_axis_arb：四通道事件仲裁
    |      +--> m_axis：64 bit AXI-Stream 事件 -> AXI DMA -> PS/DDR
    |
    +--> pd_ddr_wr_top / pd_ddr_ring_wr：原始/处理后数据的 DDR 环形缓存与快照

PS 软件 -- AXI4-Lite --> pd_axil_regs --> 配置、状态、PRPD 读取
```

不要试图按文件名把所有文件读完。按“数据从哪里来、在哪里变、去哪里、谁配置它”来读。

## 先认识的六个概念

| 概念 | 在本工程中的问题 | 第一阶段要达到的理解 |
|---|---|---|
| 同步时序逻辑 | `always @(posedge clk)` 中状态何时改变 | 能区分组合逻辑和寄存器逻辑 |
| 时钟域（CDC） | `adc_clk` 26 MHz 与 `clk` 130 MHz 不同 | 知道异步 FIFO 解决的不是“变快”，而是安全传递 |
| 有效握手 | `m_axis_tvalid` / `m_axis_tready` | 能说出一次事件真正被接收的条件 |
| AXI4-Lite | PS 配置寄存器、读取状态 | 能看懂一次读写与地址偏移 |
| AXI-Stream | 事件送往 DMA | 能从 64 bit 事件包中找到类型、通道、幅值、相位等字段 |
| 仿真与实现 | 仿真验证行为；综合/实现验证硬件可实现与时序 | 不把“仿真通过”误解成“板上一定可用” |

## 文件阅读顺序

每读一个文件，只回答四个问题：它的输入是什么？内部状态是什么？输出是什么？它在哪个时钟域运行？

1. `.../sim_1/new/tb_pd_feature_dds.v`：先看测试如何产生 26 MHz ADC 数据、写寄存器、检查事件。
2. `.../imports/rtl/pd_feature_sys_top.v`：系统边界、时钟域和完整接口。
3. `.../imports/rtl/pd_adc_cdc.v`、`async_fifo.v`、`pd_pack48.v`：ADC 到处理域的路径。
4. `.../imports/rtl/pd_feature_top.v`：四通道共同的寄存器、FIFO、仲裁与 AXIS 出口。
5. `.../imports/rtl/pd_feature_core.v`：单通道特征算法；这是最值得慢读的文件。
6. `.../imports/rtl/pd_axil_regs.v`、`pd_prpd_ram.v`：配置和 PRPD 图谱存取。
7. `.../imports/rtl/pd_ddr_wr_top.v`、`pd_ddr_ring_wr.v`：DDR 写入、环形缓冲、快照。
8. 根目录 `接口契约v3.0.md`：用接口约束反查实现，不把“规划”误当“已完成”。

## 两条重要边界

- 源码注释中还存在旧的 20 MSPS 描述；本工程当前仿真及接口契约的验证基线是 **26 MSPS / 130 MHz**。出现不一致时，先记录差异并回到 testbench、参数和时钟约束查证。
- 硬件原理图、ADC 最终型号和 I/O 时序资料仍影响上板约束签核。因此，现阶段最适合以“理解、仿真、低风险修改”为主，不能把已有实现报告等同于新的板级验证。
