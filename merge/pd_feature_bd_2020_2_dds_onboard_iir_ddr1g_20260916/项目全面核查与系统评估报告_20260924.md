## 1. 结论摘要

项目已经形成一条可运行的链路：PL 产生/接收四通道采样，完成滤波/特征提取和事件输出，DDR 负责环形缓存及快照，PS 通过 AXI-DMA/AXI-Lite 读取并归档，TCP 服务向 Qt 提供事件、快照、FFT、PRPD、扫描、告警和实时 SCOPE 数据，上位机可以显示四通道波形和相位椭圆。

但当前状态还不能称为“现场可交付版本”，主要原因不是功能完全不存在，而是以下四个闭环尚未闭合：

1. 当前实现时序仍未收敛：路由后 WNS = **-0.274 ns**、TNS = **-24.817 ns**，200 个 failing endpoints。
2. 波形 SCOPE 帧和 PRPD/峰值事件没有共享硬件时间戳或样本序号，无法证明界面高亮的波形脉冲与椭圆脉冲是同一个物理事件。
3. PL 的环形 DDR 错误诊断不完整：DataMover 的 `o_last_btt` 和 `o_sts_tdata` 当前未接出，PS 只能看到粗粒度的错误位，不能定位 DMA 错误原因。
4. 工程中存在多个 XSA、多个软件目录和两个 Qt 工程树；主工程目录没有可核对的当前 ELF，存在“PL 已更新、PS/上位机仍运行旧版本”的复现风险。

因此当前可给出两个不同的结论：

- **实验室功能演示：基本可用。** 合成 DDS、事件、快照、FFT、自检、批处理、告警和 TCP 下载已有板上通过记录。
- **工程签核/现场测量：尚不可用。** 时序、数据关联、量值标定、长时间无损采集、版本一致性和现场数据验证仍缺少证据或存在明确缺陷。

### 4.2 当前 PL 关键问题

#### P0：时序不通过

当前路由时序报告明确为：

- `clk_out1`（约 130 MHz）WNS = **-0.274 ns**；
- TNS = **-24.817 ns**；
- 200 个 failing endpoints；
- 报告结论为 `Timing constraints are not met.`。

因此 bitstream 虽然生成成功，但不能作为最终发布版本。优先查找 `clk_out1` 域中最长数据路径，重点关注滤波器、特征统计、事件打包、AXI/BRAM 访问和高扇出控制信号。

#### P0：DMA 错误不可定位

`pd_ddr_wr_top.v` 当前将 DataMover 的 BTT/status 输出悬空：

```verilog
.o_last_btt     (),
.o_sts_tdata    (),
```

当 DDR_STATUS[5] 置位时，PS 只能知道“有错误”，不能知道是长度错误、AXI response、写地址、S2MM 状态还是 ring 上溢。现场诊断和自动恢复因此不可靠。

#### P1：滤波器配置与设计目标不一致

当前 BD/XCI 的 `N_BP=1, N_NT=0`，而此前设计操作目标是 `N_BP=0, N_NT=1`。另外默认旁路开启，意味着“代码存在”不等于“当前数据通路正在经过目标滤波器”。必须在生成 bit 前做一次参数、旁路、active coefficient 和输出频响的四项确认。

#### P1：DDS 阈值不代表真实采集阈值

`pd_axil_regs.v` 中阈值从 40 调到 80，依据是 DDS 背景约 ±32、脉冲幅度较大的实验室条件。这个修改对合成 DDS 合理，但不等于真实 ADC 的单位校准；换传感器、增益或噪声环境后可能漏检或误检。

#### P1：仿真覆盖不足

已有模块/模板级仿真和 DDS 50 Hz 检查，但当前证据没有证明一个覆盖“ADC/DDS → filter → feature → DDR ring → slot → DMA → PS protocol → Qt”的顶层可重复回归。顶层仿真和硬件日志之间还缺少统一的 golden vector。

### 4.3 PL DRC/资源结论

- 布线完成、无 routing errors；
- LUT、FF、BRAM、DSP 没有超容量；
- Slice 使用率约 80.30%，属于需要关注的实现余量；
- DRC 有 139 个 warning、2 个 advisory，主要涉及 DSP 未流水化、BRAM 异步控制、写优先级和无负载网络；
- 当前没有以“0 warning”作为发布门槛，必须至少对异步 BRAM 控制和 DSP 时序相关项做风险判定并记录豁免理由。

**PL 综合结论：进行中。** 功能演示链路存在，时序签核、错误可诊断性、真实 ADC 校准和可复现构建尚未完成。

### 5.2 PS 关键问题

#### P0：源代码与实际下载 ELF 可能不是同一版本

当前主工程没有可核对的 ELF；历史日志中 ELF 来自 `F:\ps` 或 `F:\ps1`。当前主工程又存在 `sw/ps_service/tcp/main.c`、`src/main.c` 等多个入口线索。若 Vitis 工作区没有绑定本目录，最容易出现的现象就是：源码显示 PS-2/API 13，但板上仍运行旧 PS-1/API 10/11。

必须把以下信息绑定到同一个版本清单：Vivado commit、bit 文件 SHA256、XSA SHA256、Vitis application commit、ELF SHA256、Qt commit。

#### P0：SCOPE 波形与峰值事件没有同一时间基准

当前 SCOPE 从 ring 的“当前写指针前若干字节”取 1024/2048 样本；PEAKS 从事件 archive 读取峰值。两者都可以显示，但：

- SCOPE 只有 frame sequence；
- event 只有 event sequence/phase；
- 没有共享 sample index 或 hardware timestamp；
- UI 只能按轮询时刻近似拼接。

因此“波形上的脉冲”和“椭圆上的高亮点”不能被证明是同一脉冲。当前用户看到“椭圆有点、波形很平”并不一定是数据错，也可能是未触发的 1024 点窗口没有包含脉冲；但从系统验证角度，这属于数据关联缺失。

#### P1：ring error 的判定不完整

`pd_acquisition_core.c` 的 snapshot 归档路径主要检查 `PD_DDR_COPY_ERR | PD_DDR_CFG_ERR`，没有把 `PD_DDR_RING_ERR` bit5 纳入同等失败判定。由此可能出现“ring 已报错，但 snapshot 仍被报告为有效”的假成功。

#### P1：缓存/归档不是无损设计

当前 archive 是 16 个 event 槽、4 个 snapshot 槽；ring 历史窗口约 0.86 s。用户日志中已经出现 `ev_ovw=496`、`snap_ovw=6` 等覆盖计数，这是设计行为而非偶然错误，但必须在产品需求中明确“最近窗口展示”还是“无损历史记录”。

#### P1：事件包可能明显大于 8 bytes

无峰值时 event 只有 8 bytes；含峰值时可达约 8,224 bytes，且一次事件可含约 1,027 个 peak。PS/Qt 必须正确处理变长事件、CRC、包边界和超时，不能只验证 8-byte 样例。

#### P1：量值未完成物理标定

当前 Q/幅值仍是 raw code 或固定比例（如 `SCALE=256`/Q8.8 语义），没有传感器灵敏度、模拟前端增益、ADC 满量程和 pC 标准源标定。界面显示“raw ADC”是诚实的，显示“pC”则不能直接当作现场量值。

#### P2：接口版本与文档不同步

历史日志出现 API 10/11，当前源代码已到 API 13；如果没有版本握手和构建绑定，主机端可能误把旧协议当新协议解析。

**PS 结论：源代码功能较完整，真实可用性为进行中。** 板上演示通过不等于当前目录可复现，也不等于连续运行、错误恢复、同一脉冲关联和物理量准确性已经通过。

### 6.3 上位机当前最明显的问题

1. **波形和相位图来源不同。** 这正是“波形窗口没有明显脉冲、椭圆有脉冲点”的主要系统性原因之一。

4. **存在两个 Qt 工程树。** 必须指定唯一产品工程，否则后续修复可能写到未使用的目录。

### 7.2 准确性问题

- **相位准确性：** 当前 DDS 是 50 Hz、26 MSPS 的整数比，合成相位可重复；真实电网频率偏离 50 Hz 或 ADC/PL 时钟漂移时，固定 `520000 samples/cycle` 会产生相位误差。
- **幅值准确性：** raw ADC、Q 值和 pC 之间没有经过标准源/传感器标定，当前“pC”只能视为未标定结果。
- **频率准确性：** FFT bin 为 `26 MHz / 1024 = 25,390.625 Hz`，界面常显示约 25,390 Hz；这属于 bin 中心频率，不是任意真实频率的精确估计，需说明频率分辨率和窗函数误差。
- **事件准确性：** event packet 的 phase/polarity/channel 位域与 PS 头文件基本一致；但旧注释不一致，存在未来维护风险。

### 7.3 完整性问题

- event archive 只有 16 槽，snapshot archive 只有 4 槽；长时间采集必然覆盖；
- ring 只有约 0.86 s 历史，网络/PS 暂停或上位机轮询慢时会丢历史；
- 大事件包可达 8,224 bytes，若按固定 8 bytes 解析会截断；
- `SCOPE PEAKS` 受事件 archive 和最大峰值数限制，不能保证拿到一个周期内全部峰值；
- CRC32 能证明传输字节未损坏，不能证明 phase、单位、时间或通道语义正确。

### 7.4 一致性问题

- BD 当前滤波参数与既定目标不一致；
- 多个 XSA、外部 Vitis 工作区和主工程 `sw` 未形成唯一版本链；
- API 版本、历史日志、Qt 协议解析器可能不一致；
- `pd_feature_core.v` 位域注释与实际打包格式不一致；
- 旧版 UART/PS-1 入口与当前 PS-2/PS-1x TCP 源码并存，存在误构建风险；
- 两个 Qt 工程树的功能策略不同，存在界面行为不一致风险。

## 9. 问题清单（按严重程度）

### P0：必须先处理

1. **130 MHz 时序不收敛：WNS -0.274 ns/TNS -24.817 ns。** 不得以 bitstream 生成成功替代时序通过。
2. **PL/PS/Qt 版本不可唯一追溯。** 主目录没有当前 ELF，存在 `F:\ps`、`F:\ps1` 和多个 XSA/Qt 工程树。
3. **波形与相位事件没有共同时间戳/样本序号。** 目前无法证明两个窗口显示同一个局放脉冲。
4. **DataMover 详细状态未接出。** ring/DMA 错误无法定位，PS 恢复策略不具备足够依据。
5. **PS 归档路径未把 DDR ring error bit5 当作硬失败。** 可能出现错误状态下仍生成“有效 snapshot”的假成功。

### P1：完成基本产品闭环前必须处理

1. 滤波器 N_BP/N_NT 和旁路状态与目标设计不一致；
2. 真实 ADC 的阈值、量程、增益、pC 标定和 50 Hz 相位校准未完成；
3. ring/事件/snapshot 覆盖行为没有形成产品级丢失统计和告警；
4. SCOPE 未实现事件触发的 pre/post capture，1024 点窗口容易看不到脉冲；
5. SCOPE、PEAKS、event packet 没有共享样本时间基准；
6. 顶层回归测试未覆盖完整 PL→DDR→PS→TCP 链路；
7. RAMB 异步控制、DSP 未流水化等 DRC warning 未完成风险闭环；
8. PS 入口文件重复、旧 API 与新 API 并存，Vitis 构建选择容易错误；
9. Qt 两个工程树未指定唯一主工程，当前 Qt 构建/实机回归未重新核验；
10. 大事件包、事件越界、断线、重连、`START 0` 长时间运行尚无签核数据。

### P2：稳定性、可维护性和交付质量问题

1. 清理并统一 event 位域注释、协议文档和 API 版本；
2. 建立自动生成的 bit/XSA/ELF/Qt 版本 manifest 和 SHA256；
3. 统一工程文档、测试脚本和备份目录，减少未跟踪文件；
4. 增加物理量单位、校准系数、采样率、相位源、滤波配置到每个数据记录的元数据；
5. 对无负载网络、RAMB 写优先、DSP pipeline 警告建立可审计的 waiver/修复记录；
6. 增加网络断线重连、TCP 超时、PS watchdog、异常状态导出和现场日志保存。

## 10. 后续工作清单与优先级

### 阶段 A：先保证可复现和可签核（P0）

1. 冻结一个唯一工程目录和唯一 Qt 目录；删除/隔离旧入口，不再从 `F:\ps`、`F:\ps1` 交叉构建。
2. 记录当前 Git commit、Vivado bit/XSA SHA256、Vitis ELF SHA256、Qt commit；重新生成一套匹配的 bit/XSA/ELF。
3. 针对 `clk_out1` 130 MHz 路径做 timing closure：先报告最差 20 条路径，再按滤波器/统计/BRAM/高扇出逐层处理。
4. 连接并寄存 `o_last_btt`、`o_sts_tdata`，扩充 DDR 状态寄存器，PS 遇 bit5/bit8/bit9 时拒绝生成有效记录。
5. 把 `ring error`、`copy error`、`slot drop`、`event overwrite`、`snapshot overwrite` 分开统计并在 TCP/Qt 显示。

### 阶段 B：闭合数据语义和真实采集（P1）

1. 明确滤波器最终配置：N_BP/N_NT、旁路、active coefficient；增加“写入—apply—读回—频响”验证。
2. 设计事件触发的 SCOPE：每帧包含 `sample_start`、`sample_count`、`event_seq`、`phase`、`channel`、pre/post trigger 信息。
3. 让 SCOPE waveform 与 event/PEAKS 共用硬件 sample counter，Qt 以此配对高亮，而不是按轮询时间猜测。
4. 用示波器/标准局放源/实际传感器采集一组 golden vectors，验证 12 bit ADC 编码、正负极性、通道顺序、阈值和相位。
5. 建立 50 Hz 锁相/周期测量策略，不能永远假设 50 Hz 固定不变。
6. 建立 pC 标定链：传感器灵敏度、前端增益、ADC 满量程、滤波增益和 PS/Qt 显示单位统一。

### 阶段 C：长时间可靠性和上位机产品化（P1/P2）

1. 进行至少 30 分钟 `START 0` 连续采集，记录 packets/events/overwrites/drops/DDR errors/reconnect 次数。
2. 模拟 TCP 断线、PS 暂停、slot full、DMA error、ring wrap，确认恢复后不会伪造 snapshot/event。
3. Qt 增加采集质量状态：实时率、丢包、覆盖、当前 ring age、相位锁定、标定状态和错误码。
4. 统一四通道颜色、15 秒保留、缩放和高亮规则；缩放后保持相位轴、波形轴和脉冲 marker 的坐标一致。
5. 对变长 event、snapshot 分段下载、CRC、文件元数据和离线回放做自动测试。

### 阶段 D：最终验收

验收至少应同时满足：

- 当前实现 WNS/TNS ≥ 0；
- DRC 中 P0/P1 风险项有修复或书面豁免；
- bit/XSA/ELF/Qt 来自同一版本 manifest；
- 真实 ADC golden vector 的通道、极性、幅值和相位误差有量化结果；
- 波形 pulse 与椭圆 marker 通过共同 sample timestamp 配对；
- 连续采集覆盖/丢包可检测，30 分钟压力测试无未解释错误；
- pC、频率、相位、峰值等显示值均有校准或明确标注为 raw/uncalibrated；
- Qt 能导出带版本、采样率、校准和错误状态的完整数据记录。

## 11. 最终判定

当前项目不是“从零开始”，而是已经完成了较完整的实验室级 PL→PS→TCP→Qt 演示链路；其中合成 DDS、DMA/Snapshot、FFT/PRPD、扫描和告警都已有较强的功能证据。

但是，当前不能宣称“PL、PS、上位机均已真实可用”或“可以现场定量测量”。最关键的阻断项是：

- 时序未通过；
- 版本/ELF 不可唯一追溯；
- SCOPE 与事件没有共同时间基准；
- DMA 错误信息不完整；
- ring 错误未被 PS 严格处理；
- DDS/固定阈值和 raw pC 不能替代真实采集标定。

建议项目状态写为：**实验室演示完成，工程化集成进行中，现场交付未完成。**
