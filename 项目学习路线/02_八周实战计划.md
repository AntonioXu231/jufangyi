# 02 八周实战计划

建议每周 4--5 次、每次 45--90 分钟。每次结束必须留下一个可检查的产物：手绘图、波形截图、三条结论、或一次 Git 提交前的差异说明。卡住超过 30 分钟再向 AI 求助。

| 周次 | 学习目标 | 动手任务 | 验收问题 |
|---|---|---|---|
| 第 1 周 | 搭起数字电路最小基础 | 学会 `reg/wire`、位宽、时钟沿、复位、非阻塞赋值；手画本项目数据流 | 为什么寄存器通常用 `<=`？`adc_clk` 与 `clk` 为什么不能直接相连？ |
| 第 2 周 | 会使用工程和读仿真 | 在 Vivado 打开 `.xpr`，阅读 `tb_pd_feature_dds.v`；标出时钟、复位、ADC 激励、AXI-Lite 写入与 pass/fail 条件 | 测试写了哪几个地址？各通道门限为什么相同？ |
| 第 3 周 | 看懂跨时钟域 | 读 `pd_adc_cdc.v` 和 `async_fifo.v`；画写侧/读侧、满/空标志和复位路径 | 异步 FIFO 为什么会有两个时钟？只用两级触发器能不能传 48 bit 样本总线？ |
| 第 4 周 | 看懂单通道算法 | 读 `pd_feature_core.v` 的端口、状态机、峰值/相位/事件输出段；在波形中定位一个事件 | 一个事件的幅值、相位、极性从何而来？`ev_tvalid && ev_tready` 代表什么？ |
| 第 5 周 | 了解寄存器和软件边界 | 对照 `pd_axil_regs.v` 与 `接口契约v3.0.md`，列出一个通道 CTRL、THRESH、STATUS 的读写行为 | PS 写门限后，信号在哪些模块中生效？为什么有只读/W1C 寄存器？ |
| 第 6 周 | 了解事件到 DDR 的路径 | 阅读 `pd_axis_fifo.v`、`pd_axis_arb.v`、BD 中 DMA 相关连接和 `pd_ddr_wr_top.v` | 为什么需要 FIFO 和仲裁？DMA 与 DDR 环形缓存的职责有什么不同？ |
| 第 7 周 | 第一次可控修改 | 建立自己的分支或复制文件；只修改 testbench 的 `PD_THRESH_LSB`，比较事件数/通道覆盖；写下预测、结果、原因 | 阈值上调后事件数一定减少吗？若不符合预测，你会检查哪三处？ |
| 第 8 周 | 完成微型交付 | 自己写一页“项目工作原理”并做一次口头讲解；从一个小模块提出一个可验证的改进想法 | 你能否不看 AI 回复，解释系统输入、输出、控制路径和最大风险？ |

## 每周固定节奏

1. **预习 10 分钟**：写下今天要回答的一个问题和你自己的预测。
2. **阅读 20--30 分钟**：仅读一个模块或一个接口，不追求全懂。
3. **验证 15--30 分钟**：跑已有仿真、看波形、搜索信号或列出证据。
4. **复盘 10 分钟**：记下“我确认了什么、仍不懂什么、下一步怎么验证”。

## 第 7 周的安全修改规则

- 只改 `tb_pd_feature_dds.v` 中测试参数，先不要碰 CDC、寄存器映射、XDC、DDR 或 BD 连接。
- 一次只改一个变量，保存改前数值、改后数值和预期。
- 修改后先做行为仿真；不要因为一个参数实验就直接重新生成比特流或上板。
- 若要修改 RTL，先复制到个人实验目录或使用 Git 分支；每次改动都应可回退。
