> 三个模块串成一条链：**触发**（trigger）→ **选槽 + 给描述符**（slot_mgr）→ **实际搬运**（snap_copy）。本篇按这个顺序讲。

## 0. 为什么需要这一整套

冻结快照完成（`freeze_done`）之后，环形区里那一段"完整工频周期"的原始数据**仍然处在会被新数据覆盖的危险中**（虽然余量 17 倍，但不保证）。所以必须：

1. **把它复制到一块"不会再被写"的独立区域**（快照区）；
2. **这块区域不能只有一份**（因为 PS 可能要处理多次、还要支持"处理一次看一次"），所以要做**多槽轮转**；
3. **触发时机要能自动**（不能全靠人敲命令），所以要"检测到放电事件就抓快照"。

于是有了三个模块：

```
pd_feature_0/o_event_accept ──► pd_snapshot_trigger ──► freeze_trig
  (事件已进入本地 FIFO)              (每事务只发一次)         │
  软件 FREEZE_TRIG ─────────────────────────────────────────┤
                                                            ▼
                                              pd_ddr_ring_wr 冻结两个周期边界
                                                            │ freeze_done
                                                            ▼
                                              pd_ddr_slot_mgr 选一个 FREE 槽，
                                                给出 (src, dst, len)
                                                            │ copy_start
                                                            ▼
                                         pd_ddr_snap_copy 用 DataMover 环回搬运
                                                            │ copy_done
                                                            ▼
                                              slot 状态 FREE → VALID，PS 可读
```

## 1. `pd_snapshot_trigger.v`（67 行）—— 事件驱动的自动快照触发

### 1.1 文件头（第 1–9 行）

```
2  // pd_snapshot_trigger.v -- feature-event driven automatic DDR snapshot trigger
4  // The event pulse comes from pd_feature_top when a feature event is accepted by
5  // its per-channel FIFO.  It deliberately does NOT depend on AXI DMA TREADY.
6  // Exactly one trigger is emitted per freeze/resume transaction; software's
7  // FREEZE_CTRL trigger remains higher priority and is never replaced.
```
⭐ **三句话定了它的三条设计原则**：
1. **事件脉冲来自"事件已被本地 FIFO 收下"**（`o_event_accept`，见 A07 第 2.4 节），**不依赖 AXI DMA 的 TREADY**。
   - **为什么重要？** 如果依赖 DMA，快照触发时机就会受 PS 侧处理速度影响（DMA 有可能长期背压）→ **触发时刻不确定**。选在"进入本地 FIFO"这一级就与 PS 完全解耦 ✓。
2. **每次 freeze/resume 事务只发一次触发**（不重复触发）。
3. **软件触发优先级更高，且永不被替换**。

### 1.2 模块与端口（第 10–27 行）

```

```
- `i_event_accept`：4 位，每通道"事件已进入本地 FIFO"的脉冲。
- `i_enable`：是否使能自动触发。
- `i_channel_mask`：**4 位通道掩码**（只对选中的通道触发）。
- `i_sw_freeze_trig`：软件触发的 freeze（用于"软件优先"判断）。
- `i_freeze_resume`：恢复（用于"重新武装"）。
- `i_slot_full`：**四个槽都满了**（无法再抓快照）。
- `i_status_clear`：清粘滞状态。
- `o_auto_freeze_trig`：**自动触发的 freeze 脉冲**（单拍）。
- `o_armed`：**已武装**（可以接受下一个事件触发）。
- `o_slot_full_drop` / `o_slot_full_drop_count`：**因槽满而被拒绝的次数**（诊断量）。

### 1.3 武装条件（第 29–34 行）

```
29     wire event_match = |(i_event_accept & i_channel_mask);
30     reg  waiting_resume;
32     // A trigger is legal only while the ring is not already being held for a
33     // previous snapshot and at least one destination slot remains available.
34     assign o_armed = i_enable && !i_slot_full && !waiting_resume;
```
- 第 29 行 `|(i_event_accept & i_channel_mask)`：**按位与（掩码过滤）后归约或** → "选中通道里有任一事件".
  - ⭐ **四通道事件是"或"关系**：只要任一选中通道有事件就触发。所以"哪个通道触发的"**信息被丢失了** —— 快照里包含所有四个通道的原始数据，所以不需要知道触发通道 ✓ 但这意味着**无法做"只对某通道的放电抓快照"的精细控制**（掩码只能选"哪些通道能触发"，不能选"快照只存哪些通道"）。
- ⭐ **`o_armed = i_enable && !i_slot_full && !waiting_resume`** —— 三个条件：
  1. 使能；
  2. 槽没满；
  3. **不在"等 resume"状态**。
  - ⭐ **条件 3 是关键**：它实现了"**每次 freeze/resume 事务只触发一次**"。

### 1.4 主状态机（第 36–66 行）

```
42        end else begin
43            o_auto_freeze_trig <= 1'b0;
44            o_slot_full_drop   <= 1'b0;
46            if (i_status_clear)
```

⭐ **逐条精读（这是一个"优先级链"）**：

- 第 43–44 行：**先无条件清零两个单拍脉冲**（标准手法）。
- 第 46–47 行：`i_status_clear` 清计数。
- ⭐ **第 51–63 行是一个 `if/else if/else if` 优先级链，顺序决定了三条优先级规则**：
  1. **`i_freeze_resume`（最高）** → `waiting_resume = 0`（**重新武装**）。
     - ⭐ 这条实现了"**PS 通过 resume 把所有权交还**"。**只有 PS 明确 resume 之后，下一个事件才能再触发一次快照。** 这是"防重复触发"的锁。
  2. **`i_sw_freeze_trig`（次高）** → `waiting_resume = 1`（**软件触发也会"上锁"**）。
     - ⭐ 这条实现了注释第 6–7 行说的"**软件触发优先，且永不被替换**"：软件一触发，自动触发就进入"等 resume"状态，**不会再发自动触发** ✓。
  3. **`i_enable && event_match && !waiting_resume`（最低）** → 可以触发。
     - 第 56–59 行：**若槽满** → 只置 `o_slot_full_drop` 与计数，**不触发**（因为没地方放）；
     - 第 60–63 行：否则 → 发 `o_auto_freeze_trig` 脉冲 + `waiting_resume = 1`（上锁）。

⭐ **`waiting_resume` 是"一次性许可"（one-shot）机制**：
- 触发一次后立即上锁 → **不会因为事件脉冲持续为高而重复触发**；
- 只有 PS 的 `resume`（或软件触发）能解锁；
- ⭐ **这保证了"每次快照事务与一次事件一一对应"** —— PS 侧可以据此断定："我看到新槽 VALID 了，就说明有一个新事件发生了"。

⭐ **第 51–54 行的顺序还有一个精妙之处**：`i_freeze_resume` 优先于 `i_sw_freeze_trig`。若两者同拍（PS 同时发 resume 和 trig），则 `resume` 生效 → `waiting_resume = 0`。**这意味着"resume + trig 同拍" = "resume 胜出，trig 被忽略"** → 状态是"已武装"。⚠️ 但 `sw_freeze_trig` 会**在别处**（`pd_ddr_wr_top.v:210` 的 `freeze_trig = sw_freeze_trig | auto_freeze_trig`）仍然传给 ring_wr → **ring_wr 会开始一次新的冻结，但 trigger 模块认为自己是"已武装"** → 状态不一致！
- ⚠️ **【观察】** 这是一个"同拍竞态"的隐含风险。实际不会发生（PS 不会同时发），但**如果发生，会出现"ring_wr 冻结了但 trigger 没上锁"的不一致** → 可能重复触发。**记入 B09。**

## 2. `pd_ddr_snap_copy.v`（240 行）—— DataMover 环回拷贝

### 2.1 文件头（第 1–23 行）

```
5  // 契约 §3.4 / §3.5：
6  //   冻结完成后必须把"完整周期原始数据"搬进独立的冻结快照区，使 PS 后续
7  //   TCP 下载时读到的是一份**不会被环形写指针覆盖**的静态副本，
8  //   同时采集环路不中断（读快照不干扰采集写入）。
10 // 实现方式：复用 AXI DataMover(dm_cp) 的 MM2S + S2MM 两个通道做
11 // 「内存 -> 流 -> 内存」的环回：
12 //      MM2S: 从环形区 src 读  ──AXI-Stream──>  S2MM: 写入快照区 dst
13 //   这是 AMD 官方推荐的 DataMover memory-to-memory 环回接法，
14 //   比自己写 AXI 主状态机更省事，且天然获得 4KB 边界自动拆包能力。
```
⭐⭐ **这是本文件最重要的设计决策**：**用 DataMover 的 MM2S（内存→流）+ S2MM（流→内存）做环回，实现"内存到内存"拷贝**。

**为什么这么做？**
- **自己写 AXI 主状态机**（发读地址、接读数据、发写地址、送写数据）需要：
  - 处理 AXI4 突发、4 KB 边界拆包、outstanding 管理、读写通道缓冲、错误响应处理……**工作量巨大**；
  - 而且容易在边界情况出错。
- **用 DataMover 环回**：
  - DataMover 的两个方向**都已经实现了完整的 AXI 主协议**（含 4 KB 自动拆包）；
  - 只需要把 MM2S 的输出流**直接连到** S2MM 的输入流（在 `pd_ddr_wr_top.v:494-498` 与 `:531-535` 就是把 `cp_m_*` 接成环回）；
  - **天然获得 4 KB 自动拆包能力** ✓。
- ⭐ **代价**：需要**两个通道的命令都被正确下发**，且需要处理它们的状态字（更复杂的握手）。**但"省事"的价值远大于"握手复杂"。**

```
16 // 分片：一次命令的长度上限受 BTT(23bit) 与 Stream FIFO 深度限制，
17 //   本模块按 CHUNK_BYTES 分片（默认 6144B = 256 个 192bit 块），
18 //   每片发两条命令（S2MM 写 + MM2S 读），等 S2MM 状态返回后再发下一片，
19 //   **严格串行**，避免两条命令在同一通道里乱序。
```
⭐ **"分片 + 严格串行"的理由**：
- **分片**：`CHUNK_BLOCKS = 256` → `CHUNK_BYTES = 256 × 24 = 6144`。
  - **为什么 6144？** 受两个约束：① BTT 上限 8388607（远大于 6144，不是瓶颈）；② **环回的 Stream 通路上的缓冲深度**（MM2S 输出→S2MM 输入之间没有显式 FIFO，但 DataMover 内部有缓冲；分片限制单次在途的数据量，避免溢出）。
- ⭐ **严格串行**：**每片等 S2MM 状态返回后再发下一片**。
  - **为什么？** 如果连续发多条 MM2S 与 S2MM 命令，**两条命令在同一通道里可能乱序完成**（DataMover 不保证命令按序完成），就会导致"写和读不是同一段数据" → 快照内容错乱。
  - **串行化是"用吞吐换正确性"的取舍**：快照只有 3.12 MB，6144 字节/片 → 约 **508 片**；每片一次往返（约几十到几百拍）→ 总时间约**几十微秒量级**。**相对 20 ms 的工频周期完全可接受** ✓。

```
21 // 地址对齐：CHUNK_BYTES 取 24 的整数倍，src/dst/len 必须满足接口契约的
22 //   24B 原始块对齐（同时自然满足 DataMover 无 DRE 的 8B 对齐约束）。
```

## 3. `pd_ddr_slot_mgr.v`（195 行）—— 四槽轮转管理

### 3.1 为什么要"四槽"

- PS 处理一份快照（TCP 下载 3.12 MB + 解包 + FFT）需要时间；
- 如果只有**一个**快照区，那么"下一次放电事件"会在 PS 还没处理完时就**覆盖**它；
- **四槽**给 PS 一个"缓冲窗口"：最多可以积压 4 份未处理的快照 ✓。

⭐ **`DDR_SLOT_NUM = 4` 的选择依据**（在 `pd_ddr_defines.vh:122-124` 的容量分析里）：单槽 12 MiB，4 槽共 48 MiB，在 1 GiB DDR 里余 464 MiB。**4 是一个"够用且省内存"的折中。**

### 3.2 槽状态机（第 41–42 行）

```
41     localparam [2:0] SLOT_FREE=3'd0, SLOT_RESERVED=3'd1,
42                      SLOT_COPYING=3'd2, SLOT_VALID=3'd3, SLOT_LOCKED=3'd4;
```
⭐ **五态，构成一条单向弧线**：

```
FREE ──(选中预留)──► RESERVED ──(拷贝启动)──► COPYING ──(拷贝完成)──► VALID ──(PS 加锁)──► LOCKED
                                                                      │                    │
                                                                      └──(PS 释放)─────────┘
                                                                            回到 FREE
                          COPYING ──(拷贝出错)──► FREE
```
- ⭐ **注意 `LOCKED` 与 `VALID` 在"可读性"上是等价的**（第 95–96 行 `o_slot_valid[k] = (state == SLOT_VALID) || (state == SLOT_LOCKED)`）—— 即 **`LOCKED` 是"被 PS 占用中"的 `VALID`**。
- ⭐ **只有 `VALID` 能加锁**（第 137 行），**只有 `LOCKED` 能释放**（第 141 行）—— 这是"所有权移交"的严格规则（见 3.5）。

### 3.3 空闲槽选择：最低编号优先（第 79–90 行）

⭐⭐ **第 82–87 行实现的是"最低编号 FREE 槽优先"，而不是"轮询（round-robin）"**！

### 3.5 加锁/释放规则（第 134–144 行）

```
134            // lock -> read -> release: only VALID may lock and only LOCKED may release.
135            for (k=0; k<`DDR_SLOT_NUM; k=k+1) begin
136                if (i_slot_lock[k]) begin
137                    if (slot_state[k] == SLOT_VALID) slot_state[k] <= SLOT_LOCKED;
138                    else o_cmd_err <= 1'b1;
139                end
140                if (i_slot_release[k]) begin
141                    if (slot_state[k] == SLOT_LOCKED) slot_state[k] <= SLOT_FREE;
142                    else o_cmd_err <= 1'b1;
143                end
144            end
```
⭐⭐ **这是"所有权移交"的严格状态机，是防止 PS 与 PL 冲突的核心机制**：
- **`lock` 只在槽处于 `VALID` 时有效**（否则 `o_cmd_err`）→ 防止"锁一个还没写完的槽"（`COPYING`）或"重复锁"（已 `LOCKED`）。
- **`release` 只在槽处于 `LOCKED` 时有效**（否则 `o_cmd_err`）→ 防止"释放一个 PS 没锁过的槽"（那会破坏 PL 的写入）。
- ⭐ **"只有 VALID 能加锁、只有 LOCKED 能释放"** 保证了：
  - PS **先 lock 再读**（读出期间槽不会被复用）；
  - PS **读完再 release**（release 后槽才能被下次快照使用）。
- ⭐ **`o_cmd_err` 是粘滞的**（第 125–126 行由 `i_status_clear` 清）→ 非法命令会留下痕迹 ✓。

⚠️ **【观察 · 重要风险】** `release` 把槽直接置 **`FREE`**（第 141 行）—— **绕过 `VALID`！**
- 正常的流转应该是 `LOCKED → VALID → FREE`（先解锁恢复可读，再由 PL 决定是否需要）；
- 但这里 `LOCKED → FREE` 是**直接可复用**。
- ⭐ **这意味着：PS 一旦 release，这份快照就"立刻消失"（槽可被新快照覆盖）。** 如果 PS 还想再读一次（例如下载中断后重试），数据可能已经被新快照覆盖。
- ⭐ **这是设计选择（"release 即放弃"），不是 bug** —— 但 PS 侧必须清楚：**release 之后不能再去读那个槽**。`pd_acquisition_core.c` 的做法是"**先把槽内容 memcpy 到 PS DDR 归档，再 release**"（第 145–158 行）✓ 用对了。

  - **预留**只需要"有空闲槽"；
  - **启动**还需要"环形写空闲 + 拷贝引擎空闲 + 没有手动拷贝 + 没有活动事务"；
  - ⭐ **分离的好处**：如果在"预留"与"启动"之间，DataMover 正在忙（例如上一次拷贝还没完），**预留状态会保持**（注释第 165 行），等条件满足时自动启动。**这样就不会因为"暂时忙"而丢掉这次快照请求** ✓。

```
180            // Manual launch has priority; automatic launch waits one more cycle.
181            if (i_auto_snap_en && i_freeze_req && req_reserved &&
182                i_ring_write_idle && !i_copy_busy && !i_copy_err &&
183                !i_manual_copy_launch && !active_valid) begin
184                slot_state[req_slot] <= SLOT_COPYING;
185                active_slot <= req_slot; active_len <= i_freeze_len;
186                active_valid <= 1'b1;
187                o_copy_src_addr <= i_freeze_base;
188                o_copy_dst_addr <= slot_base(req_slot);
189                o_copy_len <= i_freeze_len;
190                o_copy_start <= 1'b1; o_req_ack <= 1'b1;
191                req_reserved <= 1'b0;
192            end
```
⭐ **启动条件（六项全与）**：
| 条件 | 含义 |
|---|---|
| `i_auto_snap_en` | 四槽自动模式使能 |
| `i_freeze_req` | 有冻结请求（**且已 `req_reserved`**） |
| `req_reserved` | 已预留了槽 |
| **`i_ring_write_idle`** | ⭐ **环形写已全部落地**（`o_write_idle`）—— 见 A08 §2.2 |
| `!i_copy_busy` | 拷贝引擎空闲 |
| `!i_copy_err` | 拷贝引擎无粘滞错误 |
| **`!i_manual_copy_launch`** | **手动拷贝优先**（注释第 180 行） |
| `!active_valid` | 没有正在进行的自动拷贝 |

- ⭐ **`i_ring_write_idle` 是不可省的条件**：它保证"要读的那段数据已经真的写进 DDR 了"。
- ⭐ **`!i_manual_copy_launch` 实现"手动优先"**：因为 `manual_copy_launch` 是**组合信号**（A10 会讲），在"手动拷贝正要启动"的那一拍，自动拷贝会让路 ✓。
- 第 187–189 行：**把描述符（src/dst/len）置好**（`o_copy_src_addr`/`o_copy_dst_addr`/`o_copy_len`）→ 这三个信号会被 `pd_ddr_wr_top` 送到 `pd_ddr_snap_copy` 的输入（见 A10）。
- 第 190 行：`o_copy_start = 1`（单拍脉冲）→ 启动拷贝。

### 3.7 取消与清状态（第 146–149、124–132 行）

```
146            if (i_cancel_req || !i_auto_snap_en) begin
147                if (req_reserved) slot_state[req_slot] <= SLOT_FREE;
148                req_reserved <= 1'b0;
149            end
```
- **`i_cancel_req`（接 `freeze_resume`）或 `!i_auto_snap_en`** → **取消预留**（把预留的槽释放回 `FREE`）✓。
- ⭐ **注意取消的是"预留"，不是"正在进行的拷贝"** —— 因为一旦进入 `COPYING`，就不能中断（DataMover 已经在搬了）。**所以 `resume` 只能取消"还没开始搬"的请求。** 如果要取消正在进行的拷贝，需要复位 DataMover（`pd_acq_recover` 就会做这件事）。

```
124            if (i_status_clear) begin
125                o_slot_full <= 1'b0; o_cfg_err <= 1'b0;
126                o_cmd_err <= 1'b0; o_req_overflow <= 1'b0;
127                o_snapshot_ready <= 1'b0;
128            end
129            if (i_req_overflow) begin
130                o_req_overflow <= 1'b1;
131                o_drop_count <= o_drop_count + 1'b1;
132            end
```
- `i_status_clear`（接 `SLOT_CTRL[12]`）清 **5 个粘滞标志**（含 `o_snapshot_ready`）✓。
- `i_req_overflow`（接 `slot_req_overflow_pulse`，来自 `pd_ddr_wr_top` 的"事件到达时已有未处理的 freeze 请求"检测）→ 置 `o_req_overflow` + 计数。

## 4. 三个模块协同的完整时序（一次自动快照）

| 拍 | 事件 | 相关信号 |
|---|---|---|
| T0 | `pd_feature_core` 发出一个超阈峰值事件，进入本地 FIFO | `o_event_accept[c] = 1` |
| T1 | `pd_snapshot_trigger` 检测到事件，`o_armed = 1` → 发 `o_auto_freeze_trig` | `waiting_resume = 1`（上锁） |
| T1 | `pd_ddr_wr_top` 把 `freeze_trig = sw \| auto` 传给 `pd_ddr_ring_wr` | `freeze_arm = 1` |
| T2 | 等 **第一个** `cycle_start` → 锁起始偏移 | `f_start_off`、`f_start_total` |
| T2 | 等 **第二个** `cycle_start` → 锁结束偏移、算 len、开始补尾量短命令 | `freeze_commit_wait = 1`、`o_freeze_base`、`o_freeze_len` |
| T3 | 尾量命令全部下发 **且** `o_write_idle = 1` → `o_freeze_done = 1` | `freeze_commit_wait = 0` |
| T4 | `pd_ddr_wr_top` 检测 `freeze_done` 上升沿 → `slot_freeze_req = 1` | — |
| T5 | `pd_ddr_slot_mgr` 预留一个 FREE 槽 | `SLOT_RESERVED`、`req_reserved = 1` |
| T6 | 启动条件满足（`ring_write_idle`、`!copy_busy`、…） → `o_copy_start = 1` | `SLOT_COPYING` |
| T7… | `pd_ddr_snap_copy` 分片搬运（约 508 片，每片串行） | `o_chunk_cnt`、`o_bytes_done` 递增 |
| T8 | 最后一片完成 → `o_done = 1` | `o_busy = 0` |
| T9 | `pd_ddr_slot_mgr` 把槽置 `VALID`，`o_snapshot_ready = 1`（粘滞） | `o_snapshot_seq +1` |
| T10 | PS 轮询/中断看到 `SLOT_STATUS[19] snapshot_ready` → **lock** 该槽 | `SLOT_LOCKED` |
| T11 | PS 读槽描述符（base/len/seq）→ `memcpy` 到 PS DDR 归档 → **release** | 回到 `SLOT_FREE` |
| T12 | PS 发 `FREEZE_CTRL = 2`（resume） | `waiting_resume = 0`（可再次触发）、清 `o_err`/`o_ovf`/`copy_err` |

⭐ **这条链上任何一个"粘滞标志"被清掉的时机都很关键**：
- `o_err`/`o_ovf`（ring_wr）与 `o_err`（snap_copy）都被 **`freeze_resume`** 清 → 所以 **PS 必须在同一个 resume 之前把所有相关状态都读一遍**，否则读完 resume 就再也读不到了。
- `o_snapshot_ready` 被 **`SLOT_CTRL[12] status_clear`** 清（不是 resume）→ ⚠️ **两个不同的清除命令**，PS 必须都知道。

## 5. 本篇易错点小结

1. ⭐ **AXI-Stream 的 `valid` 不能根据 `ready` 的组合值撤销**：必须"先置 valid、下一拍再看 ready 撤销"（否则 `valid` 零拍宽，命令从未送达）。
2. ⭐ **环回拷贝必须"先发 S2MM（写）再发 MM2S（读）"**，否则读出的数据无处可去会堵死 Stream 通路。
3. ⭐ **每一片都必须在环尾前截断**（`cur_len = min(chunk, src_to_ring_end)`），且下一片从 `RING_BASE` 继续，**绝不能线性读进 SNAP 分区**。
4. ⭐ **分片必须严格串行**（等 S2MM 状态返回再发下一片），否则同一通道里的命令可能乱序 → 读写不是同一段数据。
5. **启动前必须做 24 B 对齐 + 范围检查**（`start_valid`），**拒绝启动比带着错误参数执行安全**（否则会覆盖快照区）。
6. **拷贝失败时"不产生 done"**（`copy_fault_now` 立即中止）→ 槽不会被置 `VALID` → 坏数据不进有效路径。
7. ⭐ **`pd_ddr_slot_mgr` 是"最低编号 FREE 槽优先"，不是轮询**（`if (!free_found && ...)`）→ 要验"四槽轮转"必须**加锁后保持锁定**。
8. **`lock` 只在 `VALID` 有效、`release` 只在 `LOCKED` 有效**，否则置 `o_cmd_err`（防 PS/PL 所有权冲突）。
9. ⚠️ **`release` 直接把槽置 `FREE`（绕过 `VALID`）** → **release 之后不能再去读那个槽**，PS 必须先归档再 release。
10. **"预留（reservation）"与"启动（launch）"分离**，使"暂时忙"不会丢掉快照请求。
11. **自动启动必须等 `i_ring_write_idle`**（环形写全部落地），否则会读到旧数据。
12. **手动拷贝优先**（`!i_manual_copy_launch`）。
13. **`o_snapshot_ready` 粘滞，且只由 `SLOT_CTRL[12]` 清**（不是 `resume`）→ PS 必须知道有**两个不同的清除命令**。
14. **`i_enable = event_trig_en & auto_snap_en`**：事件触发必须与四槽自动路径一起使能，防止误入 legacy 手动模式（每次覆盖同一块）。
15. **`freeze_resume` 只能取消"还没开始搬"的请求**，不能中断正在进行的拷贝（那需要复位 DataMover）。
16. ⚠️ **`i_freeze_resume` 与 `i_sw_freeze_trig` 同拍时会状态不一致**（trigger 认为已武装，但 ring_wr 已开始新冻结）。
17. ⚠️ **`o_err`/`o_ovf`（ring_wr）与 `o_err`（snap_copy）都在 `freeze_resume` 时被清** → PS 必须在 resume 之前把所有状态读完。
