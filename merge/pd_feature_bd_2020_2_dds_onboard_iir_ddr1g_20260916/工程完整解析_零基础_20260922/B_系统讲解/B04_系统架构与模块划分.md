## 4. 模块划分的必要性论证

### 4.1 为什么 IO 适配（`pd_ddr_bd_adapter`）单独一层？
`pd_ddr_bd_adapter.v:3-7` 的注释明确写了原因：**业务 RTL（`pd_ddr_wr_top`）保持"扁平端口"，所有 Vivado 的 `X_INTERFACE_*` 属性集中在本文件**。这样 Block Design 的 AXI 自动连线是"显式、可检查的"，同时**不会把 Vivado 元数据（上百行 `X_INTERFACE_INFO`）渗进环形写入和快照业务逻辑**。换句话说：业务逻辑层（`pd_ddr_wr_top`）只关心 `s_axi_awaddr/wdata/...` 这些信号本身，而"怎么被 BD 识别为 AXI4-Lite / AXI4 主口"这种工具约定，全部外包给适配层。好处是业务模块可移植、可读、不受 IP Integrator 元数据污染。`pd_feature_sys_top` 同理（`pd_feature_sys_top.v:8-15` 也集中了 `X_INTERFACE` 属性）。

### 4.2 为什么 `pd_feature_sys_top` 与 `pd_feature_top` 分两层（`INPUT_CDC` 的含义）？
- `pd_feature_top` 是**契约接口主体**：实现峰值提取、1024 相位窗、n·I·P·Q 统计、PRPD 写、事件包格式，以及契约规定的 AXI-Lite 寄存器映射（`pd_feature_top.v:1-12`）。它是一个"纯算法/契约"模块，不该随板级连线方式变化。
- `pd_feature_sys_top` 是**板级/采集架构适配层**：它决定"ADC 样本怎么进 `pd_feature_top` 的 `adc_data/adc_dv`"。关键参数 `INPUT_CDC`（`pd_feature_sys_top.v:28-35`）：
  - `INPUT_CDC=1`：为每通道独立做 `adc_clk→clk` 的异步 CDC（例化 `pd_adc_cdc`，见 `:130-154`）；
  - `INPUT_CDC=0`：假设上游已经把样本送进 `clk` 域，直接 `assign adc_100 = adc_data`（`:155-158`）。
  本工程 BD 取 `INPUT_CDC=0`，因为 CDC 已经在 `pd_ddr_0` 内部（`fifo_48_cdc`）完成了——`pd_ddr_0` 在 26MHz `adc_clk` 域收样本，经异步 FIFO 送到 130MHz `clk` 域，再以 `o_feat_data/o_feat_dv` 输出给 `pd_filter_0`→`pd_feature_0`。把"是否在顶层做 CDC"抽成参数，使同一个 `pd_feature_top` 既能接"上游已 CDC"的架构，也能接"需要自己 CDC"的架构，**避免把板级时序决策写死进算法契约**。

### 4.3 为什么 `pd_pack48` 同时服务两条路径？
`pd_pack48.v:9-12` 与 `:32-41` 说明：它把同一采样时刻的 4 路 12bit 拼成 48bit 字（`[47:36]ch3 [35:24]ch2 [23:12]ch1 [11:0]ch0`），然后**一份数据同时扇出到两条路**：
- **Path A**（`o_s48_data/valid`）→ 异步 FIFO → DDR 环形缓存（原始样本落盘）；
- **Path B**（`o_ch_data/valid`，同一份 48bit 字，无损复制）→ 实时算法链（滤波→特征）。
这样设计的原因（`pd_pack48.v:13-19`）：4 路 AD9226 共用同一采样时钟，正常 `adc_dv` 四路同拍；在一个地方统一打包、统一检查"通道错位（`o_ch_skew_err`）"，再用同一份数据喂两条路，**保证 DDR 落盘的样本顺序与实时特征链看到的样本顺序严格一致**，且独立 FIFO 保证 DDR 反压/快照搬运不会改变实时链的样本节拍（`pd_ddr_wr_top.v:42-47`）。

> **如果这里搞错，会表现为：** 若把两条路径的打包分开做，某个时刻 Path A 比 Path B 多/少收一个样本，事后把"DDR 原始数据"和"特征值"按时间对齐时会对不上，PP（峰峰值）类算法直接算错；或通道 `dv` 错位没被统一检测， quietly 产生样本错序。

## 5. 接口类型总表（AXI-Lite / AXI4-Stream / 扁平信号+dv）

按"本工程在不同地方用哪种接口"统计（依据 `.bd` 的 `interface_nets` + RTL 端口）：

| 接口类型 | 用途 | 本工程出现位置（实例/信号） | 数量 |
|---|---|---|---|
| **AXI4-Lite** | PS 偶尔读写寄存器（控制/状态/系数） | ① PS `M_AXI_GP0`→`axi_ic_ctrl`；② `axi_ic_ctrl`→`axi_dma_0/S_AXI_LITE`；③ →`pd_ddr_0/s_axi`；④ →`pd_filter_0/S_AXI`；⑤ →`axi_rs_feature_ctrl_0`→`pd_feature_0/s_axi` | **5 段互联链路**（4 个 PL 从机 + 寄存器切片） |
| **AXI4（全）** | PL 经 HP 口做内存映射突发（大块搬 DDR） | ① `pd_ddr_0/m_axi_wr`→HP0（写环形区）；② `pd_ddr_0/m_axi_rd`→HP1（读环形区）；③ `pd_ddr_0/m_axi_cw`→HP1（快照拷贝写）；④ `axi_dma_0/M_AXI_S2MM`→HP0（事件流→DDR） | **4 个 AXI4 主口**（3 来自 pd_ddr，1 来自 dma） |
| **AXI4-Stream** | 点对点连续数据流（带 tvalid/tready/tlast，无地址） | ① `pd_feature_0/m_axis`(64b)→`axi_dma_0/S_AXIS_S2MM`（+`ila_0` 探针）；② （内部）`pd_ddr_wr_top` 内 `pd_pack192→axis_dfi_64→dm_wr` 也是 AXI-Stream，但属于模块内部、非 BD 顶层网 | **BD 顶层 1 条**（内部多条不计） |
| **扁平信号 + dv 脉冲** | ADC 样本流、单拍控制脉冲、中断线（用 `dv`/单 bit 做握手，不用 AXI） | `pd_dds_0` 的 `adc_data[47:0]/adc_dv[3:0]/sync_in`；`sync_pulse_0/cycle_start`；`pd_ddr_0` 的 `o_feat_data/o_feat_dv`、`i_event_accept`；`pd_filter_0` 的 `filt_data/filt_dv`；3 路 `irq`/`introut`→`xlconcat_0`；各类 `clk`/`reset`/`locked` 网 | **约 13 条扁平网**（见 `.bd` `nets` 列表） |

### 判断"该用哪种接口"的经验规则
1. **CPU 偶尔读/写一个寄存器、或少量配置/状态** → 用 **AXI-Lite**（本工程所有 `*_axil`/`*_regs` 都是）。代价最低，但每笔都是独立地址访问，不适合连续大数据。
2. **PL 要往 DDR 搬一大块数据（或反之），且地址连续** → 用 **AXI4 突发 + DMA**（本工程的 `pd_ddr`m_axi_*` 与 `axi_dma` M_AXI_S2MM）。一次突发可搬多 beat，效率最高。
3. **PL 内部/PL→PL 的连续流数据，不需要地址、只要"有 valid 就传、ready 反压"** → 用 **AXI4-Stream**（本工程的事件流 `m_axis`、以及 `pd_ddr_wr_top` 内部的 `pack192→fifo→dm_wr`）。
4. **仅仅是几路 ADC 样本或一拍控制脉冲，连握手都很简单** → 用 **扁平总线 + `dv` 脉冲**（本工程的 `adc_data/adc_dv`、`cycle_start`、`o_event_accept`）。再上 AXI 反而累赘。
5. 中断线用 **专用 `irq` 单 bit**（经 `xlconcat_0` 合成后进 PS `IRQ_F2P`），不走数据接口。

> **如果这里搞错，会表现为：** 给"每秒上亿字节的连续采样流"用 AXI-Lite 一笔一笔搬 → 总线被地址相位占满、吞吐差一个数量级；或给"偶尔读一个状态位"用 AXI4 突发 → 逻辑复杂且无法寻址到单个寄存器。

## 6. 数据通路带宽核算（26 MSPS 与 65 MSPS 两档）

所有数字的依据：`pd_ddr_defines.vh:10-13`（26MSPS 档）、`pd_pack192.v:14-17`（时序余量）、`pd_ddr_defines.vh:122-124`（65MSPS 档容量校验）。

### 6.1 基本位宽与块结构（两档相同）
- 4ch × 12bit = **48 bit = 6 Byte** / 采样时刻（`pd_ddr_defines.vh:23`）。
- 1 个 192bit 块 = 4 个 48bit 字 = **24 Byte**，AXI 64bit 下 = **3 个 beat**（`PD_BEAT_PER_BLK=3`，`:29`）。
- 系统时钟（clk）= 130 MHz；采样时钟（adc_clk）= 26 MHz（当前档）/ 【规划】65 MHz（生产档）。
- DDR 写入总线能力 = 130 MHz × 8 Byte = **1040 MB/s**（`:13`）。

### 6.2 各段链路字节率与占空比
设采样率为 `Fs`（样本/秒），则：

| 链路段 | 单位 | 26 MSPS（Fs=26e6） | 65 MSPS（Fs=65e6） | 算式 |
|---|---|---|---|---|
| 原始码流 | Byte/s | **156 MB/s** | **390 MB/s** | `6 × Fs` |
| 48bit FIFO（26M→130M CDC 后） | Byte/s | 156 MB/s | 390 MB/s | 同原始码流（仅跨时钟） |
| 192bit 块产出率 | 块/s | 6.5 M 块/s | 16.25 M 块/s | `Fs / 4` |
| AXI beat 速率 | beat/s | 19.5 M beat/s | 48.75 M beat/s | `6 × Fs / 8` |
| DDR 写入（HP0 环形写） | Byte/s | 156 MB/s | 390 MB/s | 同原始码流 |
| **HP0 总线占用率** | % | **15%** | **37.5%** | `原始码流 / 1040 MB/s` |

补充（突发与余量，来自 `pd_pack192.v:14-17` 与 `pd_ddr_defines.vh:20-22`）：
- `pd_pack192` 齿轮箱每 **5 个时钟**完成 1 个块（4 字入 / 3 beat 出）。
- 在 130MHz `clk` 域，每个样本可用时钟数 = `130 / Fs`：26MSPS 时为 **5 clk/样本 → 20 clk/块**；65MSPS 时为 **2 clk/样本 → 8 clk/块**。均远大于 5 clk/块，**余量充足**。
- 单突发命令搬 64 块 = 1536 Byte（`DDR_BURST_BLOCKS=64`，`pd_ddr_defines.vh:148-149`），< DataMover 单突发 256 beat 上限，可单突发完成。

### 6.3 快照区容量校验（决定"一槽能否装下一个工频周期"）
- 单工频周期样本数：50Hz 下 26MSPS = **520,000** 样本、65MSPS = **1,300,000** 样本。
- 每样本 6 Byte → 26MSPS 周期 = **3.12 MB**、65MSPS 周期 = **7.80 MB**。
- 单槽容量 = 12 MiB（`DDR_SLOT_SIZE=0x00C0_0000`，`:133`）→ **两档都 < 12 MiB，单槽容纳一个完整周期 ✓**（`pd_ddr_defines.vh:122-124`）。
- 环形区 128 MiB，26MSPS 下可缓冲 `134.2MB / 156MB/s ≈ 860 ms ≈ 43 个工频周期`（`:79`）。

> **如果这里搞错，会表现为：** 把采样率切到 65MSPS 却没同步改时钟（adc_clk 仍 26MHz）和 XDC → 实际吞吐只有一半，环形写被拖慢、slot 容纳不了一个周期，快照拷贝越界触发 `PD_DDR_COPY_ERR`/`PD_DDR_CFG_ERR`（见 `pd_hw_map.h:55-56`）；或在 65MSPS 下误以为 HP0 仍只有 15% 占用，实际上升到 ~37.5%，若再加快照并发写 HP1，总线竞争会抬升延迟。
