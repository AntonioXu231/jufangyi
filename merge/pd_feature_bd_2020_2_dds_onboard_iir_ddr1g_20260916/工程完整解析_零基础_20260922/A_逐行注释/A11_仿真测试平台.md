## 1. `tb_pd_filter_chain.v`（107 行）—— 把 AXI 协议细节测到位的样板

### 1.1 文件头与意图（第 1–3 行）

```
2  // Standalone regression for the added IIR filter boundary.
3  // It proves reset/default bypass and AXI4-Lite independent AW/W transactions.
```
⭐ **两句话定了两条判据**：
1. **复位/默认旁路的位精确性**（"bypass" 必须逐位透传）；
2. **AXI4-Lite 的 AW/W 独立事务**（这正是在验证 `pd_filter_chain.v` 的 `aw_hold`/`w_hold` 机制，以及间接暴露 `pd_axil_regs` 的不足）。

### 1.2 时钟与 DUT 例化（第 5–25 行）

```
15     always #3.846 clk=~clk; // 130 MHz
17     pd_filter_chain dut (
18         .clk(clk),.rst_n(rst_n),.adc_data(adc_data),.adc_dv(adc_dv),
19         .filt_data(filt_data),.filt_dv(filt_dv),
...（AXI4-Lite 全端口）
25     );
```
- ⭐ **第 15 行 `#3.846` 是半周期**（`3.846 × 2 = 7.692 ns` → **129.99 MHz**）✓ 与 `clk_out1 = 129.994 MHz` 对应。
  - ⭐ **注意这里没有例化 `clk_wiz_0`**，而是**直接产生 130 MHz 的时钟**（因为 TB 不需要验证 MMCM）。**这是模块级 TB 的标准做法：只给 DUT 需要的时钟，不引入无关模块。**
- ⭐ 第 17–25 行用**位置无关的命名端口例化**（推荐写法）。

### 1.3 四个任务：把 AXI 的"顺序与选通"都测到

⭐ **这是本 TB 最有价值的部分：它把 AXI4-Lite 的三种写顺序与字节选通全测了一遍。**

```
27     task axil_write_aw_then_w;          // ① 先 AW，后 W
28         input [15:0] addr; input [31:0] data; input [3:0] strb;
30             @(negedge clk); awaddr=addr; awvalid=1;
31             while(!awready) @(negedge clk);
32             @(negedge clk); awvalid=0;
33             @(negedge clk); wdata=data; wstrb=strb; wvalid=1;
34             while(!wready) @(negedge clk);
...
41     task axil_write_w_then_aw;          // ② 先 W，后 AW
...
55     task axil_read;                     // ③ 读
```
⭐ **第 30 行的 `@(negedge clk)` 技巧**：**在时钟下降沿驱动激励**，这样在下一个上升沿（DUT 采样时刻）信号已经稳定 —— **避免"激励与时钟同沿变化"导致的竞争**。⭐ **这是写 TB 的标准手法**（比用 `#1` 延迟更干净）。

⭐ **两个写任务的区别就是顺序**：
- `axil_write_aw_then_w`：先发 AW，等 `awready` 后再发 W；
- `axil_write_w_then_aw`：先发 W，等 `wready` 后再发 AW。
→ ⭐ **这两个任务正好测试了"AXI 允许 AW/W 任意顺序"这条规范**。如果 DUT 要求两者同时有效（如 `pd_axil_regs`），**这两个任务都会挂住**（因为 `awready` 永远等不到）。

### 1.4 判据（第 67–104 行）

```
67     task check_bypass_sample;
68         input [47:0] sample; input [3:0] valid;
70             @(negedge clk); adc_data=sample; adc_dv=valid;
71             @(posedge clk); #1;
72             if(filt_data !== sample || filt_dv !== valid) begin
73                 $display("FAIL bypass sample data=%h/%h dv=%h/%h",filt_data,sample,filt_dv,valid);
74                 errors=errors+1;
75             end
76             @(negedge clk); adc_dv=0;
```
⭐ **第 72 行用 `!==`（case inequality）而不是 `!=`** —— **这是一个重要的细节**：
- `!=` 遇到 **x/z** 时会返回 **x**，在 `if` 里被当作"假" → **可能漏报"输出是 x"的错误**；
- `!==` 会**把 x/z 当普通值比较**，所以 `x !== 0` 为真 → **能抓到 x 传播**。
- ⭐ **验证时一律用 `!==`/`===`**（四值比较），这是"找 bug 而不是找安慰"的正确做法。

⭐ **第 70–76 行的激励应用方式**：
- 在**下降沿**设置输入；
- 等**上升沿**（DUT 采样）；
- `#1` 后再比较（**避开"上升沿瞬间的 delta 周期"**）；
- 在下降沿清 `adc_dv`（避免下一次误采样）。

```
83         check_bypass_sample(48'h123_456_789_abc,4'b1111);
84         check_bypass_sample(48'hfff_800_001_555,4'b0101);
```
⭐ **两个测试向量是精心选的**：
- 第一个：**四个通道全不同**（`123`/`456`/`789`/`abc`），`dv = 1111` → 验证"四通道都没被改动顺序"；
- 第二个：`fff`/`800`/`001`/`555`，`dv = **0101**` → **部分 dv 有效**！⭐ 这是为了验证"`filt_dv` 会原样透传 `adc_dv`（**不强制全 1**）"。
  - ⚠️ **这一条很重要**：`pd_filter_chain` 是**按通道独立**的（`filt_dv[ch] = bypass ? adc_dv[ch] : sv[N_STAGE]`），所以 `0101` 应该原样透传 ✓。
  - ⭐ **如果 DUT 错误地用了"四通道 dv 全与"（像 `pd_pack48` 那样），这个测试就会失败** → **测试向量选择了能暴露该错误的输入** ✓ 很好的判据设计。

```
86         axil_read(16'h0004,rd);
87         if(rd !== 32'h0000_0400) begin $display("FAIL FSTATUS reset=%h",rd); errors=errors+1; end
88         axil_read(16'h0008,rd);
89         if(rd !== 32'h0000_000f) begin $display("FAIL bypass mask reset=%h",rd); errors=errors+1; end
```
- 第 86–87 行：**`FSTATUS` 复位值必须是 `0x0000_0400`**。
  - ⭐ **拆解 `0x0400`**：`bit[15:8] = 0x04`（版本号）+ `bit1 = 0`（`coef_dirty = 0`）+ `bit0 = 0` → `0x0400` ✓。**这个判据同时验证了"版本号在 `[15:8]`"这个位域约定**。
- 第 88–89 行：**`BYPASS_MASK`（`0x08`）复位值必须是 `0x0F`**（四通道全旁路）✓。

```
91         axil_write_aw_then_w(16'h0008,32'h0000_0005,4'b0001);
92         axil_read(16'h0008,rd);
93         if(rd !== 32'h0000_0005) begin $display("FAIL AW-first bypass mask=%h",rd); ... end
94         axil_write_w_then_aw(16'h0014,32'h0001_2345,4'b1111); // ch0/stage0/b0
95         axil_read(16'h0014,rd);
96         if(rd !== 32'h0001_2345) begin $display("FAIL W-first coefficient=%h",rd); ... end
97         axil_write_aw_then_w(16'h0014,32'h0000_ab00,4'b0010);
98         axil_read(16'h0014,rd);
99         if(rd !== 32'h0001_ab45) begin $display("FAIL WSTRB coefficient=%h",rd); ... end
100        axil_read(16'h0004,rd);
101        if(rd[1] !== 1'b1) begin $display("FAIL coefficient dirty=%h",rd); errors=errors+1; end
```
⭐ **这四条判据是全 TB 的核心**：

| 行 | 测试 | 验证了什么 |
|---|---|---|
| 91–93 | `AW 先 W 后` 写 `BYPASS_MASK = 0x5` | **AW/W 独立接收**（AW 先到） |
| 94–96 | `W 先 AW 后` 写系数 `0x0014 = 0x0001_2345` | **AW/W 独立接收**（W 先到）+ **系数地址映射**（`0x014` = ch0/stage0/b0） |
| 97–99 | 写 `0x0000_ab00` 且 `strb = 4'b0010`（**只改第 2 字节**）→ 期望读回 `0x0001_ab45` | ⭐ **WSTRB 字节选通**：低 16 位 `ab45` 的 `45` 必须保留 |
| 100–101 | 读 `FSTATUS[1]` 必须为 1 | **`coef_dirty` 被置位**（证明"写了系数、未 APPLY"）✓ |

- ⭐ **第 97–99 行的 `0x0001_ab45` 推演**：
  - 原值 `0x0001_2345`；
  - 写 `0x0000_ab00`，`strb = 4'b0010` → **只有第 2 字节（bit[23:16]）被改**；
  - 新值 = `0x0001_AB45` ✓（`ab` 覆盖了 `23`，其余保持）。
  - ⭐ **如果 DUT 不实现 WSTRB（整字覆盖），读回就是 `0x0000_ab00` → 测试失败** ✓ **判据能抓住这个 bug**。
- ⭐ **第 100–101 行的判据特别有意思**：它验证的是"**`coef_dirty` 在写系数后变 1**"。
  - ⭐ **这不是在测"写进去了"，而是在测"系统知道有新配置未生效"** —— 这正是 B09 里强调的"唯一生效判据"的**前置条件**（`coef_dirty` 从 1 变 0 才算 APPLY 成功）。
  - ⚠️ **但这个 TB 没有继续测"发 APPLY 后 `coef_dirty` 变 0"** —— 这是测试覆盖的空缺（B09 已记录）。

```
103        if(errors==0) $display("TB_PD_FILTER_CHAIN_PASS");
104        else $fatal(1,"TB_PD_FILTER_CHAIN_FAIL errors=%0d",errors);
```
⭐ **判据汇总方式**：**用一个 `errors` 计数器累加，最后统一判断**。
- ⭐ **好处**：一次仿真能暴露**所有**错误（而不是遇到第一个就停）→ **调试效率高**；
- 最后一行为 0 则打印 `*_PASS`，否则 `$fatal`（**硬失败，中止仿真**）。
- ⭐ **注意用了"打印 PASS 字符串"而不是只看 `$fatal`** —— 这是因为**上层脚本（或人）会 grep 这个字符串**作为"通过"的证据。⭐ **"可被判据字符串证明通过"是本工程所有 TB 的共同风格**（`TB_PD_FILTER_CHAIN_PASS`、`TB_PD_DDR_SLOT_MGR_PASS`、`TB_PD_SNAPSHOT_TRIGGER_PASS`、`DDS_TEST_PASS`）。

## 2. `tb_pd_ddr_slot_mgr.v`（83 行）—— 用"信号建模"代替真 DataMover

### 2.1 文件头（第 1–2 行）

```
2  // Focused RTL test: copy engine signals are modeled; no AXI DataMover BFM needed.
```
⭐ **一句话说清策略**：**"拷贝引擎信号用建模代替；不需要 AXI DataMover 的 BFM（Bus Functional Model）。"**
- ⭐ **为什么这是对的？** 因为 `pd_ddr_slot_mgr` 与 DataMover **没有直接接口**：它只通过 `o_copy_start`/`o_copy_busy`/`i_copy_done`/`i_copy_err` 这四个"抽象信号"与拷贝引擎交互。
- **所以只要"手工驱动这四个信号"，就能完整模拟拷贝引擎的行为** —— 不需要真实例化 DataMover、不需要接 AXI、不需要 BFM ✓。
- ⭐ **收益**：仿真**快**（无 AXI 事务仿真开销）、**稳定**（无 IP 初始化）、**判据清晰**（人为控制 `copy_done` 的时机）。
- ⭐ **可复用结论**：**模块级验证时，如果 DUT 的接口是"抽象信号"而不是"协议总线"，就用信号建模而非 BFM。** 只有在 DUT 直接说协议（例如 AXI 从机）时才需要事务/BFM。

### 2.2 `do_copy` 任务（第 31–51 行）

```
31     task do_copy;
32         input [31:0] expected_dst;
34             freeze_len=32'h0000_6000;
35             freeze_req=1;
36             @(posedge clk); #1; // reserve a FREE slot
37             @(posedge clk); #1; // launch into existing copy engine
38             if(!copy_start || copy_dst!==expected_dst || copy_len!==32'h0000_6000) begin
39                 $display("FAIL: copy launch dst=%h expected=%h len=%h",copy_dst,expected_dst,copy_len);
40                 $fatal;
41             end
42             copy_busy=1;
43             @(posedge clk); #1;
44             freeze_req=0;
45             copy_busy=0;
46             copy_done=1;
47             @(posedge clk); #1;
48             copy_done=0;
49             @(posedge clk); #1;
50         end
51     endtask
```
⭐ **`do_copy` 精确复现了"一次快照"的抽象时序**：
| 拍 | 动作 | 对应真实行为 |
|---|---|---|
| 1 | `freeze_req = 1` | 上游发出冻结请求 |
| 2 | 检查 `copy_start` 与描述符 | **预留**槽（拍 1 的下一拍） |
| 3 | 检查 `copy_start`/`copy_dst`/`copy_len` | **启动**拷贝（拍 2 的下一拍）→ **正是"预留与启动分两拍"的实现**（见 A09 §3.6） |
| 4 | `copy_busy = 1` | 拷贝引擎忙碌 |
| 5 | `freeze_req = 0; copy_busy = 0; copy_done = 1` | 拷贝完成 |
| 6 | `copy_done = 0` | 完成脉冲结束 |

- ⭐ **第 38 行的判据**：`copy_start && copy_dst == expected && copy_len == 0x6000` —— **同时验证"启动了"、"目标地址对"、"长度对"** ✓ 三条一起判。
- ⭐ **`#1` 的用法**：在 `posedge` 之后 `#1`，**等到非阻塞赋值都已生效**再检查输出 ✓（避免读到底层信号的旧值）。
- ⭐ **注意第 46 行 `copy_done = 1` 与第 45 行 `copy_busy = 0` 同拍** —— 这模拟了真实情形（`pd_ddr_snap_copy` 的 `o_done = 1` 与 `o_busy = 0` 确实同拍，见 A09 §2.5 第 217–218 行）✓ **模型与实现一致。**

### 2.3 判据序列（第 53–82 行）

```

56         if(!slot_valid[0] || snapshot_seq!=1 || slot0_len!=32'h0000_6000) begin

⭐⭐ **第 55–70 行是全场最精彩的判据设计**，它**主动规避了"最低编号优先"带来的歧义**：

1. **第 55 行**：第一次拷贝 → 期望落在 **slot0**（`0x2000_1000`）✓；
2. **第 59 行**：**先把 slot0 加锁**（`slot_lock = 4'b0001`）→ slot0 变 `LOCKED`；
3. **第 61 行**：**然后释放**（`slot_release = 4'b0001`）→ slot0 回 `FREE`；
   - ⭐ **这一步验证了 `lock` → `release` 的完整往返**（且验证 `lock` 后 `slot_locked[0]` 为 1、`release` 后 `slot_valid[0]` 为 0）；
4. **第 64 行**：第二次拷贝 → 期望落回 **slot0**（因为它是编号最小的 `FREE`）✓；
   - ⭐ **这正好验证了"最低编号 FREE 优先"的策略**！**TB 作者知道这个策略，所以期望值是 slot0。**
5. **第 65–67 行**：连续三次拷贝 → 依次落 **slot1 / slot2 / slot3**；
   - ⭐ **因为 slot0 仍被占用（没有释放）**，所以下一次会选编号更大的 `FREE` 槽 → **看起来像"轮转"**。
   - ⭐ **这就是 B09 里那句话的含义**："**要验四槽轮转必须『加锁后保持锁定』**" —— TB 正是这么做的（slot0 在第 64 行被再次占用后**没有再释放**）。
6. **第 68 行**：四个槽全 `VALID` + `snapshot_seq == 5`（一共 5 次成功拷贝）✓。

```
72         freeze_req=1; @(posedge clk); #1;

## 3. `tb_pd_snapshot_trigger.v`（84 行）—— 逐条验证优先级规则

### 3.1 判据设计（第 36–83 行）

⭐ **这是四个 TB 里"判据最系统"的一个**，它把 `pd_snapshot_trigger` 的四条规则**逐条测**：

```
43         channel_mask = 4'b0010;
44         pulse_event(4'b0001);
45         if (auto_freeze_trig || !armed) begin $display("FAIL: masked event"); $fatal; end
```
⭐ **规则 1：掩码过滤** —— `channel_mask = 0010` 时，**ch0 的事件不得触发**（`auto_freeze_trig` 保持 0，且仍在 `armed` 状态） ✓。

```
48         pulse_event(4'b0010);
49         if (!auto_freeze_trig || armed) begin $display("FAIL: first trigger"); $fatal; end
50         @(posedge clk); #1;
51         if (auto_freeze_trig) begin $display("FAIL: trigger width"); $fatal; end
52         pulse_event(4'b0010);
53         if (auto_freeze_trig) begin $display("FAIL: duplicate before resume"); $fatal; end
```
⭐ **规则 2 与 3**：
- 第 48–49 行：**选中通道的事件必须产生触发**，且**上锁**（`armed` 变 0）✓；
- 第 50–51 行：⭐ **触发必须是"单拍脉冲"**（下一拍 `auto_freeze_trig` 必须回到 0）✓ —— **这是一个很容易漏测的判据**（如果实现是"电平保持"，就会失败）；
- 第 52–53 行：⭐ **`resume` 之前不得重复触发**（`waiting_resume` 上锁）✓。

```
55         freeze_resume = 1'b1;
56         @(posedge clk); #1;
57         freeze_resume = 1'b0;
58         if (!armed) begin $display("FAIL: re-arm after resume"); $fatal; end
```
⭐ **规则 4：`resume` 后必须重新武装** ✓。

```
60         slot_full = 1'b1;
61         pulse_event(4'b0010);
62         if (!slot_full_drop || auto_freeze_trig || slot_full_drop_count != 1) begin
63             $display("FAIL: full-slot rejection"); $fatal;
64         end
```

### 4.4 为什么激励要用 MATLAB 生成的 `.mem`

工程里 `sim/` 目录下有：

```
sim/generate_pd_adc_waveform.m        ← 生成波形的主脚本
sim/gen_iir_coef.m                    ← 生成 IIR 系数（.hex/.csv）
sim/pd_adc_4ch_26m_40ms.mem           ← TB 用的 4 通道激励（1,040,000 点）
sim/coef_fs26m.hex / .h / _float.csv / _q16.csv   ← 三套采样率下的 IIR 系数
sim/resp_fs26m.csv 等                 ← 频响数据
```

⭐ **为什么不用"在 Verilog 里直接写波形生成"？** 三个理由：
1. **PD 脉冲的形态需要"真实的物理模型"**（上升沿、衰减拖尾、四通道幅度差异、相位分布）—— 在 MATLAB 里写这些模型**比 Verilog 方便得多**（有现成的信号处理函数）；
2. **激励必须是"可被独立复算的"**：TB 只负责"把激励灌进去"，**判据的正确性由 MATLAB 侧独立验证**（例如"这一段应该有 4 个脉冲"）；
3. **激励可以跨工具复用**：同一份 `.mem` 可以被 Verilog 仿真、被 Python 脚本、被 PS 侧 C 代码（作为测试向量）共同使用 → **形成"单一激励来源"**。
- ⭐ **这正好符合用户的工程偏好**（`~/.workbuddy/MEMORY.md` 里的"测试向量与初始化文件：用 MATLAB 生成 `.coe`/`.hex`，并在 MATLAB 内做波形仿真与逐位比对"）。
- ⭐ **`pd_adc_4ch_26m_40ms.mem` 的四个数字直接对应**：4 通道 / 26 MSPS / 40 ms（1,040,000 点） ✓ 自解释的文件名。

## 5. 仿真覆盖的空白（B09 已记录）

⭐ **没有顶层 testbench**，所以以下环节**完全未被仿真验证**：
1. **DataMover（`dm_wr` / `dm_cp`）的行为**：命令/状态字交互、错误响应、4 KB 拆包；
2. **环形写入管理器与真实 DataMover 的联合**（`pd_ddr_ring_wr` 只用过"信号建模"或上板验证）；
3. **`fifo_48_cdc`（IP）的跨时钟行为**（IP 本身有厂商验证，但"与 `pd_pack48` 的连接"没测）；
4. **`axis_dfi_64` 的弹性缓冲与反压行为**；
5. **整个 DDR 支路的端到端**（ADC → 环形写 → 冻结 → 拷贝 → 快照区）；
6. **AXI 互连 / SmartConnect / PS7 HP 口**的行为；
7. **`pd_axil_regs` 与真实 AXI 主机的交互**（`tb_pd_feature_dds` 用的是自己写的 `axil_write` 任务，**AW/W 同时有效的风格** → **所以它测不出 `pd_axil_regs` 的 AW/W 独立性问题**）；
8. **`pd_axil_regs` 的所有寄存器**（TB 只配了 `GCTRL` 与 `CTRL`/`THRESH`）；
9. **12 档门槛计数、帧统计、APPLY 生效**（`coef_dirty`/`apply_done` 的完整流程）；
10. **PRPD RAM 的读改写与清零**。

⭐ **这些空白不是"疏忽"，而是"仿真成本 vs 收益"的取舍**：
- 顶层 TB 需要例化 5 个真实 IP（DataMover×2、FIFO、axis_data_fifo、PS7 模型），**仿真启动慢、跑得慢、判据复杂**；
- 而"环写 + 冻结 + 拷贝"这条链**已经在硬件上验证过了**（见 `MEMORY.md` §0.1：`base=0x20001000`、`len=3,120,000`、四槽轮转、槽满拒绝、快照内容 32/32 逐位全中）。
- ⭐ **所以本工程的验证策略是"模块级仿真 + 硬件级端到端"，跳过了"顶层仿真"这一层。** 这是一个**明确的取舍**，代价是"环写与 DataMover 的交互细节只能靠上板调试"（这也解释了为什么 `DDR_STATUS[5]` 的二义性要靠上板+推理才能闭环）。

## 6. 本篇易错点小结

1. ⭐ **验证时一律用 `!==`/`===`（四值比较）**，不用 `!=`/`==`（遇到 x/z 会返回 x，被当"假"，漏报错误）。
2. ⭐ **激励在时钟下降沿驱动**（`@(negedge clk)`），避免与采样沿竞争。
3. ⭐ **模块级 TB 用"信号建模"代替 BFM**：当 DUT 的接口是抽象信号（非协议总线）时，手工驱动那几个信号即可，无需真实 IP。
4. ⭐ **`tb_pd_filter_chain` 用"两个写任务（AW 先/W 先）"测 AW/W 独立性** —— 这正是 `pd_axil_regs` 做不到的地方。
5. ⭐ **`check_bypass_sample` 的第二个向量 `dv = 4'b0101`** 专门验证"dv 按通道原样透传（不强制全 1）"。
6. ⭐ **`tb_pd_ddr_slot_mgr` 主动规避"最低编号优先"的歧义**：**先锁 slot0 并保持占用**，才能观察到四槽依次被填 → **"要验轮转必须加锁后保持锁定"**。
7. ⭐ **`tb_pd_snapshot_trigger` 逐条测优先级规则**，含"触发必须是单拍脉冲"与"resume 前不得重复触发"。
8. ⭐ **`tb_pd_feature_dds` 先跑一个"安静周期"让 DUT 测出 M = 520000**（否则会用 `PD_M_DEFAULT = 400000` 的错值）。
9. ⭐ **TB 可以用 `%` 与实数**（仿真奢侈），**RTL 不行**（所以要 Bresenham）—— 两者对比鲜明。
10. ⭐ **`tb_pd_feature_dds` 用的是 12 位的实际事件包位位置**（`[26:25]`/`[39:28]`/`[27]`），**与 `pd_feature_core` 的注释不一致** → **以 TB 与拼接表达式为准**。
11. ⚠️ **`"\\n"` 写出的是字面 `\n` 而非换行**（第 71/77/80 行）→ CSV 可能不是真正的多行文件。
12. ⚠️ **`USE_MATLAB_SAMPLES = 0` 时内建激励没有 PD 脉冲** → 与"必须有事件"的判据冲突，该 TB 会失败。
13. **判据用"打印 PASS 字符串 + `$fatal`"双保险**，便于脚本 grep 与硬失败。
14. **`errors` 计数器累加再统一判断**：一次仿真暴露所有错误，调试效率更高。
15. ⭐ **没有顶层 testbench**：DataMover、IP、AXI 互连、整条 DDR 支路、以及 `pd_axil_regs` 的 AW/W 独立性问题**都未被仿真覆盖** —— 靠上板验证。
