## 1. 方向正确性的论证：哪些站得住，依据是什么

### 1.1 核心架构判断 —— 正确，依据是硬约束

**主张**：FFT 执行位置固定为 PS，不恢复 PL 内四路并行 FFT；FFT 输入必须来自 DDR 原始快照。

**依据（全部为你们自己的实测数据）**：

| 依据 | 出处 |
|---|---|

→ **这一条不是偏好，是资源与相位正确性的双重硬约束。方向正确。**

**"不允许分析支路对采集/滤波/判决/快照施加反压"** —— 这条尤其重要：因为分析支路只在 PS 侧读 DDR，物理上就无法反压 PL。它同时是**架构冗余度的保证**（PS 落后不会拖死采集）。正确。

### 1.2 采样率约束 —— 正确，且与逐拍推演一致

路线书 §8.1：

```text
26 MSPS：使用 fs26m 系数
16.25 MSPS：仅适用于确认 4:1 抽取后链路
```

**该结论与 `pd_iir_biquad.v:55-60` 的逐拍推演完全一致**：

```verilog
if (!rst_n || clr)  phase <= 0;
else if (dv)        phase <= 1;      // ← dv 优先级最高
else if (phase==4)  phase <= 0;
else if (phase!=0)  phase <= phase+1;
```

130 MHz 下 5 拍/样本：26 MSPS → `dv` 每 5 拍一次，恰好走完 0→1→2→3→4（**零余量**）；
65 MSPS → `dv` 每 2 拍一次，`phase` 在 1、2 之间被反复复位，**永远到不了 4 → `dout_dv` 恒 0 → 静默失效**。✅ 路线书写对了。

## 2. 需要更正的四处

### 更正 1（最重要）：`DDR_STATUS=0x00000021` 不能作为"DDR 环形采集通过"的证据

`pd_ddr_axil.v:316-319` 的读回拼接原文：

```verilog
A_STATUS: s_axi_rdata <= {22'd0, i_snapshot_cfg_err, i_copy_err,
                          i_copy_pending, copy_done_sticky, i_err,
                          i_snap_overrun, i_freeze_done, i_hiwm,
                          i_copy_busy, o_acq_en};
```

逐位展开（MSB 先）：

| 位 | 名称 | 位 | 名称 |
|---|---|---|---|
| 9 | `snapshot_cfg_err` | 4 | `snap_overrun` |
| 8 | `copy_err` | 3 | `freeze_done` |
| 7 | `copy_pending` | 2 | `hiwm` |
| 6 | `copy_done_sticky` | 1 | `copy_busy` |
| **5** | **`i_err`** | 0 | `acq_en` |

`0x21 = 0b10_0001` → **bit0 `acq_en`=1 且 bit5 `err`=1**。

`pd_ddr_ring_wr.v:429-432` 明确 `o_err` 的含义与粘滞性：

```verilog
// 状态字约定：0x80 = 正常完成；非 0x80 视为异常。错误同样
// 粘滞到软件确认，避免轮询漏掉单拍 DataMover 状态。
if (i_freeze_resume || !i_acq_en)
    o_err <= 1'b0;
else if (i_s2mm_err || (s_sts_tvalid && (s_sts_tdata != `DM_STS_OK)))
    o_err <= 1'b1;
```

→ **bit5 表示"DataMover 返回了非 `0x80` 的状态字"**，即**一次真实的环形写错误**。

**更严重的连带问题**：`pd_snapshot_poll.c` 的通过判据只查 bit8/bit9——

```c
if (ddr_status & (DDR_STATUS_COPY_ERR | DDR_STATUS_CFG_ERR))   // 只查 bit8 / bit9
    fail_stop("DDR copy/config error");
```

**它不查 bit5。** 所以一个真实的环形写错误可以在测试报 `SNAPSHOT_POLL_PASS` 的同时被完全忽略。

→ **建议**：
1. §1 表格该行改为「DDR 环形采集｜已使能，但 `DDR_STATUS[5] err` 被置起，待解释」，并**粘贴原始完整日志**（含 `WAIT i=...` 与 `fail_stop` 行），不要只摘一个值。
2. `wait_snapshot_ready()` 把 `DDR_STATUS` bit5 纳入错误判据，或至少在 PASS 路径上单独打印并断言为 0。
3. 先查清 `0x21` 是**哪一次运行、哪一个时刻**读到的——它在"刚 arm 完"时本应为 `0x01`（因为 L184 写 `DDR_CTRL=1` 之前 `acq_en=0` 会把 `o_err` 清掉）。

### 更正 2：§2.2 的"4 KiB 页边界约束"对**长度**不成立

用同节自己引用的实测值 `len=3120000` 验算：

| 约束 | 计算 | 结果 |
|---|---|---|
| 8 字节对齐 | 3120000 / 8 = 390000 | ✅ |
| 24 字节块对齐 | 3120000 / 24 = 130000 | ✅ |
| 4 KiB 页对齐 | 3120000 / 4096 = **761.71875** | ❌ |
| 0x3000 对齐 | 3120000 / 12288 = **253.90625** | ❌ |

`pd_ddr_defines.vh` 里 `LCM(4096,24)=12288` 的"对齐铁律"**约束的是基址与整区长度**（RING 基址/长度、SNAP 基址/长度、四槽基址），
文件里逐个给的校验例也全是对着这些量算的。**单次快照长度只受 24 字节块对齐约束**——
26 MSPS 下一个工频周期 520,000 点，不可能同时凑成 4096 的整数倍。

→ **风险**：若这条被当成硬要求写进 `pd_snapshot_unpack()` 的长度校验，会把**每一次正常快照都判为非法**。
建议把三条对齐要求**分别注明适用范围**（4 KiB 只约束基址/整区；24 B 约束数据块；8 B 被 24 B 蕴含）。

### 更正 3：PRPD 归属与现有 RTL 冲突

路线书 §1.1 把「快照解包、FFT、频谱峰值、选频、**PRPD 和统计分析**」划给 PS 分析子模块，§8 的处理链也以「事件统计 → PRPD」收尾。

但 `pd_feature_core.v:538` 的状态机注释原文：

```verilog
// 事件链 S_ACC->(S_PEAKN)->S_PRRD->S_PRWR 原子执行, S_CYC 仅在 S_IDLE
```

→ **PRPD 已经在 PL 里实现了**（`S_PRRD` 累加、`S_PRWR` 写出，且与事件链原子执行）。
而且 09-17 的数据流定案把 PRPD 明确列在 PL 侧（"PL 留采集、CDC、相位、峰值/门槛、**PRPD**、事件包、DDR 环形写、快照与槽管理"）。

**这不是文字分歧，它决定了数据通路设计：**

| PRPD 放哪 | PS 需要收到的数据量 | 落后时的后果 |
|---|---|---|
| **PL 实时**（现状） | 只需读累积直方图（几百字节级） | 基本无害 |
| **PS**（路线书口径） | 必须收到**每一个事件**的（相位, 幅值） | 事件流经 DMA 变长写入 DDR，PS 一旦落后，环形区被覆盖 → **PRPD 静默漏计** |

→ **这是整份路线书里最有后果的架构歧义，必须显式裁决。**
建议口径：「**PL 保留实时 PRPD 作为产品主路径；PS 基于原始快照重算 PRPD 仅用于离线校核与显示**」——
这样既不推翻已验证的 RTL，又保留了 PS 的分析能力。

### 更正 4（09-18 补，实算）：路线书完全没有提到"解除旁路会改变全部码域判据"

路线书 §4 把 `pd_filter.c` 的职责写到"解除旁路"为止；§8 的 PS 算法链也没提 PL 滤波器对特征核的影响。
**但 `pd_feature_0` 就在滤波器下游**（已核实：`pd_filter_0/filt_data → pd_feature_0/adc_data`），
一旦解除旁路，特征提取的**全部幅度域判据**立即失效。以下为用 100 kHz–1 MHz 那组量化系数的实算：

| 判据域 | 参数 | 量纲依据 | 滤波切换后 |
|---|---|---|---|
| 相位域 | `cfg_phase_win` / `cfg_phase_inc` / REG0-REG1 相位区间 | — | ✅ 几乎不受影响（群延迟变化折算 **0.016°**） |
| **码域** | `cfg_thresh` / `cfg_pos_thr[6]` / `cfg_neg_thr[6]` | `pd_feature_core.v:442-443` 原文"均为 ADC 码(与 THRESH 同域)" | ❌ **必须重标**：PD 脉冲幅度只剩 **38.1%** → 等效门槛抬高 **2.6 倍** |
| pC 域 | `cfg_reg0_q` / `cfg_reg1_q` | `q_pc = (q_code × cfg_scale) >> 8`（`L390-392`） | ⚠️ 随 `cfg_scale` 同步重标即恢复 |

**并且发现一处路线书未涉及的实质风险（新）**：滤波后振铃的**负峰 = 正峰 × 13.5%** →
**输入 ≥ 约 780 码的 PD 脉冲，负向振铃会超过 40 码负阈值 → 同一颗正极性放电会在负阈值上再触发一次**
→ 帧正/负计数各错一次、**PRPD 负半周凭空多出一簇**。
可操作约束：**`cfg_neg_thr ≥ 0.25 × cfg_pos_thr`**（起点值）。

**另需一并更正**：`cfg_deadtime` 需按振铃宽度重设。`pd_feature_core.v:768-770` 明确跨窗去重
"**不设回差、全靠死区**"；滤波把高于门槛的宽度从 4 样点拉到 12 样点 → 跨窗概率 0.8% → 2.4% →
**死区需 ≥ 1 个相位窗（26 MSPS/N=1024/50 Hz 下约 508 样点）**。

→ **建议**：
1. §4.2 的 `pd_filter.c` 接口增加配套的 `pd_feature_recalibrate(fs_hz, filter_state)`；
2. 在 §6（IRQ）之后、§8（PS 算法链）之前，**插入一次"旁路态 vs 滤波态同段激励 A/B"作为标定实验**
   （记录 `cfg_thresh` 命中率、帧正/负计数、6 档直方图、PRPD 快照）；
3. **标定值不得用推算值直接下发**——上面 38.1% 来自 DDS 的 4 样点矩形脉冲，真实 PD 脉冲更窄
   （单样点脉冲实测仅 17.6%），必须实测。

> 完整推导、逐幅度档数据与参数清单见：本目录 `IIR滤波配置闭环实施方案_20260918.md` **§1.6**。

## 4. 风险清单（按影响排序）

### R1（高）——「PL 实时算法核心：已完成并板级通过」目前**无证据支持**

三个独立事实：

**(a) BD 里没有 `tready_tie1`**（我对 `pd_feature_bd.bd` 做 `tready_tie1|xlconstant` 计数 = **0**）。
`pd_feature_0/m_axis` 只接两个下游：

```json
"pd_feature_0_m_axis": { "interface_ports": [
    "pd_feature_0/m_axis", "axi_dma_0/S_AXIS_S2MM", "ila_0/SLOT_0_AXIS" ] }
```

→ **tready 由 DMA 提供**。DMA 未启动（没有描述符、`RS=0`）时 `s_axis_s2mm_tready = 0`。

**(b) 特征核的事件链状态直接受下游反压门控**（`pd_feature_core.v`）：
`L651 else if (fsm_take_cyc) fsm <= S_CYC;`、`L695/L725 if (ev_tready) begin`、`L840-841 S_CYC: begin if (ev_tready) begin`。
而 `ev_tready = c_tready[i]`，由本地事件 FIFO 驱动；FIFO 满 → 整条链停住。

**(c) 本项目自己的记录**（09-17 同事对比）：
「tready=0 → 内部 `S_CYC` 不推进 → 写 APPLY 后阈值永不生效 → 上板恒为 `POS: 6 6 6 6 6 6`；
**补上后 DMA 未启动即可读到 `6 5 4 3 2 1`**」。

**而 `SNAPSHOT_POLL_PASS` 不能证明特征核正常** —— 关键在这行（`pd_feature_top.v:375-377`）：

```verilog
// c_tready is driven by the local event FIFO.  Therefore this pulse means ...
assign o_event_accept = c_tvalid & c_tready;
```

`c_tready` 来自**本地事件 FIFO**，**不依赖 `m_axis_tready`** → **自动快照这条路绕过了下游反压**。
所以它 PASS 只证明"触发仲裁器 + DDR 拷贝 + 槽管理"这条链通了，与"阈值判决正确、事件输出正常"是两件事。

→ **判定条件**：只有在「启动 DMA S2MM 并持续搬运」或「补上 `tready_tie1`」之后，特征核的阈值/事件输出才能算已验证。
在此之前，§1.1「PL 实时算法核心：已完成并板级通过」与 §15「原型闭环完成」都应标为**未验证**。

### R2（高）—— `FILTER_APPLY_VERIFY_PASS` 缺乏可复核留档，时间线显示很可能从未打印成功

证据链：

| 事实 | 出处 |

### R4（中）——「真实 AD9226」放在阶段 9（倒数第二），与原计划冲突

| 顺序 | 原《PL自动快照触发与项目完整实施计划》§7 | 本路线书 §14 |
|---|---|---|
| … | 3 滤波闭环 → **4 顶层快照仿真** → **5 真实 ADC 前端** → 6 PS 数据通路 → 7 上位机 → 8 时序收敛 | … → 5 PS 算法链 → 6 四槽轮转 → 7 协议 → 8 上位机 → **9 真实 AD9226** → 10 长期运行 |

→ **真实 ADC 从第 5 位挪到第 9 位**，之前 8 个阶段全部基于 26 MSPS DDS。

**风险**：65 MSPS 会改动 PL 架构（CDC 深度、FIFO、判决支路抽取、DDR 带宽），

**建议**：不必真上板，但要把「**65 MSPS 的 PL 架构决策**」提前到阶段 1–2 之间**先锁死**（即：判决支路确认走 CIC 4:1 抽取 → 16.25 MSPS，或另定方案），避免 PS 侧返工。

### R6（低）—— 若干接口细节

1. **§4.2 `pd_filter_apply_26m_bandpass()`**：把采样率写进函数名，与"系数按 Fs 参数化"的初衷冲突。建议 `pd_filter_apply_bandpass(uint32_t fs_hz, const pd_band_t *band)`。
2. **§7.2 `pd_waveform_t` 用 `uint16_t *ch[4]`**：原始数据是**偏移二进制**（0..4095，中值 2048）。"去直流"应是**减 2048**（或减滑动均值），不是普通的零均值化。结构里没体现符号约定——这是经典出错点。
3. **§10.2 快照帧把四通道排成连续平面**：解包需要 4×520,000×2 B = **4.16 MB** 额外缓冲（数据从 3.12 MB 变 4.16 MB），多一次 DDR 搬运。1 GB DDR 下可行，但应有意识地设计。
4. **§2.1 接口基线表未标注**：本工程地址映射与接口契约/同事**相反**（契约是 ddr 在前、feature 在后）——这是已记录的上板隐患，同事驱动跑你的 bit 会全打错地址。
5. **§7.2 `sample_count = bytes / 6`** 正确（一个采样时刻 = 48 bit = 6 Byte），但措辞"样本计数"容易被误读为"每通道样本数"。建议注明"采样时刻数"。

## 5. 该方向成立 / 不成立的条件

### ✅ 方向成立的前提（全部满足才叫走通）

1. **`m_axis_tready` 有确定来源** —— 要么启动 DMA S2MM 持续搬运，要么补 `tready_tie1`。
   → 否则"PL 实时核心通过"永远无法成立（R1）。
2. **`FILTER_APPLY_VERIFY_PASS` 能在串口上真实复现一次**（并留下日志）。
   → 否则 §15「原型闭环完成」不成立（R2）。
3. **PS 侧单槽处理时间实测 < 80 ms**（4 × 20 ms 冻结节拍）。
   → 否则四槽必然溢出，PRPD/事件统计必须改成"允许丢弃 + 计数上报"的设计（A1）。
4. **65 MSPS 的 PL 架构在阶段 1–2 就锁定**（判决支路抽取 vs 降速）。
   → 否则阶段 5–8 可能整体返工（R4）。
5. **契约 §2/§8 关于"DDR 存原始 vs 存滤波后"的表述完成修订。**
   → 否则与搭档的接口处于未定义状态（A5）。
6. **AD9226 的电气前提冻结**（输出模式、时钟来源、IO 电压、数据引脚）。
   → 否则 §12 无法开工。
7. **滤波状态与特征判据"配套固化"**（更正 4）。只要滤波会开，`cfg_scale` / `cfg_thresh` /
   `cfg_pos_thr[6]` / `cfg_neg_thr[6]` / `cfg_deadtime` 就必须整体切换，不能只切一半。
   → 否则会出现"旁路态标定、滤波态运行"的 2.6 倍系统性偏差，**且不报任何错**。

### ❌ 明确不成立的边界（这些路上不要走）

| 不要做 | 原因 |
|---|---|
| 把 FFT 放回 PL（四路并行） | 已实测放置失败：需 7,232 Slice > 7,205 |
| 65 MSPS 直连当前五拍 IIR | `dv` 每 2 拍复位相位 → `dout_dv` 恒 0，**静默失效** |
| 把 `filt_data` 当 FFT 输入 | ① 它根本不进 DDR；② IIR 非线性相位污染 PRPD |
| 把 `SNAPSHOT_POLL_PASS` 当作"特征提取/阈值判决已验证" | 两条路径的反压耦合点不同（`o_event_accept` 不依赖 `m_axis_tready`） |
| 把 100 kHz–1 MHz 当最终规格 | 未完成契约确认前只是实验参数（⚠️ 这一点 13:17 的 `实施顺序` 写明了，新路线书反而没写） |
| 在 BSP 没有命名中断宏前硬编码 GIC ID | 猜错的表现是"能编能跑但不进中断"，静默失效。✅ §6.3 自己写对了，保持 |
