## 2. 三条可执行路线（按代价排序）

### 路线 A ★ 最高优先｜零 RTL 改动，只改 PS

**目的**：判定 `DDR_STATUS[5]` 是**粘滞旧错误**还是**真实故障**。

**做法**：在 `pd_snapshot_poll.c` 里，于开采集前与 fail 前各读一次进度寄存器并打印。

**判据表**：

| `0x38 CMD_CNT` | `0x18/0x1C WR_BYTES` | 结论 |
|---|---|---|
| 在涨 | 在涨 | 写路径**活着** → `err` 是粘滞旧错误，需要复位 DataMover（路线 C 的 `sw_rst` 问题） |
| 在涨 | 不动 | 命令在发但数据不落盘 → DataMover 真报错 |
| 不动 | 不动 | 写路径整体停摆 → 更上游就不工作了 |

**为什么它是最优先**：它不需要综合、不需要 ILA、不需要写 TB，
只重编 ELF 就能把"甲/乙"这个岔路分开。**在做任何波形工作之前先做它。**

**附加**：同一轮里先读一次 `SLOT_SEQ` 与 `SNAP_TRIG_DROPS`，作为"本轮是否发生过任何快照动作"的旁证。

### 路线 B｜需写 TB，看**仿真**波形（这才是"看整体"的正路）

**B1 先跑已有的 4 个模块级 TB**，拿"已知良好"基线：
```
tb_pd_filter_chain    → TB_PD_FILTER_CHAIN_PASS
tb_pd_snapshot_trigger→ TB_PD_SNAPSHOT_TRIGGER_PASS
tb_pd_feature_dds     → 事件包
tb_pd_ddr_slot_mgr    → 槽生命周期
```
这一步的价值是：**证明"模块本身没问题"，把问题范围收敛到模块之间的接线与顶层**。

**B2 再写顶层 TB**（需 Codex 写），覆盖定稿阶段 2 八项。

**注意**：B1 通过**不能**推出"PL 整体没问题"——模块级通过 + 顶层没测，恰恰是这次出问题的位置。

### 路线 C｜需改 RTL + 重综合，让 `err` 可归因

**C1（最省）**：把 `pd_ddr_wr_top.v:782-791` 已算好的 `dbg_ddr` 接到 `pd_ddr_axil` 的空闲偏移 `0xA4`。

```

            hiwm[10], ring_err[9], copy_err[8], skew_err[7], wr_off[6:0] }
```
**含 `ring_err`，不含 `ring_ovf`** → `[9]=1` 就是 DataMover 错；`[9]=0` 而 `DDR_STATUS[5]=1` 就必然是 `ring_ovf`（上游丢数）。

**C2（补充）**：再把 `pd_ddr_wr_top.v:453-454` 悬空的 `o_sts_tdata`(8b) 与 `o_last_btt`(32b) 接到 `0xA8`/`0xAC`，拿到 DataMover 状态字与最近一次 BTT。

**C3（验证手段）**：路线 C 之后，若还要"看波形"，应新增一个探针 ILA 挂 `pd_ddr_0` 内部的
`wr_off / wrap_cnt / dm_wr_err / sts_tdata[7:0] / sts_tvalid / acq_en`，而不是继续用现有那个只探 AXIS 的 ILA。

> ⚠️ C1/C2 之后**必须重跑门禁 B0 再综合**，且 `Place 30-487`、WNS/TNS 需重新确认。

### 7.2 数值核算：单位命令字节数精确命中参数

| 区间 | WR_BYTES 增量 | CMD 增量 | 比值 | `DDR_BURST_BYTES` |
|---|---|---|---|---|

| AFTER → FAIL | 2,966,016 | 1,931 | **1,536.0** | 同上 |

- `PTR` 增量与 `WR_BYTES` 增量**逐段相等**（3 段全满足）——`WRAP=0` 时二者必须相等，成立。
- 累计 8,655,888 B ≈ 8.66 MB，环容量 128 MB → **未回绕**，`WRAP=0` 自洽。

### 7.3 结论

**(1) PS 正确性：通过（强证据）**

6 个进度寄存器全部读出，且**内部自洽**：`PTR == WB`、`WB / CMD == 1536` 精确等于参数；
`PRE` 全 0 说明采集使能前确无活动（`DDR_CTRL` 写通路正确）；契约校验与武装校验通过。
→ **PS 的 AXI-Lite 读写、地址映射、寄存器语义理解全部正确。**

**(2) PL 正确性：核心链路通过，仅 `err` 起因未定**

| 项 | 结论 | 证据 |
|---|---|---|
| 环形写 | ✅ **健康** | CMD/WB/PTR 单调推进，1536 B/命令精确命中参数 |
| 冻结 | ✅ 成功 | `DDR_STATUS=0x69` → bit3 `freeze_done=1` |
| 槽拷贝 | ✅ 成功 | 同值 → bit6 `copy_done`（粘滞）=1 |
| 槽就绪 | ✅ | `SLOT_STATUS=0x00080001` → bit0 slot0 valid + bit19 `snapshot_ready` |
| 丢数 | ✅ 无 | `SLOT_DROPS=0`、`TRIG_DROPS=0` |
| `err` | ❌ **未定** | bit5=1；bit8/bit9=0 → 只能是 `ring_err \| ring_ovf` |

**(3) ⭐ 结构性发现：本轮的 `SNAPSHOT_FAIL` 是假警报**

`SLOT_STATUS=0x00080001` 已表明槽就绪（快照成功），但轮询循环里 `err` 检查排在 `READY` 检查之前，
于是直接停机并打印 `SNAPSHOT_FAIL`。

→ **上一轮与这一轮的 `SNAPSHOT_FAIL` 都不能推出"快照失败"。**
（本轮之所以能看出快照成功，是因为进度探针的约 32 ms 忙等给了冻结+拷贝完成的时间。）

→ **`err` 与"快照是否成功"是两件独立的事。** 这是定稿 §5 的盲点：它只说 `err=1` 不算通过，
却没要求把 `err` 与快照结果**分开报告**，导致一个部分成功的链路被报告成全失败。

### 8.2 ✅ 判定：`err` 是一次性启动瞬态，机制已定位

`PROGRESS[CLEARED]` 的 `STS=0x00000001` → **bit5=0**。清零后约 45 ms（WB +6,965,760 B）内**未复现**。
→ **`err` 为一次性瞬态，不是持续性故障。** 判据表命中"bit5=0"分支。

**机制（RTL 逐步对上）**：

```
1. pd_ddr_wr_top.v:413  up_ovf = (s48_a_valid & (fifo_full | fifo_wr_busy)) | ...
                        —— 不受 acq_en 门控
   pd_ddr_wr_top.v:341  beat_en 来自 pd_pack192.o_beat_en  —— 同样不受 acq_en 门控
                        → 采集关闭期间上游仍在持续喂数，信用/缓存一直在堆积

2. pd_ddr_ring_wr.v:298  avail_bytes 仅由 cmd_fire 排空，而命令下发受 acq_en 控制
                        → PRE 时 AVAIL=4144 ≥ OVF_THRESH(3072)，hiwm=1（STS bit2=1）

3. pd_ddr_ring_wr.v:428  if (i_freeze_resume || !i_acq_en) o_err <= 1'b0;
                     :431  else if (i_s2mm_err || (s_sts_tvalid && s_sts_tdata != DM_STS_OK))
                              o_err <= 1'b1;
                        → acq_en=0 时 err 被优先分支**强制清零**（所以 PRE 读到 err=0，
                          尽管此时 up_ovf 已经是高）

4. acq_en=1 的那一拍，else-if 生效 → 因 up_ovf 仍为高，o_err **立刻置位**
                        → 与"BEFORE（acq_en 后约 3.8 ms）已是 STS=0x21"完全吻合

5. 随后命令开始排空信用：AVAIL 4144 → 1176 → 1016 → 232，FIFO 解除满状态，
   up_ovf 回落但 o_err 粘滞
                        → resume 清粘滞后不再置位（CLEARED bit5=0）✓
```

**根因**：`i_beat_en` 与 `up_ovf` 都没有按 `acq_en` 门控，**采集未使能时上游仍在灌数据**，
使能瞬间信用/缓存已饱和 → `ring_ovf` 置位一次。

**两种可选修法**（二者取一即可，属 RTL 改动）：
- (a) 用 `acq_en` 门控 `i_beat_en` 与 `up_ovf`（采集关闭时不计数、不报溢出）；
- (b) 在 `acq_en` 上升沿清 `avail_bytes`，使每次使能都从零信用开始。

> 归因置信度说明：`DDR_STATUS[5] = ring_err | ring_ovf | copy_err | snapshot_cfg_err`，
> 实测 bit8/bit9=0 故只需在 `ring_err` / `ring_ovf` 之间二选一。
> 判为 `ring_ovf` 的依据是：① 一次性且不复现；② 稳态速率完全正常（1536 B/命令精确）；
> ③ `up_ovf` 在 acq_en=0 期间本就应为高（AVAIL 4144 ≥ 阈值）；
> ④ 而 `ring_err` 需要 DataMover 活动才可能置位，PRE 时 CMD=0、无命令下发。
> **若要 100% 终审，仍需把 `dbg_ddr[9]`（`ring_err`）引出来看——见路线 C1。**

### 8.3 快照链路：全部通过（含数据读回）

```
SNAPSHOT slot=0 base=0x20001000 len=3120000 seq=1 flags=0x00000001
```
- `base=0x20001000` = `DDR_SLOT0_BASE` ✓
- `len=3,120,000`；3,120,000 / 24 = **130,000** 整 → 24 字节对齐成立（定稿 §6）✓
- `seq=1`，`flags` 有效位 ✓

**数据读回非平凡**：`first=0x118007FC`、`last=0x81A7F67F`。
按小端 32 位字解码，`bits[11:0]` 与 `bits[23:12]` 两个 12 位通道分别落在

### 8.4 ⚠️ 新发现的待查项：resume 后没有第二次快照

`PROGRESS[CLEARED]` 的 `SLOT=0x00080000` → bit19 `snapshot_ready` 仍为 1，

## 12. v5：数据内容验证（2026-09-20 16:00）

### 12.1 ⚠️ 先更正一处此前的错误记录

此前多处（含本清单 §11.3）记为"**固定 101.5625 kHz 三角波**"，即假设相位**步进为 1**（26e6/256）。
但 `pd_dds_adc_source.v:110-113` 实际是：

```verilog
phase0 <= phase0 + 8'd3;
phase1 <= phase1 + 8'd5;
phase2 <= phase2 + 8'd7;
phase3 <= phase3 + 8'd11;
```

→ 相位 256 回绕，但**一个回绕里三角波走 3/5/7/11 个整周期**。因此：

| 通道 | 相位步进 | 三角频率 |
|---|---|---|
| ch0 | 3 | 26e6 × 3/256 = **304.7 kHz** |
| ch1 | 5 | 26e6 × 5/256 = **507.8 kHz** |
| ch2 | 7 | 26e6 × 7/256 = **710.9 kHz** |
| ch3 | 11 | 26e6 × 11/256 = **1117.2 kHz** |

**该更正有实质影响**：定稿 §7 的滤波 A/B 标定讨论建立在"谐波在通带内"的假设上，
而 305–1117 kHz 是否落在 `pd_filter_0` 通带内需重新核对（与本次验证无关，但要在标定前确认）。

### 12.2 波形模型（全部由 RTL 推出，非经验值）

```

ch1 = 2056 + (tri >>> 2) + pulse(n, 195000)
ch2 = 2038 + (tri >>> 1) + pulse(n, 325000)
ch3 = 2062 + (tri >>> 2) + pulse(n, 455000)
pulse(n,c) = 720 / 600 / 460 / 300 于 n = c, c+1, c+2, c+3；其余 0
```
