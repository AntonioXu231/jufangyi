## 1 · 从零打开并构建工程

### 1.1 用 GUI 打开
1. 启动 **Vivado 2020.2**。
2. `File → Open Project`，选 `pd_feature_bd_2020_2.xpr`。
3. 在 `Flow Navigator → IP Integrator → Open Block Design` 打开 `pd_feature_bd`。
4. `Generate Block Design`（生成 BD 包装与 `pd_feature_bd_wrapper`）。
5. `Flow → Run Synthesis` → `Run Implementation` → `Generate Bitstream`。

### 1.2 用 Tcl 批处理（推荐，可复现）
工程自带脚本体系，核心两个：
- `scripts/01_baseline_synth.tcl`：只做综合 + 收报告，**不实现、不出 bit**（验证基线用）。
  ```bash
  vivado.bat -mode batch -source scripts/01_baseline_synth.tcl -notrace
  ```
  脚本行为（`01_baseline_synth.tcl:15-48`）：检查 `.xpr` 存在 → `open_project` → `update_compile_order` → 若 synth 未完成则 `reset_run`+`launch_runs synth_1` → 写 `reports/baseline_synth/` 下的时序/资源/DRC。
- `scripts/02_fix_clock_constraint_and_rebuild.tcl`：修复 Clock Wizard 重复主时钟约束后**重新综合+实现+布线**，并校验 PL 时钟确为 **130MHz（周期 7.692ns）**（`02_fix_clock_constraint_and_rebuild.tcl:45-53`）。

其余脚本（按需 source，均含 `Run inside Vivado Tcl console` 注释）：
`03_add_dds_testbench` / `04_restore_v3_axi_address_map`（地址映射恢复，配套 `05_check_v3_post_impl` 收证据）/ `06_enable_onboard_dds_test_mode` / `07_add_ila_pd_stream_debug` / `08_add_iir_notch_filter_bypass` + `08_validate_iir_filter_ooc` / `09_insert_feature_axil_register_slice` + `09_remove_fft_chain` / `10_enable_event_auto_snapshot` / `add_clock_reset_diag_ila`。

> ⚠️ 这些脚本是**迭代补丁**而非一次性构建脚本；第一次拿到工程建议先跑 `01` 看基线，再据需要 source 对应脚本。**不要一次性全 source**——例如 `09_remove_fft_chain` 会移除 FFT 链（与当前默认不符）。

### 1.3 实现基线（实测，非估算）
取自 `pd_feature_bd_wrapper_timing_summary_routed.rpt` 与 `utilization_placed.rpt`：
- 时序：**WNS=0.000ns，TNS=0.000ns，0 个失败端点，98513 总端点**；WHS=0.017ns；结论「All user specified timing constraints are met.」
  - 分时钟：clk_out1（PL 130MHz）WNS=0.000；clk_out2 WNS=33.421（余量极大，未充分约束）；clk_fpga_0 WNS=0.418。
- 资源：Slice LUTs **27965/53200 (52.57%)**；Slice Registers **33524/106400 (31.51%)**；Block RAM Tile **32.5**（RAMB36=28, RAMB18=9）；DSPs **28/220 (12.73%)**。

## 2 · 仿真流程（4 个 testbench）

仿真入口在 `pd_feature_bd_2020_2.srcs/sim_1/new/`。**注意：工程没有顶层（top-level）testbench**，4 个是独立的模块级仿真，各自单独设成 active sim。

### 2.1 如何跑（通用）
Vivado GUI：`Simulate → Run Simulation → Run Behavioral Simulation`，选定对应 `tb_*` 为 top。或 Tcl：
```tcl
set_property top tb_pd_filter_chain [get_filesets sim_1]
launch_simulation
```

### 2.2 四个 testbench 与 PASS/FAIL 标记

#### (a) `tb_pd_filter_chain.v` — 滤波链（影子/APPLY/WSTRB）
- 失败标记（任意一条触发即 `$fatal` 或 `errors++`）：
  - `:73` `FAIL bypass sample data=...`
  - `:87` `FAIL FSTATUS reset=...`
  - `:89` `FAIL bypass mask reset=...`
  - `:93` `FAIL AW-first bypass mask=...`
  - `:96` `FAIL W-first coefficient=...`
  - `:99` `FAIL WSTRB coefficient=...`
  - `:101` `FAIL coefficient dirty=...`
- 通过/失败终结：
  - `:103` `TB_PD_FILTER_CHAIN_PASS`（errors==0）
  - `:104` `TB_PD_FILTER_CHAIN_FAIL errors=%0d`
- **已知缺口**：该 tb **未覆盖「APPLY 后 `coef_dirty` 变 0」**这条路径（见 B09 R-TB-1）。

#### (b) `tb_pd_ddr_slot_mgr.v` — 4 槽管理器
- 失败：`:39` copy dst/len 不符；`:57` slot0 completion；`:60` lock；`:62` release；`:69` 四槽填满；`:74` 满槽拒绝；`:78` 超长拒绝。
- 通过：`:80` `TB_PD_DDR_SLOT_MGR_PASS seq=... drops=...`

#### (c) `tb_pd_snapshot_trigger.v` — 自动快照触发
- 失败：`:45` masked event；`:49` first trigger；`:51` trigger width；`:53` duplicate before resume；`:58` re-arm；`:63` full-slot rejection；`:72` software priority；`:80` counter clear。
- 通过：`:81` `TB_PD_SNAPSHOT_TRIGGER_PASS`

#### (d) `tb_pd_feature_dds.v` — 板载 DDS 事件流
- 终结：`:97` `DDS_TEST_PASS events=... channels=...`（前置 `:95` 无事件或 `:96` 通道不全会 `$fatal`）。
- **已知 bug**：`:71/77/80` 的 `$fwrite` 里用的是字面两字符 `\\n`（`\` 加 `n`），**不是换行符 `\n`**。结果 CSV 头部/每行末尾是字面 `\n` 文本而非换行，Excel 打开会合并成一行（**事实**，不影响 PASS 判定但影响人工查看）。

> 仿真激励：`sim/pd_adc_4ch_26m_40ms.mem` 是 4 通道 26MSPS/40ms 的 MATLAB 生成波形（`generate_pd_adc_waveform.m` 产生）。IIR 系数同目录有 `coef_fs26m.*` / `coef_fs65m.*` / `coef_fs16p25m.*`（`.h` 供 C 包含，`.hex` 供初始化）。

## 3 · 上板流程（Vitis / PS 侧）

### 3.1 导入与构建（依据 `sw/ps_service/README.md`）
1. Vitis 2020.2 → `File → New → Application Project`，选 `ps7_cortexa9_0`（本工程 XSA 为 `pd_feature_bd_wrapper.xsa`）。
2. 把 `sw/ps_service/src/`、`sw/ps_service/tcp/`、`sw/ps_service/include/`、`sw/ps_service/tools/` 加入工程源。
3. 链接 lwIP（TCP 服务依赖）、Xilinx DMA/Cache 库。
4. Build → 生成 `pd_acquisition.elf`。

### 3.2 运行与 TCP 命令
PS 启动后监听 **TCP 6001**（`pd_tcp_service.c:22`）。用 `telnet/nc` 连上后支持（命令见 `pd_tcp_service.c:620-696` `execute_command`）：

| 命令 | 作用 |
|---|---|
| `HELP` | 打印命令清单 |
| `START [n]` | 开始捕获，n=包数限制（0=连续） |
| `STOP` | 请求停止 |
| `STATUS` | 打印 state/packets/events/snaps/ddr/slot/dma/drops/err |
| `CONFIG` | 打印 archive 槽数/步长/默认限制 |
| `SET LIMIT n` | 设每轮包数限制 |
| `SET FFTFS hz` | 设 FFT 采样率（默认 26000000；**65MSPS 需 `SET FFTFS 65000000`**） |
| `RECOVER` | 故障态恢复（清槽、复位 DMA） |
| `CATALOG` | 列出 event/snap 归档窗口 |
| `EVENT n\|SEQ n` / `SNAP n\|SEQ n` | 查询归档记录 |
| `ANALYZE SNAP n` | 对快照做 min/max/mean 分析 |
| `FFT CONFIG\|SELFTEST\|SNAP n [start]\|AUTO SNAP n` | FFT；`FFT SELFTEST` 期望 `FFT_SELFTEST_PASS bins=37/83/151/255 amplitude=1024(+/-tol)`（`pd_tcp_service.c:352-356`） |
| `SPECTRUM [AUTO] SNAP n [start]` | 保存可复现 FFT 结果 |
| `GET EVENT\|SNAP n offset bytes` | 带 CRC32 回传原始数据 |
| `CLEAR` | 清采集与分析元数据（须 idle） |

> 默认快照大小 **3,120,000 字节 = 520000 样本**（4 通道 × 24 字节/样本），默认 26MSPS（README）。

### 3.3 PS 侧关键纪律（缓存一致性，见 B07 知识点 17）
- 搬快照前 `Xil_DCacheInvalidateRange`（`pd_acquisition_core.c:145`）。
- 提交 DMA 前 `FlushRange`+`InvalidateRange`（`pd_acquisition_core.c:169-170`）。
- 归档后 `FlushRange`（`pd_acquisition_core.c:97`）。

## 5 · 三条铁律（改造/复用时必守）

1. **配置参数走「影子 + APPLY」，绝不直写生效寄存器。**（`pd_filter_chain.v:85-97`）半新半旧系数会产生假脉冲。改完必须发 APPLY 并确认 `coef_dirty` 回 0。
2. **AXI-Stream 的 valid 在握手上必须保持，且 valid 不能由 ready 组合产生。**（`pd_ddr_snap_copy.v:174-176`）跨域/反压踩过坑。
3. **PS 与 PL 共享 DDR 必须管缓存：DMA 写→PS 读前 Invalidate；PS 写→DMA 读前 Flush。**（`pd_acquisition_core.c:145/169-170/97`）否则「时好时坏」。

## 6 · `pd_feature_core` phase / stat 语义速查

### 6.1 事件包 layout（8 字节）—— ⭐ **以拼接表达式为准，不要用源码注释**
> ⚠️ `pd_feature_core.v:552-561` 的注释是 **`PH_FIELD_W = 10` 时代**的位位置（`[39:30]`/`[29]`/`[28:27]`/`[26:0]`），而 `pd_defines.vh:36` 当前是 **12** → **按注释解析会整体错位 2 位**。下表由拼接表达式（`:562-567` / `:577-578`）推导，并已用 `tb_pd_feature_dds.v:76-78` 交叉验证。

**峰值事件包（`type = 0x00`）**
| 位段 | 宽 | 含义 |
|---|---|---|
| `[63:56]` | 8 | type = 0x00（周期统计包为 0x01，且 `tlast=1`） |
| `[55:40]` | 16 | q：Q8.8 有符号补码（pC） |
| `[39:28]` | 12 | phase：相位窗号（宽度 = `PD_PH_FIELD_W`） |
| `[27]` | 1 | polarity：**0 = 负、1 = 正**（内部 `q0_pol_r` 恰好相反，故拼接时写 `~q0_pol_r`） |
| `[26:25]` | 2 | ⭐ **ch_id（峰值包）** |
| `[24:0]` | 25 | evt_seq：每通道自增事件序号（用于 PS 丢帧检测） |

**周期统计包（`type = 0x01`，帧尾 `tlast = 1`）**
| 位段 | 宽 | 含义 |
|---|---|---|
| `[63:56]` | 8 | type = 0x01 |
| `[55:32]` | 24 | cycle_idx：周期序号（`phase + cycle_idx` 可还原绝对时间） |
| `[31:30]` | 2 | ⭐ **ch_id（周期包，位置与峰值包不同！）** |
| `[29:16]` | 14 | cyc_n：本周期放电次数（⚠️ 14 位，> 16383 会回绕） |
| `[15:0]` | 16 | cyc_qmax：本周期最大电荷量 |

> ⭐ **两条关键提醒**：① 峰值包 `ch_id` 在 `[26:25]`、周期包在 `[31:30]` → **下游必须先读 `type` 才能定位 `ch_id`**；② 位宽恒等式 `8+16+PH_FIELD_W+1+2+(37−PH_FIELD_W) = 64` 必须成立（改 `PD_PH_FIELD_W` 会移动所有字段）。

### 6.2 统计寄存器语义（`pd_feature_core.v:85-96` 端口）
| 信号 | 含义 |
|---|---|
| `st_sn_n` | 快照：放电脉冲计数 n |
| `st_sn_qmax` | 快照：最大视在电荷量 Q(pC) |
| `st_sn_sum_abs_q` | 快照：Σ\|q\| → I = Σ\|q\|/T |
| `st_sn_sum_qu` | 快照：Σq·u → P = Σq·u/T |
| `st_live_cycles` | 自清零以来累积周期数 |
| `st_frame_n_pos` / `st_frame_n_neg` | 本帧正/负脉冲计数 |
| `st_frame_ad_max` / `st_frame_ad_min` | 本帧 ADC 码包络极值（无样本时输出 0，`:860-863`） |
| `st_frame_id` | 帧序号 |
| `st_frame_stat[0]` | frame_valid（新帧就绪）；由 `cfg_frame_ack` 清（`:629`） |
| `st_frame_stat[1]` | overflow（上一帧未读即被覆盖）；由 `cfg_frame_ovf_ack` 清（`:630`） |

### 6.3 模式相关
- `PD_MODE_ABSMAX=0`（默认）：窗口内绝对值最大。
- `PD_MODE_PP=1`：峰峰值 `q_pp`，**恒为正**（`:383`）。
- `PD_MODE_POSNEG=2`：`q0_code = h_max` 且 `q0_pol = POS`（`:368`），即正峰硬取最大；`stat_q1_pol` 在 S_ACC 赋值 `q1_pol_r`（`:747`）并于 `:797` 用于正负计数。

## 7 · 最小复用检查清单

复用本工程到新板/新项目前，逐条确认：
- [ ] 器件一致：`.xpr` 的实际 `xc7z020clg400-2` vs 目标板封装（B09 R-DEV-1）。
- [ ] 时钟：PL 130MHz、ADC 26MHz；若换采样率，4 处（sys_top / dds_source / PS FFTFS / hw_map）同步改。
- [ ] DDR 地址：`pd_ddr_defines.vh` 基址/大小与目标板 PS-PL 地址映射一致。
- [ ] 事件包 layout：下游解析**先读 `type`**，再按包型取 `ch_id`（峰值 `[26:25]` / 周期 `[31:30]`），**不要照源码注释写**（见 §6.1）。
- [ ] ⭐ **`pd_iir_biquad` 的前置条件**：`dv` 间隔必须 **≥ 5 拍**（否则 `phase` 永久锁在 1、`dout_dv` 恒 0，静默失效）。26 MSPS 下满足；**65 MSPS 直连不满足 → 必须先做 CIC 抽取降速**（见 `B09` R-2）。
- [ ] 缓存管理：PS 侧 Invalidate/Flush 三处不可省。
- [ ] 仿真：4 个 tb 全部 PASS；注意 DDS tb 的 `\\n` 仅影响 CSV 可读性、不影响判定。
- [ ] 时序：实现后确认 WNS≥0（基线 0.000，刚好收敛，留余量小）。
- [ ] 配置入口：所有调参走影子+APPLY，确认 `coef_dirty` 回 0。
