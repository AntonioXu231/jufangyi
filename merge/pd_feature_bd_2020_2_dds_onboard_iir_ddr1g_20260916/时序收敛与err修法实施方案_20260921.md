## 二、关键路径解剖（19 级逻辑，布线占 54.9%）

报告原文（`Slack (VIOLATED) : -0.054ns`）：

```
Source      : pd_feature_bd_i/pd_ddr_0/inst/u_ddr/u_ring/wr_off_reg[0]/C
Destination : pd_feature_bd_i/pd_ddr_0/inst/u_ddr/u_ring/ring_remain_r_reg[1]/CE
Requirement : 7.693 ns
Data Path   : 7.433 ns  (logic 3.354 / route 4.079)，Logic Levels = 19
              (CARRY4=11  LUT1=1  LUT2=1  LUT3=1  LUT5=2  LUT6=3)
```

逐段展开（netlist 资源名）：

1. `wr_off_reg[0]/Q` → `ring_remain_r[4]_i_2`（LUT1）
2. → **`ring_remain_r_reg[4..31]_i_1` 共 11 级 CARRY4**：即 `RING_SIZE − wr_off` 这条 **32 位减法**
3. → `ring_remain[29]` → `seg_len_r[10]_i_5`（LUT2）→ `seg_len_r[10]_i_2`（LUT6）→ `seg_len_r[8]_i_3`（LUT3）
   即 `normal_seg_len / commit_seg_len` 的比较与选择
4. → `FSM_sequential_o_state_i_65 / _reg_i_43 / _i_29 / _i_19 / o_state1 / _i_7 / _i_3`（≈7 级）
   即状态机的下一状态 / 进位链
5. → `ring_remain_r[31]_i_1`（LUT6，扇出 95 → `seg_len_r`）
6. → `ring_remain_r_reg[1]/CE`

**根因（一句话）：`ring_remain = RING_SIZE − wr_off` 是纯组合逻辑，却和"比较 + 选择 + 状态机下一状态"挤在同一拍，直接驱动 `ring_remain_r` 的时钟使能。32 位减法被综合成 11 级 CARRY4，占了整条链的大头。**

源码落点（`pd_ddr_ring_wr.v`）：

```verilog
198:  wire [31:0] ring_remain    = RING_SIZE - wr_off;                 // ← 组合减法，链头
199:  wire [31:0] normal_seg_len = (ring_remain >= BURST_BYTES) ? BURST_BYTES : ring_remain;
203:  wire [31:0] commit_seg_len = (ring_remain >= commit_cap_len) ? commit_cap_len : ring_remain;
285:  end else if (!freeze_commit_wait && i_acq_en &&
286:               (normal_seg_len != 0) &&
287:               (avail_bytes >= normal_seg_len[AVAIL_W-1:0])) begin   // ← 条件进 CE
290:      ring_remain_r <= ring_remain;                                  // ← 目的寄存器的 D
```

## 三、修法

### 阶段 1（零 RTL 改动，且发布门禁本就要求）：移除 dbg_hub / ILA 后重跑实现

- 现状：当前 bit 含调试核（`dbg_hub` + `ila_0`，`C_NUM_OF_PROBES=9`，在树的实现里有 1,311 处引用）。
- 依据：发布门禁明确要求 **移除 dbg_hub/ILA**；同时该路径布线占 54.9%，撤掉调试核可显著降低局部拥塞与布线延迟，对 −0.054 ns 这种"零头"失配通常即可收敛。
- 操作（用户在 Vivado 侧执行）：
  1. 在 Block Design 中删除 `ila_0` 实例（连同其与 `pd_feature_0_m_axis` / `axi_dma_0` 的 SLOT 连接）；
  2. `Generate Output Products` → `Reset Output Products` 后 `Generate`；
  3. `Reset Synthesis Runs` + `Reset Implementation Runs` → 重新 `Run Synthesis` → `Run Implementation`；
  4. 复测：`report_timing_summary`。
- 通过判据：WNS ≥ 0 且 TNS = 0。

> 注意：这一步会暂时失去 ILA 观测能力。若本轮还需要 ILA 现场调试，先做阶段 3 的可观测性补丁（把错误位引到 AXI-Lite 0xA4），再撤 ILA。

### 阶段 2（RTL，确定性修法）：把 `ring_remain` 寄存器化，打断长链

**改动点（`pd_ddr_ring_wr.v`，仅 3 处）：**

1. 段 1 内部寄存器声明处（现第 165–170 行一带）新增：

```verilog
reg [31:0] ring_remain_q;   // RING_SIZE - wr_off 的寄存版本，供 FSM 决策使用
```

2. 主状态机的时序块内（`else begin` 段，与 `o_wr_off <= wr_off;` 同处，约第 322 行附近）新增连续寄存：

```verilog
ring_remain_q <= RING_SIZE - wr_off;   // 减法只有 reg→组合→reg，一拍裕量充足
```

3. 复位分支（约第 240 行 `ring_remain_r <= RING_SIZE;` 同级）新增：

```verilog
ring_remain_q <= RING_SIZE;
```

4. 组合段（现第 198 行）改为使用寄存值：

```verilog
wire [31:0] ring_remain = ring_remain_q;    // 原：RING_SIZE - wr_off
```

**为什么安全（时序语义不变）：**

- `wr_off` 只在 `cmd_fire` 那一拍变化；变化后 `ring_remain_q` 于次拍更新。
- 两次命令之间需要攒够 1536 B 信用（`avail_bytes >= 1536`，8 B/拍 ⇒ 约 192 拍），远大于 1 拍的寄存器延迟，`ring_remain_q` 在下一次决策前早已稳定。
- 回绕判定仍用命令时刻锁存的 `ring_remain_r`，语义不变。
- 冻结尾量路径（`commit_seg_len`）同样只是把输入从组合减法换成寄存减法，决策时刻仍是"攒够则发"，不受影响。

**预期效果：** 关键路径由 `reg → 11×CARRY4 → 比较/选择 → FSM → CE` 缩为
`reg(ring_remain_q) → 比较/选择 → FSM → CE`，链头 11 级 CARRY4 被移出一拍外，depth 从 19 降到约 8，裕量应转为正。

**可选的次生项：** 第 324 行 `o_blk_idx <= wr_off / BLK_BYTES;`（÷24）在综合里会展开为乘加链。但顶层 `.o_blk_idx()` 悬空（`pd_ddr_wr_top.v:442`），会被优化掉，**本轮不必动**；若后续要接出来，改成"块计数寄存器递增"而非实时除法。

### 阶段 3（实现策略兜底，不改功能）

若阶段 1+2 后仍有零星负数：把实现的综合/实现 directive 提到性能档——
`synth_design -directive PerformanceOptimized` 与 `phys_opt_design -directive AggressiveExplore`，
**不要**用 `set_max_delay` / `set_false_path` 去"抹"这条路径（属于掩盖错误，违反本项目原则）。

## 四、DDR_STATUS[5] 一次性启动瞬态误报 · 修法（与时序并行）

### 4.1 现象与定性

上板实测：首轮冻结即置位 `err`（`DDR_STATUS[5]`），但进度探针显示数据通路完全正常——
每命令精确 1536 B、两段区间复现、清零后约 45 ms 不复现、采集前 `AVAIL` 已堆到 4144（> 溢出阈值 3072）。
结论：**不是 datapath 错误，而是采集关闭期的上游溢出声被 `ring_ovf` 记成了"错误"。**

### 4.2 机理（源码取证）

- `i_err = ring_err | ring_ovf | copy_err | snapshot_cfg_err`（`pd_ddr_wr_top.v:743`）；实测 bit8/9 = 0 ⇒ 只能是 `ring_err | ring_ovf`。
- `beat_en`（`:341`）与 `up_ovf`（`:413-414`）**都不受 `acq_en` 门控**：`acq_en=0` 期间上游仍在灌数，
  `avail_bytes` 一路堆高（实测 4144 ≥ OVF_THRESH 3072，`hiwm=1`）。
- `pd_ddr_ring_wr.v:429` 的 `if (i_freeze_resume || !i_acq_en) o_err <= 1'b0;` 是**优先分支**，把 err 强制清零；
  于是 `acq_en=0` 期间"看起来干净"，`acq_en=1` 那一拍 `else-if` 立刻生效 ⇒ err 一次性置位。

### 4.3 修法（二选一，推荐 ①）

**① 在顶层用 `acq_en` 门控上游事件（改动最小、语义最直白）**
`pd_ddr_wr_top.v`：

```verilog
341:  .o_beat_en (beat_en),              →  改为  .o_beat_en (beat_en_gated),
413:  wire up_ovf = (s48_a_valid & (fifo_full | fifo_wr_busy)) |
                   (s48_b_valid & (feat_fifo_full | feat_fifo_wr_busy));
      新增：wire beat_en_gated = acq_en & beat_en;
            wire up_ovf_gated  = acq_en & up_ovf;     // 并把 u_ring 的 .i_up_ovf 接 up_ovf_gated
```
即 `acq_en=0` 时 `pd_ddr_ring_wr` 既不计信用、也不记上游溢出，从源头消除启动瞬态。

**② 在 `pd_ddr_ring_wr.v` 内清信用（备选）**
在 `acq_en` 上升沿清 `avail_bytes`（增加 `acq_en_d` 打拍做边沿检测），使能瞬间信用从 0 起算。

> 注意：修法 ① 会改变 `avail_bytes` 的累计语义（关闭期不再累加）。请确认 PS 侧不依赖"关闭期信用值"这一读数（当前 PS 只读它做健康判据，不依赖历史累计），确认后再改。

### 4.4 可观测性补丁（把二义性彻底消掉）

- `dbg_ddr` 在 RTL 里已算好（`pd_ddr_wr_top.v:782-791`，含 `ring_err[9]`、`skew_err[7]`、`copy_err[8]`），
  但 `.bd` 中**只有端口声明、无网络连接** ⇒ 被优化掉、不可观测。
- 把 `dbg_ddr[9]`（`ring_err`）与 `dbg_ddr[5]`（`ring_ovf`）接到 AXI-Lite 表空闲偏移
  **`0xA4` / `0xA8`**（表止于 `0xA0`），即可让 PS **零逻辑开销**地区分"真 ring_err"与"启动瞬态 ring_ovf"。
- 顺带把悬空的 `o_last_btt` 也引到 `0xA8` 之后的空闲偏移，给错误一个可归因的现场。

## 五、执行步骤与通过判据（用户在 Vivado / 板侧操作）

1. **（零 RTL）** 移除 `ila_0` → 重生成 → 重综合 → 重实现 → `report_timing_summary`。
2. 若 WNS < 0：**（RTL）** 按 §3 阶段 2 改 `pd_ddr_ring_wr.v`（3 处），重综合重实现，再测。
3. 仍不足：上性能 directive（§3 阶段 3），再测。
4. 并行：按 §4.3 打 err 修法 + §4.4 可观测性，重编 ELF，上板复测 `DDR_STATUS` 与 `0xA4`。

**发布门禁判据（全过才算收敛）：**
- `Place 30-487` = 0
- WNS ≥ 0 且 TNS = 0
- WHS ≥ 0 且 THS = 0
- 无阻断级 DRC
- 最终发布 bit **不含** `dbg_hub` / ILA

## 七、风险与不做什么

- **不做**：`set_max_delay` / `set_false_path` 掩盖该路径；加 `-no_debug_cores` 之类"绕过"手段。
- **风险**：阶段 2 的寄存器化会让 `ring_remain` 滞后一拍。已在 §3 论证语义不变，但**必须在仿真里回归**
  （边界：`wr_off` 恰好使 `ring_remain` 跨 1536 的临界拍、回绕前后各一拍）后再上板。
- **前置**：`err` 修法 ① 会改变关闭期信用累计，改前先与 PS 侧确认无依赖。
