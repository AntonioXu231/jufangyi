# 局放采集 Qt 6 上位机（实时示波器 + 360° 相位环）

直接面向当前板端 PS TCP 服务的 Qt 6 Widgets 桌面工程。

**核心工作方式**：常态下上位机就是一台示波器——四通道波形与四通道 360° 相位环
**同时持续刷新**；只有需要看连续细节时，才按下"暂停并抓取快照"，把板端切到 IDLE
下载一份快照，看完再一键恢复取帧。

**连上就自动开始**：「连接后自动取帧」默认勾选，连接后自动走
`STATUS →（必要时 START 0）→ SCOPE ON → 持续取帧`，日志会写明实际发送了什么。
不想要这个行为就取消勾选。

## 两种模式

### 常态：示波器模式（波形 + 相位环一起刷新）

| 显示 | 数据来源 | 板端约束 |
|---|---|---|
| 四通道波形 | `SCOPE NEXT` 循环取帧；含峰值事件后请求 `SCOPE EVENT SEQ record samples channel evt_seq` 候选相位窗口 | 需采集运行中；单帧 256..2048 点；快照与事件周期关联仍不精确 |
| 四通道 360° 相位环 | `GET EVENT SEQ n …` 读事件归档 | **采集运行中板端明确允许** |

板端源码原话（`ps_service/tcp/pd_tcp_service.c` 的 `start_get`）：

```c
/* EVENT is a compact archived record and may be read during START 0 for
   live PRPD display.  SNAP remains IDLE-only because it is multi-chunk. */
```

所以"波形持续更新 + 相位环持续更新"是板端设计支持的用法，**不是**在偷偷轮询快照。

两者的相位来源是 **PL 的 12-bit 相位字段**（事件包 bits 39:28），幅值是 Q8.8 原始码
（未标定，界面标注 raw，不代表 pC）。

**链路仲裁与事件排空**：板端同一时刻只允许一个二进制传输，因此取帧与事件包下载交替。
Qt 默认每 100 ms 发起一轮（可调，最小 100 ms）；每轮最多按序处理 32 条，从 PS 当前保留区
最旧的未处理序号向最新序号前进。轮次开始时先收完在途 SCOPE 帧，然后暂停发起新帧，
顺序读取 `CATALOG` / `EVENT SEQ` / 必要的 `GET EVENT`，批次结束恢复取帧。空事件记录
（`peaks=0`）跳过二进制下载，但仍推进序号游标。每批至多请求一个事件波形候选，优先留带宽
给事件归档排空。失败的下载或解码不推进游标，下轮重试；若 PS 环形归档已覆盖未读序号，
Qt 累计并显示明确 gap，而不是静默跳过。每轮摘要显示处理条数、游标、待处理 backlog、
覆盖缺口和耗时。

批次上限和轮询间隔是吞吐调度参数，不等于已证明无损。PS 归档为 2048 槽；必须在目标板
测量事件产生速率、每轮耗时、backlog 与 gap。若持续 backlog 增长或 gap 增长，当前板端
产出速率仍高于 Qt 可消费速率，需要调整网络/批次调度或在 PS 侧缓存/推送，而不能把
15 秒椭圆显示保留时间误当成无损归档保证。

**显示缓冲**：椭圆图与 PRPD 点图按 50 ms 合并刷新，减少突发事件时重复重建绘图缓存；默认保留最近 15 秒（按 Qt 收到事件包的时间计，不是 PL 的采样时间戳），每个通道另设 1,000,000 点容量上限。达到容量上限时控件仍会淘汰最旧点；目标板长时间运行应观察各面板点数和 Qt 内存。

**归档冻结时不再空转**：连续两次 `CATALOG` 窗口不变即判定归档冻结（采集已停或无新事件），
在无未处理 backlog 的情况下，连续两次 `CATALOG` 窗口不变才退避 3 s；有 backlog 时不退避，
避免把未读事件误判为冻结。

**相位直方图不再"点了没数据"**：`PRPD BINS` 需要板端 IDLE，而取帧意味着 RUNNING。
现在点它若正在取帧，会自动停取帧 → `STOP` → 轮询到 IDLE → 自动发查询。

### 按需：暂停抓快照

按「暂停并抓取快照」后，程序自动完成：

1. 停止取帧（发 `SCOPE OFF`）；
2. `STOP` 让板端回到 IDLE —— **板端 `GET SNAP` 在多段下载期间强制要求 IDLE**；
3. `CATALOG` 取 `snap_seq=[first,next)`，选最新一份 `next-1`；
4. 按 16 KiB 分段 `GET SNAP SEQ n …` 下载并逐段 CRC32 校验；
5. 载入「归档记录波形」页签（520,000 点 = 20 ms 连续记录，横轴完全可信）。

抓完之后板端处于 IDLE，此时 `ANALYZE` / `FFT SNAP` / `PRPD BINS` 都可以直接跑。
点「恢复取帧」自动 `START 0` + `SCOPE ON` 回到示波器模式。

每个阶段都有 10 s 超时（下载阶段按"有无分段进展"判定），超时明确报错退出，不无限等待。

## 页签结构

| 页签 | 内容 |
|---|---|
| **示波器：波形 + 椭圆图谱** | 上=四通道波形（含 PD 脉冲标注，可缩放/游标/触发），下=1×4 椭圆图谱（可缩放），两者同时常时刷新 |
| **PRPD 散点（相位-幅值）** | 2×2 标准 PRPD 直角坐标，与椭圆图同一批事件 |
| 归档记录波形（暂停抓取） | 暂停抓取的快照，横轴为连续时间 |
| 单通道实时页 | 从最近的 `SCOPE` 帧选择一个通道，PS 执行 Hann/去直流 1024 点 FFT，Qt 校验 CRC 后只绘制 513 个单边幅值码；静态全周期快照的 FFT bins 仍未接入 PS 接口。 |
| PRPD 相位直方图 | `PRPD BINS` 64 桶（**需要 IDLE**，先暂停抓快照再读） |

> **不要把"滚动"波形模式当成连续时间轴。** 板端 `SCOPE` 每次只推送 DDR 环上
> "距写指针 24 KiB 之前"的一个窗口，两次取帧之间写指针已前进约 25 个窗口宽度
> （定量分析见工程目录下 `上位机实时示波器_设计与验证_20260923.md`）。
> 因此滚动模式横轴是**到达样本序号**，界面已明确标注。要连续时间轴请用暂停抓快照。

## 图谱控件的交互与呈现

**椭圆图谱**（示波器页下半）：滚轮以鼠标为锚点缩放、`Ctrl+滚轮` 只缩幅度轴、
左键拖拽平移、双击复位、单击脉冲选中（与波形联动）。详见下面「椭圆图谱与 PD 脉冲标注」。

**PRPD 散点**：标准直角坐标（横轴相位 0..360°，纵轴幅值）。背景点以密度网格绘制，
超过高亮阈值的点用亮色真实几何绘制；最新到达的点用白色描边突出。

两者共用同一批峰值事件与同一个上位机绝对阈值口径，互为印证。实时波形还会
额外取 `max(绝对阈值, 6×sigma)` 抑制噪声；事件归档没有该帧的噪声统计，因而
按绝对阈值筛选。注意阈值职责分层：
PL 的 `cfg_thresh` 只负责产生候选事件、保护硬件吞吐；现场可调的“检测阈值”
在 Qt 上位机执行，不下发 PL。`CONFIG` 回传四路实际 `SCALE(Q8.8)`；四路相同时 Qt
自动同步公共换算系数，若通道间不同则明确告警（当前该控件是公共值，不能表达四路不同标定）。
上位机收到事件归档后按 `abs(event.adcCodes)` 筛选椭圆点、PRPD 点和事件波形请求，
因此调节阈值不会重配置 PL，也不会改变
原始事件序号/丢帧统计。

- **时间老化**：只保留最近 N 秒（默认 10 s，可调 2..120 s）内的事件，按新近程度决定亮度
  ——形成"正在刷新"的观感，而不是无限堆积的点云。
- 每个面板的标题栏显示：通道徽章、当前幅值（pC 或 AD 码）、频带标签。
- 底部行显示：高亮阈值、点数、已确认数、标定状态、数据来源（事件 seq / 等待状态）。
- 每次事件回合的日志会写明"接收多少点、绘制多少点、各通道分布"——抽样不静默吃掉信息。

## 波形模式

- **实时**：每帧都刷新，横轴 = 单帧时基（1024 点 = 39.38 µs @ 26 MSPS）。
- **触发**：只在帧内找到满足"通道 + 边沿 + 电平 + 迟滞"的触发点时才刷新；无触发帧保持
  上一幅（示波器 Hold 行为）。勾选"触发对齐"后把触发点固定在视图的预触发比例位置。
  > SCOPE 协议返回固定窗口，没有硬件预/后触发控制，所以这里是**帧内判定 + 保持**。
- **滚动**：连续帧按到达顺序拼接进环形缓冲，横轴为到达序号。

## 首次联调顺序

1. 电脑有线网卡 `192.168.1.6/24`，板端 `192.168.1.10:6001`。
2. 点"连接"，日志应出现 `PD_ACQ TCP PS-2 READY`。
3. 点 `CONFIG`，**确认回复含 `scope=` 字段**。没有这个字段说明板端 ELF 不支持 SCOPE，
   必须先更新固件（见上一节），否则波形永远不会出现。
4. 点**"开始取帧"**（「连接后自动取帧」默认已勾选，连上就会自动走一遍）。
   板端若为 IDLE，程序会自动 `START 0`，随后自动 `SCOPE ON`。
5. 左侧波形应持续刷新，状态栏滚动显示 `SCOPE V1 seq=... fs=...`，统计行显示帧率。
6. 右侧四个相位环开始出现脉冲点（每 20 ms 工频周期每通道一个），工具行显示累计点数。
7. 调"时基"改变窗口长度（256..2048，4 的倍数）；切"触发"模式并选 CH0 / 上升沿 /
   电平约 2400（DDS 的 CH0 脉冲顶点可达 2769），应只在含脉冲的帧刷新。
8. 想看连续波形时点**"暂停并抓取快照"**：板端回 IDLE，自动下载最新快照并载入
   "归档记录波形"；此时也可跑 `ANALYZE SNAP 0`、`FFT SNAP 0`、`PRPD BINS`。
9. 点**"恢复取帧"**回到示波器模式（已抓到的快照保留在归档，不受影响）。
10. 需要留档时点"导出 CSV"（滚动模式会在文件头写明横轴不是时间）或"导出 PNG"。

## 已知限制

- SCOPE 帧头里 `fs=26000000` 是板端写死的（`pd_tcp_service.c` 的 `start_scope_frame`）。
  将来切 65 MSPS 必须同步改板端这一处，否则上位机时间轴错 2.5 倍。
- 滚动模式横轴不代表时间（原因见上）。
- 触发是帧内判定，不能跨帧边界。
- 相位环的相位字段位移/位宽（bits 39:28，12 位）**只在上位机里有唯一定义**
  （`pd_sample_codec.h` 的 `eventpacket` 命名空间）：PS 的 `pd_event_decode.c` 没有取
  相位字段，两端无法互相纠错。若 PL 的相位字段改为 10 位，必须同步改这里与 PRPD 桶映射。
- 未做 UDP 推送与多板并发；当前只支持一板一连接。

## ⛔ 首要待办：板端 ELF 必须支持 SCOPE 命令

2026-09-23 上板实测：**当前烧写的 ELF 没有 `SCOPE` 命令**，因此实时波形永远不会出现。

证据（一条命令两次独立复现）：

```text
[scope] 采集运行中，发送 SCOPE ON 1024。
<< ERR unknown command; type HELP          ← SCOPE ON 被拒
...
>> STOP
<< ERR unknown command; type HELP          ← 停取帧时发的 SCOPE OFF 也被拒
<< OK stop requested
```

**处置**：用当前 `sw/ps_service/` 重新编译应用并下载 ELF（该目录的 TCP 前端实现了
`SCOPE ON|NEXT|OFF`）。在此之前的现象是：相位环能出数据（走 EVENT 归档路径），
但四通道波形一直显示"等待数据"。

上位机已加入**固件能力探测**：开始取帧时先发 `CONFIG`，若回复里没有 `scope=` 字段，
立即进入故障态并明确提示"板端固件不支持 SCOPE 命令，请更新 ELF"——
不再像以前那样把 `unknown command` 静默吞掉、让你只看到"没数据"。

## 椭圆图谱与 PD 脉冲标注（2026-09-23 新增）

**「示波器：波形 + 椭圆图谱」页**：上半是四通道波形，下半是四个椭圆图谱（CH1 黄 / CH2 青 /
CH3 红 / CH4 品红，照参考图配色），由同一批峰值事件驱动、同时刷新。

### 椭圆图谱是什么

椭圆不是装饰，它是**工频相位刻度盘**：`x(θ) = cx + Rx·sin θ`，`y(θ) = cy − Ry·cos θ`。
一个发生在相位 θ 的脉冲就画在该 x 处的竖直对称线上，线长跨过椭圆上下边界
`cy ± Ry·|cos θ|` 再向两端各伸出与幅值成正比的长度。

这也正好解释参考图里"**竖线中间长、两端短**"的形态：`|cos θ|` 在 θ=0/180（中轴）为 1、
在 θ=90/270（椭圆两端）为 0。

相位对应关系用三样东西显式表达：每 30° 一个径向刻度、四象限标 `0°/90°/180°/270°`、
选中脉冲时从圆心到该相位点画径向线 + 白点。

### PD 脉冲标注

判据两条，取较严格者，界面上都显示（不做黑盒）：

- **上位机用户绝对阈值**（默认 120 AD 码）：PD 脉冲增量是 +720/+600/+460/+300 码，
  而 DDS 背景相对 2048 的最大偏离只有 42 码，120 码能干净挡开背景；
- **自适应阈值 6×sigma**，`sigma = 1.4826×MAD`。用 MAD 而不是标准差，
  因为标准差会被脉冲本身抬高；基线用**中位数**而不是均值。

波形上画竖直标线与极性三角标记（正向上、负向下），超过高亮阈值的用亮色 + 端点圆；
椭圆图上同源同色。单击脉冲可选中并显示幅值/极性/时间读数。PL 事件归档先
经过同一个上位机阈值筛选；界面状态栏分别显示“PL 候选/主机通过/筛掉”计数。

⚠️ **联动边界**：PL 事件包没有携带 DDR 字节地址，而快照按完整工频周期冻结；现在 PS 新增
`SCOPE EVENT SEQ record_seq samples channel evt_seq`，先在 PL 事件记录里精确选中指定通道和事件字，再按该字相位在最新完整快照中提取候选窗口，用 `SCOPE V2` 传给 Qt。当前快照记录没有事件周期/样本时间戳关联字段，所以这只是相位近似定位，不保证窗口内包含该 `evt_seq` 的同一个瞬态脉冲；不可作为严格同步波形证据。
因此波形与椭圆点共享同一个 PL 事件序号和相位映射；若快照在事件之后轮转，仍可能相差数个工频周期，
帧头会公开 `snap_seq/event_seq/start/center/phase` 供诊断，不能把它当作硬件级逐采样时间戳。

另外，波形上算不出工频相位（没有 sync 信号），所以**相位只在椭圆图上给出**。

### 单位与标定

事件包幅度字段是 **Q8.8 视在电荷量**：`q = sat16(AD码 × SCALE) >>> 8`，SCALE 上电默认 256（=1.0）。
所以：

- 默认标定下 **`q` 的原始数值就是该脉冲的 AD 码幅度**（这正是两边能按幅值互相印证的原因）；
- `pC = q / 256`，但**这不是真实标定**——界面会明写"pC 未标定(SCALE=1.0)"；
- 界面上可填公共 `SCALE` 与切换纵轴单位（pC / AD 码）。板端 `CONFIG` 现在回传四路实际值；相同则 Qt 自动同步，不同则告警并保留手动值。当前单个控件不能表达四通道不同标定。

## 多线程：为什么以前容易卡死

卡死在 GUI 线程做重活，不在网络。四处热点及量级：

| 位置 | 做的事 | 量级 |
|---|---|---|
| `PrpdPanel::paintEvent` | 每次重绘遍历全部点求峰值，再对**每个点**调 cos/sin、构造 QPen、`drawPoint` | 2 万点 ×(2 三角函数 + 画笔 + 逐点绘制) |
| `ScopeWidget::drawTraces` | 每次重绘重算 min/max 包络抽稀 | 520,000 点 ×4 = **208 万次比较** |
| `loadSnapshotPlots` | 读 3.12 MB → 解 200 万个 double → 统计 → 4 次 FFT，全在事件循环里 | 一次阻塞数百毫秒（**"暂停抓取后卡死"的直接原因**） |
| 日志逐条 `appendPlainText` | SCOPE 帧 20 ms 一条、下载 190 条 DATA 头 | 持续争抢 GUI 线程 |

**现在的架构**：

```
GUI 线程：只绘制与交互
  ├─ 渲染节流：30 ms 内多次 update() 合并成一次重绘
  └─ 日志合并：120 ms 合并追加一次（上限 2000 条，超出只计数不排队）

PdAnalysisWorker（常驻工作线程）
  解码 / 统计 / FFT / 脉冲检测 / 大文件 IO → **成品**经 queued 信号回传
  波形帧用 QSharedPointer 传递（零拷贝，避免 16.7 MB 深拷贝）
```

两个明确的取舍：

- **TCP 套接字留在 GUI 线程**：它是异步的、本身不阻塞；真正的开销在解码与统计。
  搬走计算即可达到目的，而套接字留下能让所有命令调用保持同步、改动面小得多。
- **实时帧的脉冲检测留在 GUI 线程**：一帧只有 1024 点，检测约万次整数运算，
  跨线程往返的成本比计算本身还高。只有 520,000 点的静态记录才交给工作线程。

渲染侧另做了三件事：包络抽稀结果按 (数据版本, 视图窗口, 像素列数) **缓存**（重绘从
O(样本数) 降到 O(像素列数)）；相位→sin/cos 改 **4096 项查表**（热循环里没有三角函数）；
两个图谱控件的背景点改**密度网格**，只有"已确认脉冲"走精细几何且设上限。

## 界面布局（已按 1280×720 级别适配）

实测发现控制区的 11 列网格把窗口**最小尺寸硬撑到 1550×869**，在 1280×720 级别的屏上
放不下——相位环被切、日志被挤出屏幕。

已改为：

- 控制区与相位环工具栏放进 `QScrollArea`（不再参与撑宽窗口）；
- 主区改为**可拖动的纵向分区**（页签视图 | 日志）；
- 采集/归档/手动命令三个框移入独立页签「命令与归档」；
- 全局深色底色（此前滚动区回落到系统浅色主题，中间会有一条白带）；
- 波形控件最小高度 160、椭圆面板最小 230×118；
- 状态读数与统计从控制网格移到底部常显行（它们是"读数"不是"控件"，
  占一整行会把脉冲控件挤出可视区）。

⚠️ 实测：`QLabel` 在 `wordWrap=false` 时 `minimumSizeHint` 等于整行文字宽度，
放在滚动区之外会**把窗口最小宽度顶到 1668 px**——所以底部那几个长文本标签必须开换行
并给一个很小的最小宽度。

现在窗口最小可到 **1024×700**。

## 上板已知现象（2026-09-23 实抓，现行阈值分层）

实测相位环落点严重偏斜：**CH2 有 14336 点，CH0/CH1 各 14 点，CH3 仅 2 点**。根因在板端门限：

- `pd_axil_regs.v` 上电默认 `r_thresh[c] <= 32\'d40`（**40 ADC 码**）；
- `pd_feature_core.v` 判决为幅值比较 `amp >= cfg_thresh`；
- 各通道相对 2048 的最大偏离：CH0 = 16、CH1 = 24、CH2 = **42**、CH3 = 30
  （CH2 幅度是 `>>>1` 即 ±32，另有 10 码直流偏置）。

**只有 CH2 越得过 40 码门限**，与实测落点完全吻合。所以环上画的是 DDS 背景三角波在 CH2 上
反复越限产生的密集"事件"，不是局放脉冲（也因此出现 202 条记录/秒、归档 79 ms 转一圈的高速率）。

这说明 `THRESH` 是“PL 候选事件门限”，不是现场人员应该频繁调节的最终检测阈值。
当前设计保留一个较低的 PL 候选门限以保证不漏候选；Qt 上位机的“检测阈值”
（默认 120 AD 码，可运行时调整）再对实时波形、事件椭圆和 PRPD 点做最终筛选。
因此不会因为改变界面阈值而写 AXI-Lite `THRESH`，也不需要重新综合或重新下载 PL。
若后续实测证明事件吞吐已经成为瓶颈，再单独做“固定安装标定门限”优化，不能把它
与运行时动态阈值混为一谈。
