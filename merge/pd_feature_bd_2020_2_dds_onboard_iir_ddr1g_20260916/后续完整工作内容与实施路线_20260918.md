## 1.1 FFT 的归属与执行位置

FFT 属于 `pd_feature` 算法域中的**分析子模块**，但不放在当前 PL 的 `pd_feature_0` 实时判决路径中执行。

最终职责划分如下：

```text
pd_feature 算法域
├── PL 实时子模块：滤波预处理、相位窗、峰值提取、阈值判决、事件编码
└── PS 分析子模块：快照解包、FFT、频谱峰值、选频、PRPD 和统计分析
```

物理数据流为：

```text
原始 ADC
  ├─> DDR 环形缓存/四槽快照
  │      └─> PS 读取原始快照
  │             ├─> 四通道解包
  │             ├─> 窗函数
  │             ├─> FFT
  │             ├─> 频谱峰值和选频
  │             └─> PRPD/统计
  │
  └─> pd_filter_0
         └─> pd_feature_0 PL 实时判决核心
```

因此：

- `pd_feature_0` 仍是 PL 实时特征提取和事件判决核心；
- FFT 的算法归属仍属于 `pd_feature`，但执行实体是 PS 侧分析服务；
- FFT 输入必须来自 DDR 保存的**原始 ADC 快照**，不能把 `pd_filter_0/filt_data` 当作 FFT 输入；
- 当前工程不恢复四路并行 PL FFT，也不允许 FFT 分析支路对采集、滤波、特征判决或快照施加反压；
- `pd_feature_0/m_axis` 输出的是事件包，不是 FFT 频谱流。

当前状态：

```text
PL 实时算法核心：已完成并板级通过
PS FFT 分析子模块：尚未实现
```

## 8. 第五阶段：PS 端算法链

`pd_feature_0` 是 PL 实时算法核心；其前置 `pd_filter_0` 只服务实时判决支路。PS 从 DDR 读取的是原始数据，因此 FFT 必须作为 `pd_feature` 算法域中的 PS 分析子模块，独立处理原始快照。

建议处理链：

```text
原始快照
 -> 去直流
 -> 窗函数
 -> PS IIR/FIR
 -> FFT
 -> 频谱峰值提取
 -> 事件统计
 -> PRPD
```

### 8.1 采样率约束

```text
26 MSPS：使用 fs26m 系数
16.25 MSPS：仅适用于确认 4:1 抽取后链路
65 MSPS：禁止直接使用当前五拍 IIR
```

### 8.2 PS FFT 分析子模块`r`n`r`nFFT 的执行位置固定为 PS 侧，不恢复 PL 内四路并行 FFT。PS FFT 服务接收 `pd_snapshot_unpack()` 输出的四通道原始波形，完成频谱分析；它不参与 `pd_feature_0` 的实时事件触发闭环。

初始建议：

```text
FFT 点数：1024
窗函数：Hann
四通道独立处理
输出频率、峰值幅度、主频和能量
```

26 MSPS、1024 点时频率分辨率约为：

```text
26 MHz / 1024 = 25.39 kHz
```

后续根据实际频率分辨率需求选择 2048 或 4096 点。
