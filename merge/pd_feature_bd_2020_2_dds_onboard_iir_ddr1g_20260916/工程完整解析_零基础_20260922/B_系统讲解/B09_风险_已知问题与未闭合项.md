## 🔴 红色：高风险（建议优先修）

### R-1 · 周期统计/阈值换档被 `ev_tready` 卡死
- **现象**：长时间无周期统计包，或改阈值后不生效。
- **文件:行号**：`pd_feature_core.v:841`（`S_CYC: if (ev_tready) begin ...`）；换档在 `S_CYC` 内完成（`:422`）。
- **推演/原因【事实】**：`S_CYC` 状态只在 `ev_tready` 为高时推进并发送周期包、做阈值换档。若下游（DMA/S2MM）反压拉低 `ev_tready`，`S_CYC` 永远不完成 → 周期统计不更新、**APPLY 后的新阈值永远不生效**。
- **影响**：阈值“调了没反应”、周期统计包缺失，是最隐蔽的“静默失效”。
- **建议修法**：将阈值换档与周期包发送解耦——换档在 `S_CYC` 进入即做（不依赖 `ev_tready`），`ev_tdata/ev_tvalid/ev_tlast` 仍等握手但用局部寄存器暂存；或加超时强制推进。

### R-2 · IIR 相位状态机缺 `phase==0` 保护 → `dv` 间隔 < 5 拍时永久锁死
- **现象**：滤波器输出"有效标志恒为 0"，即整条滤波链**静默失效**（输出无数据，但不报错）。
- **文件:行号**：`pd_iir_biquad.v:55-60`，关键是 **`:57`** `else if (dv) phase <= 3'd1;`
- **推演/原因【事实】（逐拍推演）**：
  ```
  55  always @(posedge clk or negedge rst_n) begin
  56      if (!rst_n || clr) phase <= 3'd0;
  57      else if (dv) phase <= 3'd1;          // ★ 无 phase==0 保护
  58      else if (phase == 3'd4) phase <= 3'd0;
  59      else if (phase != 3'd0) phase <= phase + 3'd1;
  60  end
  ```
  - 第 57 行的优先级**高于**第 58/59 行，且**没有任何 `phase == 0` 的前置条件**；
  - 若 `dv` 每 2 拍来一次（65 MSPS @130 MHz 的情形：`adc_dv` 间隔 = 2 拍 < 5 拍）：
    - 第 1 拍 `dv=1` → `phase` 被**强制**置 1；
    - 第 3 拍 `dv=1` → 又被强制置 1（而不是走 1→2）；
    - → **`phase` 永远到不了 4** → 第 74 行 `dout_dv <= (phase == 3'd4)` **恒为 0** → **模块永远不输出有效数据**。
  - ⭐ **所以本模块的硬性前提是"`dv` 间隔 ≥ 5 拍"**，这一点在文件头第 2–4 行的注释里只说了"五时钟"，**没有把"间隔 ≥5"这个前提写清楚**。
- **影响**：
  1. **65 MSPS 不能直接把本 IIR 串在采样链上**（这是"必须做 CIC 抽取降速"的**精确机制**；另一种解法是把时钟提到 325 MHz，不可达）；
  2. 更隐蔽的是：**它不报错、不打标志** —— 输出只是"永远无效"，看起来像"上游没数据"。
- **建议修法（二选一）**：
  - **① 加保护**：把第 57 行改为 `else if (dv && phase == 3'd0) phase <= 3'd1;` —— 但这会改变"背靠背样本"的行为（间隔恰好 5 拍时仍要能连续处理），**需仿真回归确认**；
  - **② 明确约束**：保持实现不变，但在文件头**写清"`dv` 间隔必须 ≥ 5 拍"**，并在调用方（`pd_filter_chain` 上游）加"降速/抽取"保证该前提。
- **⭐ 附带结论（对项目决策有用）**：这条 NOT 是"IIR 写得不好"，而是**"路线 B（窗口峰值域）在 65 MSPS 下的必然限制"**。要上 65 MSPS，正确做法是**在进 `pd_filter_0` 之前做 CIC 4:1 抽取**（把判决支路的样本率降到 16.25 MSPS → 130/16.25 = 8 拍/样本 > 5 拍 ✓ 余量 1.6×），而不是去改 IIR。

### R-3 · AXI4-Lite 从设备要求 AW 与 W 同时有效（违反协议）
- **现象**：用标准 AXI 主设备（如 PS 先发 W 后发 AW）访问时总线挂死。
- **文件:行号**：`pd_axil_regs.v:260`、`:281`、`:287`（均要求 `aw_valid && w_valid` 同时）。
- **推演/原因【事实】**：AXI4-Lite 协议允许 AW/W 乱序到达，本从设备却要求同拍。对比 `pd_ddr_axil.v` 在 **B 响应处**才耦合 AW/W（符合协议）。
- **影响**：与「先 W 后 AW」的主设备组合会死锁；可移植性差。
- **建议修法**：改成用 `aw_ready`/`w_ready` 各自握手、在 B 响应时合并（参照 `pd_ddr_axil.v` 的做法）。

### R-4 · `sw_rst` 单脉冲导致 `ddr_rst_n` 仅拉低 7.7ns
- **现象**：DataMover/环形写偶发不复位干净。
- **文件:行号**：`pd_ddr_wr_top.v:237-238`（sw_rst 单脉冲 → ddr_rst_n 仅 7.7ns）。
- **推演/原因【推测】**：单周期脉冲经同步后复位脉宽过窄；对某些 IP（DataMover 复位需满足最小脉宽）可能不足。**【事实】**脉宽数值来自代码注释/时钟推算，复位“失败”现象未上板取证。
- **影响**：复位不可靠，上电或恢复后状态机可能停在中间态。
- **建议修法**：将 `sw_rst` 展宽到若干 PL 周期（或保持到 `ddr_rst_n` 确认生效），再释放。

### R-5 · ~~`pk_s48_ready` 与 `pk_tready` 多驱动冲突~~ → **已核实：不成立（撤销）**
- **核实过程**：本项最初由"代码里同时出现 `pk_s48_ready` 与 `pk_tready`"误判而来，**逐行复核后不成立**：
  - `pk_s48_ready`：**只被 `pd_pack192` 的 `.o_s48_ready` 驱动**（`pd_ddr_wr_top.v:335`），在 `:324` 只是被**读**（`assign fifo_rd_en = pk_s48_ready & ~fifo_empty & ~fifo_rd_busy;`）→ **单一驱动源，无多驱动**。
  - `pk_tready`：**只被 `axis_dfi_64` 的 `.s_axis_tready` 驱动**（`:354`），在 `:338` 只是被**读**（`.m_axis_tready(pk_tready)`）→ **单一驱动源，无多驱动**。
- ⭐ **为什么会误判**：`pd_ddr_wr_top.v:152-155` 有一段**警告性注释**：
  ```
  152 // pk_tready   : 下游(axis_data_fifo)的接收 ready —— 单向，只由 IP 驱动
  153 // pk_s48_ready: pd_pack192 自身的接收 ready（块未装满）—— 单向，只由 RTL 驱动
  154 // 二者必须分开！若把 o_s48_ready 也接到 pk_tready 上会形成多驱动（Synth 8-6859）
  ```
  这段注释描述的是"**如果**这么做**会**出问题"，是**预防性说明**，不是现状描述。**当前实现是分开的、正确的。**
- **教训（更值得记录）**：**读代码时必须区分"描述现状的注释"与"描述反例的注释"**。本工程有大量"曾经踩过的坑"注释（`pd_axil_regs.v:10-12`、`pd_axis_fifo.v:5-34`、`pd_prpd_ram.v:9-12`、`async_fifo.v:8-20`、`pd_ddr_ring_wr.v:256-259`），**它们一律是"别这么做"，不是"现在这么做"。**
- **结论**：本项**降级为 🟢 良性**（实现正确）。

### R-6 · PS 侧 `XAxiDma_ResetIsDone` 无超时，可能死循环
- **现象**：DMA 异常时 PS 线程卡死在 `while(!ResetIsDone)`。
- **文件:行号**：`pd_acquisition_core.c:219`（`pd_acq_init`）、`:252`（`pd_acq_poll` STOPPING 分支）。
- **推演/原因【事实】**：两处均为裸 `while (!XAxiDma_ResetIsDone(&s_dma)) { }`，无计数上限；对照 `:184-186` 的 `reset_dma()` 是有超时的——说明作者知道要超时，却在这两处漏了。
- **影响**：DMA 不回复位完成位时，PS 永久自旋，整机无响应。
- **建议修法**：复用 `reset_dma()` 的超时模式，或在此两处加 `PD_SHUTDOWN_POLL_LIMIT` 计数，超时转 `fail("DMA reset timeout")`。
