### 1.2 已确认的目标参数与实际架构

当前参数为四通道、单通道 12 bit、65 MSPS，PL 运算域 130 MHz，测试源工频同步为 50 Hz。48 bit 是四路同一采样时刻的打包宽度，不是 ADC 单通道位数。

计算得到：每个 20 ms 周期包含每通道 1,300,000 点，打包原始快照为 `1,300,000 × 6 = 7,800,000 bytes`。完整原始连续流为 390 MB/s，即 3.12 Gbit/s，尚未计入协议开销。

当前数据通路：

```text
四个 COE / Block Memory Generator ROM + 20 ms 事件调度器
                      ↓ 4×12 bit，65 MHz
pd_ddr_0：四通道打包、公共 FIFO、原始 DDR 环形写与整周期冻结
         ├── 原始快照 → PL 四槽 → PS 四槽归档
         │                         ├── PS 全周期 min/max 包络 → Qt 四通道视图
         │                         └── PS 1024 点 FFT + 同窗波形 → Qt 单通道页
         └── 特征数据 → pd_filter_0 → pd_feature_0
                                          ├── 峰值、周期字、PL PRPD
                                          ├── AXIS → Simple DMA → PS 事件归档 → TCP → Qt
                                          └── event_accept → 自动快照触发
```

四通道事件图谱的峰值来源为 **PL 检测**，PS 负责归档和传输，Qt 进行显示阈值筛选与绘图。FFT 来源为 **PS 计算**，Qt 只换算 dBFS 并绘图。原始 DDR 快照位于滤波前，PL 检测支路位于滤波后；滤波启用后两者的峰值不必相等。

## 4. PL 核查结果

### 4.1 工程完整性、顶层、ROM IP

已对 XPR 的 `sources_1/constrs_1/sim_1` 文件条目展开工程变量检查，未发现指向不存在文件的当前 File 条目。历史 `ImportPath` 和增量路径仍有其他磁盘位置，不能作为独立重新导入流程的可靠来源，但当前实际工程文件存在。

XPR 指定 `xc7z020clg400-2`，BoardPart 为空；不是 Zynq UltraScale+。顶层只有普通输入 `pl_gclk_50`，以及 PS DDR/FIXED_IO 接口，当前没有真实 ADC 数据/时钟/OTR/外部同步端口。

四个 `pd_pd_template_rom_ch0..3` 是 Block Memory Generator 8.4，单端口 ROM，深度 1024，读宽 12，读延迟 1，无输出寄存器。每份 COE 均为 1024 个 12-bit 值，实际生成的四份 MIF 与 COE 完全一致；XCI 的当前运行属性为 `RUNTIME_PARAM.SYNTHESISFLOW=GLOBAL`，此前嵌套 Module Reference 的 OOC 问题在当前保存的 IP 中已经解决。

但 `scripts/13_configure_matlab_coe_roms.tcl:35` 开始的创建/配置流程没有设置关闭 OOC 的属性。现有 IP 可继续使用，不代表删除重建 ROM IP 后该脚本一定重现成功。此项属于可复现性风险，不能报告为“当前还存在 OOC 构建错误”。

### 4.2 数据通路、地址、中断

BD 的实际主链：DDS → DDR 公共 FIFO → filter → feature；`pd_feature_0.INPUT_CDC=0`。此路径避免在特征模块里再经过四个独立通道 CDC。原始数据打包为 `{CH3,CH2,CH1,CH0}`，连续四组 48-bit 样本变成 192-bit 块，再输出三个 64-bit beat。PS 解包和 Qt 6-byte 解包的通道顺序一致。

| 寄存器模块 | 地址区间 | 三方核查 |
|---|---|---|
| pd_ddr_0 | 0x40000000..0x4000FFFF | BD/HWH、BSP、pd_hw_map.h 一致 |
| pd_feature_0 | 0x40010000..0x4001FFFF | 一致 |
| pd_filter_0 | 0x40020000..0x4002FFFF | 一致 |
| axi_dma_0 | 0x40400000..0x4040FFFF | 一致，Simple 模式，仅 S2MM，64-bit，长度宽 16 |

PS GP0 承载 AXI-Lite 控制，HP0 承载原始环形写和事件 DMA，HP1 承载快照读/复制写。DMA 接收缓冲上限 65528 bytes、8-byte 对齐，与 16-bit BTT 的配置相容。

`xlconcat_0.In0/In1/In2` 分别连接 FEATURE、DMA、DDR IRQ，再接 PS IRQ_F2P。实际软件采用轮询并禁用 DMA 中断，没有当前应用注册 PL 三路 ISR 的证据；能轮询工作，但不等于历史“IRQ 驱动服务”已经实现。

### 4.3 时钟、复位与 CDC

XDC 已约束 PL 时钟 U18、LVCMOS33、20 ns；Clock Wizard 将 50 MHz 生成 130/65 MHz。路由后报告直接确认 130.000/65.000 MHz。PS FCLK0 实际为 142.857 MHz，仅用于诊断 ILA，不是主算法时钟，不能因与 130 MHz 不同就认定主链采样率错误。

可见 CDC 保护：DDR 主路径使用 FIFO Generator 异步 FIFO，`pd_sync_pulse` 对同步输入有 ASYNC_REG 两级同步；DDR ADC 侧复位释放也有两级同步。当前 test source 的 65 MHz 内部逻辑直接使用在 130 MHz 同步释放的 `peripheral_aresetn`，未看到其本地 reset deassert 同步器。

具体未关闭风险：

- XDC 将同一 MMCM 的 65/130 MHz 全域划为异步。最新方法学报告有 TIMING-47 两项；TIMING-24 四项明确记录该分组覆盖 FIFO 的 `set_max_delay -datapath_only`。虽然八项 bus-skew 检查 slack 为正，不能据此宣称 CDC 约束完整。
- 方法学报告 TIMING-9 一项提示未知 CDC，PDRC-190 十三项提示同步链放置问题。没有当前完整 `report_cdc` 结果可供分类验收。
- `pd_ddr_wr_top.v:413` 的 ADC 域 `up_ovf` 直接送 `pd_ddr_ring_wr` 的 130 MHz `i_up_ovf`，该连接未经过可见的 sticky + 两级同步/握手。`o_feat_ovf` 也没有在 BD 接至特征模块的质量输入。此处是具体可见的状态 CDC/质量传播风险，尚无板上故障归因证据。
- 真实独立 ADC 时钟尚未接入。未启用的 INPUT_CDC=1/2 固定标称整数比读取方案不能自动证明长期异步 ppm 偏差下不会累计 FIFO 溢出；当前测试源与 PL 由同一 MMCM 驱动，不能覆盖此风险。

`check_timing` 报告列出的 no_clock、unconstrained_internal_endpoints、no_input_delay、no_output_delay、multiple_clock 均为 0。其范围是当前测试顶层；由于没有真实 ADC 端口，不能将“无 ADC 输入延时违例”解释为“真实 ADC 输入延时已约束通过”。

### 4.5 特征检测、IIR 和测试波形的功能边界

PL 默认 N=1024 相位窗、ABSMAX 模式、门限 80 ADC 码、scale=256。`pd_feature_core` 对相位窗取极值，再经过门限、死区、区域筛选输出事件。两个物理脉冲在同一相位窗内时，ABSMAX 通常只保留一个极值；相邻窗又可能重复同一脉冲。该算法不等于逐脉冲独立检测或逐采样事件流。

当前每个相位窗约 1269.5 个样本（约19.53 μs），ROM 模板长度1024（约15.75 μs）。CH1 调度里有相距1024样本的相邻事件，这个组合应专门测试合并/重复率。现有源仿真 PASS 只证明激励数，不证明 PL 输出峰值数等于注入数。

IIR 已实现 65 MSPS 参数与两拍/并行乘积结构，存在系数资料；`pd_filter_chain.v:90` 默认全旁路、各级禁用、系数零。当前 TCP 主程序没有 `PD_FILTER_BASE` 写入/系数初始化调用。独立 `sw/pd_filter_apply.c`、smoke 工具不代表该配置已自动进入当前应用。过滤频段、响应、量化稳定性和启停瞬态应另行验收。

### 5.4 状态、错误恢复与协议

初始化静态IP192.168.1.10/24、网关192.168.1.1，监听TCP6001，只允许一个客户端。`pd_acq_poll`先调用TCP轮询钩子，再处理采集/归档；TCP轮询处理lwIP定时器、输入、包络步骤和发送。

已有IDLE/RUNNING/STOPPING/FAULT状态、STOP排空、RECOVER、CATALOG序号窗口、CRC及越界检查。事件批量响应复制最多32包至专用131072byte缓冲，减少往返开销，未在该步骤抽取峰值。

具体缺口：

- `pd_acquisition_core.c:219/252`仍有无限DMA ResetIsDone等待。硬件复位不完成时网络服务可能停止推进；其他路径已有计数上限，但不能覆盖这两处。
- PS快照每次7.8MB memcpy/flush是同步任务，中途不调用网络钩子；其实际最长阻塞时间未测量。
- PEAKS头中的wins/lock是**读取历史事件时**查当前PL寄存器得到，并未随归档保存。调参、失锁、重锁后可能用现在的配置解释过去事件；对真实相位正确性存在风险。
- `SCOPE EVENT`选择指定历史事件字，却从最新SNAP按相位提取窗口；没有共同cycle/sample ID的快照描述符。只能视为相位候选窗口，不能保证同一个物理瞬态。
- `start_scope_envelope`只接受长度恰为7,800,000bytes；Qt归档/包络也固定1,300,000。真实工频/采样时钟变化导致周期样本数变化时，会拒绝合法完整周期。当前准确50Hz测试源不能覆盖此情况。
- `SET FFTFS`允许IDLE时修改FFT解释采样率，Qt归档则要求65MHz；如果人为改成其他值会造成频轴错误或被客户端拒绝。应由硬件/快照元数据约束，不作为任意校准旋钮使用。

### 5.5 FFT正确性和精度

PS实现去均值、周期Hann、1024点radix-2、每级右移一位，输出513个u16幅值；乘4近似补偿单边频谱及Hann相干增益。Qt用2048码峰值为0dBFS。

65MHz/1024=63,476.5625Hz。协议bin_hz为整数63476Hz；peak_hz按bin×Fs/1024计算。截图CH4主峰1,079,101Hz对应bin17，CH3主峰698,242Hz对应bin11，与频率网格一致。START0只覆盖约15.75μs，而脉冲位于毫秒级周期相位区，所以首窗看不到局放脉冲是合理的窗口选择结果。

但“FFT整张图完全正确”仍不能确认：

- 窗函数作用于ADC整数差值，随后10级右移缩放，并未先提升输入有效精度；幅值最终`isqrt(power)*4`，最小非零值4ADC码，对应-54.185dBFS。实际图中大量4码/0码跳变和-100dBFS地板可由整数精度限制解释；不能把该底噪或细小谱线直接解释为真实物理频谱。
- `FFT SELFTEST`固定检查约1024ADC码的大幅单频输入，不能证明小信号噪声、非整bin、脉冲宽带频谱正确。旧26MSPS的SELFTEST PASS也不能替代当前app10的板上实测记录。
- 对Nyquist bin512同样乘4，在单边实信号幅值约定下端点无需乘普通正频率bin相同的倍数，存在约2倍端点幅值偏差风险；须用Nyquist输入单独验算。
- 显示的是一个1024点窗口的幅值谱，不是全周期FFT，不是PSD，也不是已标定的pC/能量频谱。
