# 本项目学习路线

这不是一份“把工程跑起来”的清单，而是一套把现有工程变成你自己能力的训练计划。目标是：遇到一个模块、波形或报错时，你能先提出自己的解释和验证办法，再用 AI 帮你查漏、核对和加速，而不是让 AI 替你做判断。

## 先看这里

本目录只包含学习资料，不修改 `merge/` 中的 RTL、约束或 Vivado 工程。

当前项目的学习基线：

| 项目项 | 当前证据 |
|---|---|
| 工程 | `merge/pd_feature_bd_2020_2/pd_feature_bd_2020_2.xpr` |
| 工具 | Vivado 2020.2（由工程目录和已有构建产物推断） |
| 器件 | `xc7z020clg400-2`（Zynq-7020） |
| 数据输入 | 四通道、每通道 12 bit ADC；当前验证配置 26 MSPS |
| 主处理时钟 | 130 MHz |
| 主功能 | ADC 采样、跨时钟域传输、局放特征/PRPD 统计、AXI-Lite 配置、AXI-Stream 事件输出、DMA/DDR 通路 |
| 仿真入口 | `merge/pd_feature_bd_2020_2/pd_feature_bd_2020_2.srcs/sim_1/new/tb_pd_feature_dds.v` |

## 建议顺序

1. 从 `01_学习地图.md` 建立全局视图，能画出数据流。
2. 依照 `02_八周实战计划.md` 做练习；不要跳到“上板”或“改复杂算法”。
3. 每次打开工程前先完成 `03_独立思考与AI协作.md` 的三问；每周更新一次 `04_学习记录模板.md` 的副本。

## 完成标准

八周后，你不需要背诵所有 Verilog 或 AXI 信号；但应能独立做到：

- 说明一个 ADC 样本从输入到 DDR/事件流会经过哪些模块、哪些时钟域。
- 对一个小模块写出“输入、状态、输出、时序行为”的解释，并用波形验证。
- 在不依赖 AI 直接给答案的前提下，定位一次失败仿真的首个错误、阅读报错并提出假设。
- 完成一个低风险 RTL 参数/门限改动，比较改动前后波形或事件数量，并能撤销。

学习不是一次性补齐所有基础。每天稳定完成 45--90 分钟的可验证小任务，比偶尔长时间“看懂全部工程”有效得多。
